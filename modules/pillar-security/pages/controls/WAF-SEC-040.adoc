= WAF-SEC-040 – Encryption in Transit – TLS Enforcement
:page-toc: right
:control-id: WAF-SEC-040
:pillar: security
:severity: high
:category: identity-access
:automatable: High
:description: All network communication between clients and services, and between internal services, MUST use TLS 1.2 or higher. HTTP listeners on application load balancers MUST either redirect to HTTPS or be prohibited. CloudFront distributions MUST enforce a minimum TLS policy of TLSv1.2. Internal service-to-service communication within VPCs MUST be encrypted. Expired, self-signed, or untrusted TLS certificates MUST NOT be used in production environments.

[.metadata]
*Säule:* Security | *Schweregrad:* Hoch | *Kategorie:* Identity Access | *Automatisierbar:* High

== Beschreibung

All network communication between clients and services, and between internal services, MUST use TLS 1.2 or higher. HTTP listeners on application load balancers MUST either redirect to HTTPS or be prohibited. CloudFront distributions MUST enforce a minimum TLS policy of TLSv1.2. Internal service-to-service communication within VPCs MUST be encrypted. Expired, self-signed, or untrusted TLS certificates MUST NOT be used in production environments.

== Begründung

[cols="1,3"]
|===
|Risiko |Beschreibung

|*Risk* |Sensitive data is exposed if storage or transport lacks strong encryption.

|*Risk* |Compromised keys or weak key rotation extend the blast radius of a breach.

|===

== Anforderungen

* All network communication between clients and services, and between internal services, MUST use TLS 1.2 or higher.
* HTTP listeners on application load balancers MUST either redirect to HTTPS or be prohibited.
* CloudFront distributions MUST enforce a minimum TLS policy of TLSv1.2.
* Internal service-to-service communication within VPCs MUST be encrypted.
* Expired, self-signed, or untrusted TLS certificates MUST NOT be used in production environments.

== Implementierungsleitfaden

1. Implement the required configuration as code in Terraform or equivalent IaC.
2. Add an automated check to CI/CD so deviations are caught before deployment.

== Checks

=== waf-sec-040.tf.aws.alb-https-listener

*Engine:* `terraform` | *Provider:* aws | *Automated:* Ja

*ALB and NLB listeners must use HTTPS, not HTTP*

Application and Network Load Balancer listeners must be configured with the HTTPS protocol (or TLS for NLB). Listeners configured with plain HTTP on port 80 are only acceptable if they redirect to HTTPS via a fixed-response redirect rule and do not forward traffic to targets.

*Scope:* `resource` — `aws_lb_listener`, `aws_alb_listener`

*Assertions:*
* `protocol` not equals `HTTP` — Load balancer listener MUST use HTTPS (or HTTP-to-HTTPS redirect), not plain HTTP forwarding.

*Remediation:* Change the listener protocol to HTTPS and provide a valid ACM certificate ARN. If a port 80 listener is required for redirect purposes, change the default_action to type = "redirect" with redirect { protocol = "HTTPS", status_code = "HTTP_301" }.

.Compliant

[source,terraform]
----
resource "aws_lb_listener" "https" {
  load_balancer_arn = aws_lb.main.arn
  port              = 443
  protocol          = "HTTPS"
  ssl_policy        = "ELBSecurityPolicy-TLS13-1-2-2021-06"
  certificate_arn   = aws_acm_certificate.main.arn
  default_action {
    type             = "forward"
    target_group_arn = aws_lb_target_group.app.arn
  }
}
resource "aws_lb_listener" "redirect_http" {
  load_balancer_arn = aws_lb.main.arn
  port              = 80
  protocol          = "HTTP"
  default_action {
    type = "redirect"
    redirect {
      port        = "443"
      protocol    = "HTTPS"
      status_code = "HTTP_301"
    }
  }
}
----

.Non-Compliant

[source,terraform]
----
resource "aws_lb_listener" "http" {
  load_balancer_arn = aws_lb.main.arn
  port              = 80
  protocol          = "HTTP"   # WAF-SEC-040 violation: plain HTTP forwarding
  default_action {
    type             = "forward"
    target_group_arn = aws_lb_target_group.app.arn
  }
}
----

=== waf-sec-040.tf.aws.cloudfront-tls-policy

*Engine:* `terraform` | *Provider:* aws | *Automated:* Ja

*CloudFront distributions must enforce TLS 1.2 or higher*

CloudFront distributions must have a viewer_certificate block with minimum_protocol_version set to at least TLSv1.2_2021 to prevent connections using outdated TLS versions.

*Scope:* `resource` — `aws_cloudfront_distribution`

*Assertions:*
* `viewer_certificate` attribute exists — CloudFront distribution must have an explicit viewer_certificate block configured.

*Remediation:* Add a viewer_certificate block to the aws_cloudfront_distribution resource. Set minimum_protocol_version = "TLSv1.2_2021" and ssl_support_method = "sni-only". Use a custom ACM certificate instead of the default CloudFront certificate for production workloads with custom domains.

.Compliant

[source,terraform]
----
resource "aws_cloudfront_distribution" "main" {
  # ... origin and cache behavior config
  viewer_certificate {
    acm_certificate_arn      = aws_acm_certificate.cdn.arn
    ssl_support_method       = "sni-only"
    minimum_protocol_version = "TLSv1.2_2021"
  }
}
----

.Non-Compliant

[source,terraform]
----
resource "aws_cloudfront_distribution" "main" {
  # ... origin and cache behavior config
  viewer_certificate {
    cloudfront_default_certificate = true
    # minimum_protocol_version not set – defaults to TLSv1 (WAF-SEC-040 violation)
  }
}
----

=== waf-sec-040.tf.azurerm.web-app-min-tls

*Engine:* `terraform` | *Provider:* azurerm | *Automated:* Ja

*Azure App Service and Function Apps must enforce TLS 1.2*

All azurerm_linux_web_app, azurerm_windows_web_app, azurerm_linux_function_app, and azurerm_windows_function_app resources must set site_config.minimum_tls_version to "1.2".

*Scope:* `resource` — `azurerm_linux_web_app`, `azurerm_windows_web_app`, `azurerm_linux_function_app`, `azurerm_windows_function_app`

*Assertions:*
* `site_config.minimum_tls_version` equals `1.2` — App Service / Function App must enforce TLS 1.2 minimum.

*Remediation:* Set minimum_tls_version = "1.2" in the site_config block of every App Service and Function App resource.

.Compliant

[source,terraform]
----
resource "azurerm_linux_web_app" "app" {
  name                = "app-service"
  resource_group_name = azurerm_resource_group.main.name
  location            = azurerm_resource_group.main.location
  service_plan_id     = azurerm_service_plan.app.id
  site_config {
    minimum_tls_version = "1.2"
    ftps_state          = "Disabled"
  }
}
----

.Non-Compliant

[source,terraform]
----
resource "azurerm_linux_web_app" "app" {
  name                = "app-service"
  resource_group_name = azurerm_resource_group.main.name
  location            = azurerm_resource_group.main.location
  service_plan_id     = azurerm_service_plan.app.id
  site_config {
    # minimum_tls_version defaults to "1.0" on older APIs
  }
}
----

=== waf-sec-040.tf.azurerm.cdn-no-http

*Engine:* `terraform` | *Provider:* azurerm | *Automated:* Ja

*Azure CDN endpoints must not allow plain HTTP delivery*

All azurerm_cdn_endpoint resources must set is_http_allowed to false so content is only served over HTTPS.

*Scope:* `resource` — `azurerm_cdn_endpoint`

*Assertions:*
* `is_http_allowed` is false — CDN endpoint must not allow plain HTTP delivery.

*Remediation:* Set is_http_allowed = false on every azurerm_cdn_endpoint resource. Configure HTTPS delivery and a valid custom domain certificate if needed.

.Compliant

[source,terraform]
----
resource "azurerm_cdn_endpoint" "app" {
  name                      = "app-cdn"
  profile_name              = azurerm_cdn_profile.app.name
  location                  = azurerm_resource_group.main.location
  resource_group_name       = azurerm_resource_group.main.name
  is_http_allowed           = false
  origin_host_header        = azurerm_storage_account.app.primary_web_host
}
----

.Non-Compliant

[source,terraform]
----
resource "azurerm_cdn_endpoint" "app" {
  name                      = "app-cdn"
  profile_name              = azurerm_cdn_profile.app.name
  location                  = azurerm_resource_group.main.location
  resource_group_name       = azurerm_resource_group.main.name
  # is_http_allowed defaults to true
}
----

=== waf-sec-040.tf.google.ssl-policy-tls-1-2

*Engine:* `terraform` | *Provider:* google | *Automated:* Ja

*Google Cloud SSL policies must enforce TLS 1.2 or higher*

All google_compute_ssl_policy resources must set min_tls_version to "TLS_1_2" or "TLS_1_3".

*Scope:* `resource` — `google_compute_ssl_policy`

*Assertions:*
* `min_tls_version` in `['TLS_1_2', 'TLS_1_3']` — SSL policy must enforce TLS 1.2 or higher.

*Remediation:* Set min_tls_version = "TLS_1_2" (or "TLS_1_3") on every google_compute_ssl_policy resource.

.Compliant

[source,terraform]
----
resource "google_compute_ssl_policy" "app" {
  name            = "app-ssl-policy"
  profile         = "CUSTOM"
  min_tls_version = "TLS_1_2"
  custom_features = ["TLS_ECDHE_RSA_WITH_AES_128_GCM_SHA256"]
}
----

.Non-Compliant

[source,terraform]
----
resource "google_compute_ssl_policy" "app" {
  name            = "app-ssl-policy"
  profile         = "COMPATIBLE"
  # min_tls_version defaults to TLS_1_0 in COMPATIBLE profile
}
----

=== waf-sec-040.tf.stackit.resource-data-class-tags

*Engine:* `terraform` | *Provider:* stackit | *Automated:* Ja

*STACKIT resources must be tagged with data classification*

All STACKIT resources that store or process data must carry a data-class tag (public, internal, confidential, restricted) to enforce appropriate security controls.

*Scope:* `resource` — `stackit_object_storage_bucket`, `stackit_postgres_flex_instance`, `stackit_mysql_instance`, `stackit_redis_instance`, `stackit_opensearch_instance`, `stackit_load_balancer`, `stackit_network`

*Assertions:*
* `tags` key exists — STACKIT resource must have a 'data-class' tag.

*Remediation:* Add a data-class tag to all STACKIT resources. Use a shared tagging module and enforce it via CI/CD checks.

.Compliant

[source,terraform]
----
resource "stackit_object_storage_bucket" "app" {
  project_id = var.stackit_project_id
  name       = "app-data"
  tags = {
    data-class = "confidential"
    owner      = "platform-team"
  }
}
----

.Non-Compliant

[source,terraform]
----
resource "stackit_object_storage_bucket" "app" {
  project_id = var.stackit_project_id
  name       = "app-data"
  # Missing data-class tag – WAF-SEC-040 violation
}
----
