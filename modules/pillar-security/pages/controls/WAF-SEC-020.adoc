[.metadata]
*Säule:* Security | *Schweregrad:* Kritisch | *Kategorie:* Identity Access | *Automatisierbar:* High

== Beschreibung

IAM policies MUST NOT grant wildcard actions (Action: "*") combined with wildcard resources (Resource: "*"). The AWS-managed AdministratorAccess policy MUST NOT be attached to roles used for automated workloads, CI/CD pipelines, or application service accounts. All IAM permissions MUST follow the principle of least privilege, granting only the minimum rights required for the intended function. Privilege escalation paths MUST be identified and eliminated using IAM Access Analyzer.

== Begründung

[cols="1,3"]
|===
|Risiko |Beschreibung

|*Risk* |Wildcard permissions allow all actions on all resources in principle and facilitate lateral movement.

|*Risk* |Administrator roles attached to workload principals risk unintended or malicious destruction.

|===

== Anforderungen

* IAM policies MUST NOT grant wildcard actions (Action: "*") combined with wildcard resources (Resource: "*").
* The AWS-managed AdministratorAccess policy MUST NOT be attached to roles used for automated workloads, CI/CD pipelines, or application service accounts.
* All IAM permissions MUST follow the principle of least privilege, granting only the minimum rights required for the intended function.
* Privilege escalation paths MUST be identified and eliminated using IAM Access Analyzer.

== Implementierungsleitfaden

1. Implement the required configuration as code in Terraform or equivalent IaC.
2. Add an automated check to CI/CD so deviations are caught before deployment.

== Checks

=== waf-sec-020.tf.aws.no-admin-policy-attachment

*Engine:* `terraform` | *Provider:* aws | *Automated:* Ja

*AdministratorAccess managed policy must not be attached to workload IAM principals*

The AWS-managed AdministratorAccess policy (arn:aws:iam::aws:policy/AdministratorAccess) must not be attached to any IAM role, user, or group used for automated workloads, applications, or CI/CD pipelines.

*Scope:* `resource` — `aws_iam_role_policy_attachment`, `aws_iam_user_policy_attachment`, `aws_iam_group_policy_attachment`

*Assertions:*
* `policy_arn` not equals `arn:aws:iam::aws:policy/AdministratorAccess` — AdministratorAccess managed policy MUST NOT be attached to any IAM principal.

*Remediation:* Remove the AdministratorAccess attachment and replace it with a scoped IAM policy that grants only the specific actions and resources required for the workload. Use IAM Access Advisor to identify which permissions were actually used in the last 90 days as a baseline.

.Compliant

[source,terraform]
----
resource "aws_iam_role_policy_attachment" "app_policy" {
  role       = aws_iam_role.app_role.name
  policy_arn = aws_iam_policy.app_scoped_policy.arn  # custom, least-privilege policy
}
resource "aws_iam_policy" "app_scoped_policy" {
  name = "app-scoped-policy"
  policy = jsonencode({
    Version = "2012-10-17"
    Statement = [{
      Effect   = "Allow"
      Action   = ["s3:GetObject", "s3:PutObject"]
      Resource = "arn:aws:s3:::my-app-bucket/*"
    }]
  })
}
----

.Non-Compliant

[source,terraform]
----
resource "aws_iam_role_policy_attachment" "bad" {
  role       = aws_iam_role.app_role.name
  policy_arn = "arn:aws:iam::aws:policy/AdministratorAccess"
  # WAF-SEC-020 violation: AdministratorAccess must not be attached to workload roles
}
----

=== waf-sec-020.tf.aws.no-inline-wildcard-policy

*Engine:* `terraform` | *Provider:* aws | *Automated:* Ja

*IAM policies must not combine wildcard actions with wildcard resources*

Inline and managed IAM policies must not contain statements with Action: '*' combined with Resource: '*'. This check requires manual review or a supplementary static analysis tool (e.g., Cloudsplaining, Checkov) as Terraform plan output must be parsed for policy document content.

*Scope:* `resource` — `aws_iam_policy`, `aws_iam_role_policy`, `aws_iam_user_policy`, `aws_iam_group_policy`

*Assertions:*
* `policy` json not contains pattern pattern `"Action":\\s*"\\*"` — IAM policy must not use wildcard Action '*'. Use scoped actions instead.

*Remediation:* Replace wildcard actions with a specific list of required API actions. Replace wildcard resources with specific ARNs or ARN patterns. Use IAM Access Advisor to determine which actions are actually used by the role.

.Compliant

[source,terraform]
----
resource "aws_iam_policy" "scoped" {
  name = "scoped-s3-policy"
  policy = jsonencode({
    Version = "2012-10-17"
    Statement = [{
      Effect   = "Allow"
      Action   = ["s3:GetObject", "s3:PutObject", "s3:DeleteObject"]
      Resource = "arn:aws:s3:::my-bucket/*"
    }]
  })
}
----

.Non-Compliant

[source,terraform]
----
resource "aws_iam_policy" "wildcard" {
  name = "bad-wildcard-policy"
  policy = jsonencode({
    Version = "2012-10-17"
    Statement = [{
      Effect   = "Allow"
      Action   = "*"          # WAF-SEC-020 violation
      Resource = "*"          # Combined wildcard = full admin
    }]
  })
}
----

=== waf-sec-020.tf.azurerm.no-owner-contributor-assignment

*Engine:* `terraform` | *Provider:* azurerm | *Automated:* Ja

*Azure built-in Owner or Contributor roles must not be assigned to workload principals*

azurerm_role_assignment resources must not use the built-in Owner or Contributor role definitions for application service principals, CI/CD pipelines, or automated workloads. Use custom or built-in roles scoped to least privilege.

*Scope:* `resource` — `azurerm_role_assignment`

*Assertions:*
* `role_definition_name` not in `['Owner', 'Contributor']` — Owner and Contributor built-in roles must not be assigned to workload principals.

*Remediation:* Replace azurerm_role_assignment entries using "Owner" or "Contributor" with scoped custom roles or built-in roles that grant only the actions required (e.g., Reader, Storage Blob Contributor, Key Vault Secrets User).

.Compliant

[source,terraform]
----
resource "azurerm_role_assignment" "app_storage" {
  scope                = azurerm_storage_account.app.id
  role_definition_name = "Storage Blob Data Contributor"
  principal_id         = azuread_service_principal.app.object_id
}
----

.Non-Compliant

[source,terraform]
----
resource "azurerm_role_assignment" "bad" {
  scope                = data.azurerm_subscription.current.id
  role_definition_name = "Owner"
  principal_id         = azuread_service_principal.cicd.object_id
  # WAF-SEC-020 violation: Owner assigned to workload principal
}
----

=== waf-sec-020.tf.azurerm.custom-role-no-wildcard

*Engine:* `terraform` | *Provider:* azurerm | *Automated:* Ja

*Azure custom role definitions must not include wildcard actions*

azurerm_role_definition resources must not declare permissions with Action "*" or NotAction "*" combined with assignable scopes that grant broad access. Custom roles should list explicit actions and data actions.

*Scope:* `resource` — `azurerm_role_definition`

*Assertions:*
* `permissions` not contains `*` — Custom role permissions must not contain wildcard action "*".

*Remediation:* Replace wildcard actions in azurerm_role_definition permissions blocks with explicit Microsoft.* actions required by the workload. Avoid NotAction "*" patterns.

.Compliant

[source,terraform]
----
resource "azurerm_role_definition" "scoped" {
  name        = "App Scoped Role"
  scope       = data.azurerm_subscription.current.id
  permissions {
    actions     = ["Microsoft.Storage/storageAccounts/read"]
    not_actions = []
  }
  assignable_scopes = [data.azurerm_subscription.current.id]
}
----

.Non-Compliant

[source,terraform]
----
resource "azurerm_role_definition" "wildcard" {
  name  = "Wildcard Admin"
  scope = data.azurerm_subscription.current.id
  permissions {
    actions     = ["*"]  # WAF-SEC-020 violation: wildcard action
    not_actions = []
  }
}
----

=== waf-sec-020.tf.google.no-basic-project-roles

*Engine:* `terraform` | *Provider:* google | *Automated:* Ja

*GCP basic project roles must not be bound to workload principals*

google_project_iam_member and google_project_iam_binding resources must not use roles/owner, roles/editor, or roles/viewer for application service accounts, CI/CD pipelines, or automated workloads.

*Scope:* `resource` — `google_project_iam_member`, `google_project_iam_binding`, `google_organization_iam_member`, `google_organization_iam_binding`

*Assertions:*
* `role` not in `['roles/owner', 'roles/editor', 'roles/viewer']` — GCP basic roles must not be assigned to workload principals.

*Remediation:* Remove google_project_iam_member / google_project_iam_binding entries using roles/owner, roles/editor, or roles/viewer. Replace with predefined service-specific roles (e.g., roles/storage.objectAdmin) or custom roles listing only required permissions.

.Compliant

[source,terraform]
----
resource "google_project_iam_member" "app_storage" {
  project = var.project_id
  role    = "roles/storage.objectAdmin"
  member  = "serviceAccount:${google_service_account.app.email}"
}
----

.Non-Compliant

[source,terraform]
----
resource "google_project_iam_member" "bad" {
  project = var.project_id
  role    = "roles/editor"  # WAF-SEC-020 violation: overly permissive basic role
  member  = "serviceAccount:${google_service_account.cicd.email}"
}
----

=== waf-sec-020.tf.google.custom-role-no-wildcard

*Engine:* `terraform` | *Provider:* google | *Automated:* Ja

*GCP custom IAM roles must not include wildcard permissions*

google_project_iam_custom_role and google_organization_iam_custom_role resources must not include "*" in their permissions list. Permissions should be explicit GCP service methods.

*Scope:* `resource` — `google_project_iam_custom_role`, `google_organization_iam_custom_role`

*Assertions:*
* `permissions` not contains `*` — Custom role permissions must not contain wildcard "*".

*Remediation:* Replace wildcard permissions in google_project_iam_custom_role with explicit permissions required by the workload. Audit the custom role using IAM Policy Analyzer or gcloud iam roles list.

.Compliant

[source,terraform]
----
resource "google_project_iam_custom_role" "scoped" {
  project = var.project_id
  role_id = "appScoped"
  title   = "App Scoped Role"
  permissions = [
    "storage.objects.get",
    "storage.objects.create",
  ]
}
----

.Non-Compliant

[source,terraform]
----
resource "google_project_iam_custom_role" "wildcard" {
  project = var.project_id
  role_id = "wildcardAdmin"
  title   = "Wildcard Admin"
  permissions = ["*"]  # WAF-SEC-020 violation: wildcard permission
}
----
