= WAF-SEC-060 – Secrets Management – No Hardcoded Credentials
:page-toc: right
:control-id: WAF-SEC-060
:pillar: security
:severity: critical
:category: identity-access
:automatable: High
:description: All secrets, API keys, passwords, database credentials, and certificates MUST be stored in a dedicated secrets management solution (AWS Secrets Manager or HashiCorp Vault). Secrets MUST NOT be hardcoded in IaC code, Terraform variable files, environment variables in task definitions, source code, or CI/CD pipeline configuration. Secrets Manager secrets MUST be encrypted with customer-managed KMS keys. Automatic rotation MUST be configured for all long-lived credentials where the target service supports it.

[.metadata]
*Säule:* Security | *Schweregrad:* Kritisch | *Kategorie:* Identity Access | *Automatisierbar:* High

== Beschreibung

All secrets, API keys, passwords, database credentials, and certificates MUST be stored in a dedicated secrets management solution (AWS Secrets Manager or HashiCorp Vault). Secrets MUST NOT be hardcoded in IaC code, Terraform variable files, environment variables in task definitions, source code, or CI/CD pipeline configuration. Secrets Manager secrets MUST be encrypted with customer-managed KMS keys. Automatic rotation MUST be configured for all long-lived credentials where the target service supports it.

== Begründung

[cols="1,3"]
|===
|Risiko |Beschreibung

|*Risk* |Sensitive data is exposed if storage or transport lacks strong encryption.

|*Risk* |Compromised keys or weak key rotation extend the blast radius of a breach.

|===

== Anforderungen

* All secrets, API keys, passwords, database credentials, and certificates MUST be stored in a dedicated secrets management solution (AWS Secrets Manager or HashiCorp Vault).
* Secrets MUST NOT be hardcoded in IaC code, Terraform variable files, environment variables in task definitions, source code, or CI/CD pipeline configuration.
* Secrets Manager secrets MUST be encrypted with customer-managed KMS keys.
* Automatic rotation MUST be configured for all long-lived credentials where the target service supports it.

== Implementierungsleitfaden

1. Implement the required configuration as code in Terraform or equivalent IaC.
2. Add an automated check to CI/CD so deviations are caught before deployment.

== Checks

=== waf-sec-060.tf.aws.secrets-manager-exists

*Engine:* `terraform` | *Provider:* aws | *Automated:* Ja

*Secrets Manager secrets must be defined with a recovery window*

All aws_secretsmanager_secret resources must have a name attribute set and recovery_window_in_days >= 7 to prevent accidental deletion from causing immediate and irrecoverable data access loss.

*Scope:* `resource` — `aws_secretsmanager_secret`

*Assertions:*
* `name` attribute exists — Secrets Manager secret must have an explicit name attribute.
* `recovery_window_in_days` greater than or equal `7` — Secrets Manager secret recovery window must be at least 7 days to allow recovery from accidental deletion.

*Remediation:* Add name and recovery_window_in_days = 30 to all aws_secretsmanager_secret resources. Do not set force_overwrite_replica_secret = true or recovery_window_in_days = 0 unless in a controlled testing environment.

.Compliant

[source,terraform]
----
resource "aws_secretsmanager_secret" "db_password" {
  name                    = "prod/app/db-password"
  description             = "RDS master password for production application database"
  kms_key_id              = aws_kms_key.secrets.arn
  recovery_window_in_days = 30
  tags = {
    owner       = "platform-team"
    environment = "production"
  }
}
----

.Non-Compliant

[source,terraform]
----
resource "aws_secretsmanager_secret" "db_password" {
  # name not set                           – WAF-SEC-060 violation
  recovery_window_in_days = 0              # WAF-SEC-060 violation: no recovery window
  # kms_key_id not set                     – WAF-SEC-060 violation (check 2)
}
----

=== waf-sec-060.tf.aws.secrets-encrypted-with-cmk

*Engine:* `terraform` | *Provider:* aws | *Automated:* Ja

*Secrets Manager secrets must be encrypted with a customer-managed KMS key*

All aws_secretsmanager_secret resources must have a kms_key_id attribute referencing a customer-managed KMS key. Using the default AWS-managed key (aws/secretsmanager) is not acceptable for production workloads containing sensitive credentials.

*Scope:* `resource` — `aws_secretsmanager_secret`

*Assertions:*
* `kms_key_id` attribute exists — Secrets Manager secret MUST be encrypted with a customer-managed KMS key (kms_key_id must be set).

*Remediation:* Create an aws_kms_key resource with enable_key_rotation = true and reference its ARN via kms_key_id = aws_kms_key.secrets.arn in the aws_secretsmanager_secret resource. Ensure the KMS key policy grants the Secrets Manager service principal permission to use the key for encryption and decryption.

.Compliant

[source,terraform]
----
resource "aws_kms_key" "secrets" {
  description         = "CMK for Secrets Manager encryption"
  enable_key_rotation = true
}
resource "aws_secretsmanager_secret" "api_key" {
  name       = "prod/app/external-api-key"
  kms_key_id = aws_kms_key.secrets.arn
}
----

.Non-Compliant

[source,terraform]
----
resource "aws_secretsmanager_secret" "api_key" {
  name = "prod/app/external-api-key"
  # kms_key_id not set – using default aws/secretsmanager key
  # WAF-SEC-060 violation: CMK encryption required for production secrets
}
----

=== waf-sec-060.tf.azurerm.key-vault-secret-expiration

*Engine:* `terraform` | *Provider:* azurerm | *Automated:* Ja

*Azure Key Vault secrets must have an expiration date*

All azurerm_key_vault_secret resources storing workload secrets must have expiration_date set to enforce rotation and lifecycle.

*Scope:* `resource` — `azurerm_key_vault_secret`

*Assertions:*
* `expiration_date` attribute exists — Key Vault secret must have an expiration_date for lifecycle management.

*Remediation:* Set expiration_date on every azurerm_key_vault_secret resource and establish a rotation workflow that refreshes the secret before expiration.

.Compliant

[source,terraform]
----
resource "azurerm_key_vault_secret" "db_password" {
  name         = "db-password"
  value        = var.db_password
  key_vault_id = azurerm_key_vault.main.id
  expiration_date = "2026-01-01T00:00:00Z"
}
----

.Non-Compliant

[source,terraform]
----
resource "azurerm_key_vault_secret" "db_password" {
  name         = "db-password"
  value        = var.db_password
  key_vault_id = azurerm_key_vault.main.id
  # expiration_date not set
}
----

=== waf-sec-060.tf.google.secret-manager-exists

*Engine:* `terraform` | *Provider:* google | *Automated:* Ja

*Google Secret Manager secrets must be defined for workload secrets*

All workload secrets must be stored in google_secret_manager_secret resources rather than plain text or local state.

*Scope:* `resource` — `google_secret_manager_secret`

*Assertions:*
* `secret_id` attribute exists — Workload secrets must be stored in Google Secret Manager.

*Remediation:* Create google_secret_manager_secret resources for all sensitive configuration values. Reference secret versions via data sources rather than storing values in Terraform state.

.Compliant

[source,terraform]
----
resource "google_secret_manager_secret" "db_password" {
  secret_id = "db-password"
  replication {
    auto {}
  }
}
----

.Non-Compliant

[source,terraform]
----
# Secret value stored in plain text or Terraform variable
# Use google_secret_manager_secret instead
----

=== waf-sec-060.tf.stackit.secret-manager-rotation

*Engine:* `terraform` | *Provider:* stackit | *Automated:* Ja

*STACKIT secrets must be stored in Secret Manager and rotated*

Credentials, API keys, and other secrets used by STACKIT workloads must be stored in stackit_secret_manager_secret resources and rotated regularly. Hard-coded secrets in Terraform are prohibited.

*Scope:* `resource` — `stackit_secret_manager_secret`

*Assertions:*
* `name` attribute exists — STACKIT secrets must be stored in Secret Manager resources.

*Remediation:* Create stackit_secret_manager_secret resources for all sensitive values. Reference them via data sources in application configuration. Implement rotation via automation or documented process.

.Compliant

[source,terraform]
----
resource "stackit_secret_manager_secret" "db_password" {
  project_id = var.stackit_project_id
  name       = "db-password"
  # value managed via STACKIT Secret Manager; rotation automated
}
----

.Non-Compliant

[source,terraform]
----
# Database password hard-coded in Terraform or plain text.
# WAF-SEC-060 violation: secrets not managed in Secret Manager
----
