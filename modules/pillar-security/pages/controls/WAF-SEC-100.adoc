== Beschreibung

An incident response (IR) plan MUST exist, be documented, version-controlled, and tested at least annually via tabletop exercises or simulated incident drills. SNS topics or equivalent alerting channels MUST be configured to receive security findings from GuardDuty, Security Hub, and CloudTrail metric alarms. Security-relevant CloudWatch log groups MUST retain logs for a minimum of 365 days. S3-based CloudTrail and VPC Flow Log archives MUST be retained for at least 12 months. The incident response plan MUST define roles and responsibilities, escalation paths, communication templates, and steps for evidence preservation, containment, eradication, and recovery.

== Begründung

[cols="1,3"]
|===
|Risiko |Beschreibung

|*Risk* |Missing incident-response plans extend reaction times and worsen the impact of security incidents.

|*Risk* |Untested IR processes lead to wrong decisions and missed regulatory reporting obligations in a real event.

|===

== Anforderungen

* An incident response (IR) plan MUST exist, be documented, version-controlled, and tested at least annually via tabletop exercises or simulated incident drills.
* SNS topics or equivalent alerting channels MUST be configured to receive security findings from GuardDuty, Security Hub, and CloudTrail metric alarms.
* Security-relevant CloudWatch log groups MUST retain logs for a minimum of 365 days.
* S3-based CloudTrail and VPC Flow Log archives MUST be retained for at least 12 months.
* The incident response plan MUST define roles and responsibilities, escalation paths, communication templates, and steps for evidence preservation, containment, eradication, and recovery.

== Implementierungsleitfaden

1. Document the requirement in a version-controlled policy or standard.
2. Assign ownership and establish a review cadence (e.g., quarterly).

== Checks

=== waf-sec-100.tf.aws.sns-security-alerts

*Engine:* `terraform` | *Provider:* aws | *Automated:* Ja

*SNS topic for security alerts must be provisioned*

An aws_sns_topic resource for security alerting must exist in the account. This topic should be subscribed to GuardDuty and Security Hub EventBridge rules, and must have at least one active subscription routing to an on-call system.

*Scope:* `resource` — `aws_sns_topic`

*Assertions:*
* `name` attribute exists — An SNS topic for security alerts must be provisioned with a defined name.

*Remediation:* Create an aws_sns_topic resource named 'security-alerts' or similar. Add subscriptions (aws_sns_topic_subscription) pointing to PagerDuty, OpsGenie, or a Slack webhook endpoint. Configure EventBridge rules targeting this topic for GuardDuty findings with severity >= 7 and Security Hub CRITICAL findings.

.Compliant

[source,terraform]
----
resource "aws_sns_topic" "security_alerts" {
  name              = "security-alerts"
  kms_master_key_id = aws_kms_key.sns.id
  tags = {
    owner       = "security-team"
    environment = "production"
  }
}
resource "aws_sns_topic_subscription" "pagerduty" {
  topic_arn = aws_sns_topic.security_alerts.arn
  protocol  = "https"
  endpoint  = var.pagerduty_endpoint
}
----

.Non-Compliant

[source,terraform]
----
# No aws_sns_topic resource for security alerts present
# WAF-SEC-100 violation: security alerting channel not provisioned in IaC
----

=== waf-sec-100.tf.aws.cloudwatch-log-retention-security

*Engine:* `terraform` | *Provider:* aws | *Automated:* Ja

*Security-relevant CloudWatch log groups must retain logs for at least 365 days*

CloudWatch log groups used for security-relevant data (application logs, VPC flow logs ingested into CloudWatch, Lambda security function logs) must have retention_in_days set to at least 365 to satisfy forensic and regulatory retention requirements.

*Scope:* `resource` — `aws_cloudwatch_log_group`

*Assertions:*
* `retention_in_days` greater than or equal `365` — Security-relevant log groups MUST retain logs for at least 365 days to support forensic investigation and regulatory compliance.

*Remediation:* Set retention_in_days = 365 (or higher) on all security-relevant aws_cloudwatch_log_group resources. For CloudTrail and VPC Flow Logs with higher volume, consider using S3-based retention with lifecycle policies (Standard for 12 months, Glacier for 7 years) rather than CloudWatch to optimize cost.

.Compliant

[source,terraform]
----
resource "aws_cloudwatch_log_group" "app_security" {
  name              = "/security/application-events"
  retention_in_days = 365
  kms_key_id        = aws_kms_key.logs.arn
  tags = {
    owner       = "security-team"
    data-class  = "operational"
  }
}
----

.Non-Compliant

[source,terraform]
----
resource "aws_cloudwatch_log_group" "app_security" {
  name              = "/security/application-events"
  retention_in_days = 30  # WAF-SEC-100 violation: below 365-day minimum
}
----

=== waf-sec-100.manual.any.incident-response-plan

*Engine:* `manual` | *Provider:* any | *Automated:* Ja

*Incident response plan must exist, be version-controlled, and tested annually*

A formal incident response plan must be documented, stored in version control, and tested via tabletop exercise or live drill at least once per year. The plan must cover roles, escalation paths, GDPR breach notification workflow, and playbooks for the top incident types relevant to the workload.

*Scope:* `terraform`

*Assertions:*
* `ir_plan_version_controlled` is true — Incident response plan must be stored in version control (e.g., Git repository under /docs/security/ir-plan.md).

*Remediation:* 1. Draft an incident response plan covering: Preparation, Detection & Analysis,\n   Containment, Eradication, Recovery, and Post-Incident Review phases.\n2. Define RACI matrix for each phase including external communication and\n   GDPR DPA notification responsibility.\n3. Create runbooks for top 5-10 incident types (credential compromise, data exfiltration,\n   ransomware, privilege escalation, supply chain attack).\n4. Store the IR plan in a version-controlled repository with mandatory review. 5. Schedule annual tabletop exercise; document results and track action items.

.Compliant

[source,text]
----
# IR plan stored at: docs/security/incident-response-plan.md (version-controlled)
# Last tested: 2025-11-15 via tabletop exercise (ref: IR-DRILL-2025-001)
# Runbooks available at: docs/security/runbooks/
# GDPR DPA notification workflow: docs/security/gdpr-breach-notification.md
----

.Non-Compliant

[source,text]
----
# No incident response plan exists in the repository.
# WAF-SEC-100 violation: IR plan is a mandatory governance artifact.
----
