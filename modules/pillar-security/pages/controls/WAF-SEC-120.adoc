== Description

Container workloads MUST run as non-root users (UID != 0) with explicit user and group IDs set in Dockerfile or Kubernetes security context. Privileged container mode MUST be disabled for all production workloads. Container images MUST originate from registries with image scanning enabled (ECR or equivalent) and MUST NOT be pulled directly from unauthenticated public registries at runtime. EKS clusters MUST have the API server endpoint restricted; public access MUST be disabled or limited to known CIDR ranges. Container runtime security monitoring MUST be implemented to detect and alert on anomalous container behaviors at runtime.

== Rationale

[cols="1,3"]
|===
|Risk |Description

|*Risk* |Internet-facing resources or open management ports become direct attack vectors.

|*Risk* |Lateral movement is easier when network segmentation and access rules are missing.

|===

== Requirements

* Container workloads MUST run as non-root users (UID != 0) with explicit user and group IDs set in Dockerfile or Kubernetes security context.
* Privileged container mode MUST be disabled for all production workloads.
* Container images MUST originate from registries with image scanning enabled (ECR or equivalent) and MUST NOT be pulled directly from unauthenticated public registries at runtime.
* EKS clusters MUST have the API server endpoint restricted; public access MUST be disabled or limited to known CIDR ranges.
* Container runtime security monitoring MUST be implemented to detect and alert on anomalous container behaviors at runtime.

== Implementation Guidance

1. Implement the required configuration as code in Terraform or equivalent IaC.
2. Add an automated check to CI/CD so deviations are caught before deployment.

== Checks

=== waf-sec-120.tf.aws.eks-private-endpoint

*Engine:* `terraform` | *Provider:* aws | *Automated:* Yes

*EKS cluster API server endpoint must not be publicly accessible*

The aws_eks_cluster vpc_config block must be present. The EKS API server endpoint should have endpoint_public_access disabled or restricted to known CIDR ranges. Public EKS API endpoints expose the Kubernetes control plane to internet-based attacks targeting API vulnerabilities and credential compromise.

*Scope:* `resource` — `aws_eks_cluster`

*Assertions:*
* `vpc_config` attribute exists — EKS cluster must have a vpc_config block defined to configure endpoint access restrictions.

*Remediation:* Add a vpc_config block to the aws_eks_cluster resource. Set endpoint_public_access = false to disable public API access entirely and use a VPN or AWS Direct Connect for cluster management. If public access is required, set endpoint_public_access_cidrs to specific CIDR ranges for your organization's VPN or office IPs and set endpoint_private_access = true. Deploy a bastion host or use AWS Systems Manager Session Manager in the VPC for kubectl access.

.Compliant

[source,terraform]
----
resource "aws_eks_cluster" "main" {
  name     = "production-cluster"
  role_arn = aws_iam_role.eks_cluster.arn
  version  = "1.30"

  vpc_config {
    subnet_ids              = aws_subnet.private[*].id
    endpoint_private_access = true
    endpoint_public_access  = false
    security_group_ids      = [aws_security_group.eks_cluster.id]
  }

  enabled_cluster_log_types = ["api", "audit", "authenticator", "controllerManager", "scheduler"]

  tags = {
    environment = "production"
  }
}
----

.Non-Compliant

[source,terraform]
----
resource "aws_eks_cluster" "main" {
  name     = "production-cluster"
  role_arn = aws_iam_role.eks_cluster.arn
  version  = "1.30"

  vpc_config {
    subnet_ids             = aws_subnet.public[*].id
    endpoint_public_access = true   # WAF-SEC-120 violation: public API server endpoint
    # endpoint_private_access not set – defaults to false
  }
  # enabled_cluster_log_types not set – audit logging disabled
}
----

=== waf-sec-120.tf.aws.ecr-scan-on-push

*Engine:* `terraform` | *Provider:* aws | *Automated:* Yes

*Container images must be sourced from ECR repositories with scanning enabled*

All aws_ecr_repository resources supplying container images to production EKS or ECS workloads must have image_scanning_configuration with scan_on_push = true. This ensures vulnerability detection occurs at the point of image ingestion, not as a periodic job that may miss images deployed between scan cycles.

*Scope:* `resource` — `aws_ecr_repository`

*Assertions:*
* `image_scanning_configuration` attribute exists — ECR repository must have image_scanning_configuration defined to ensure all pushed images are scanned for vulnerabilities.

*Remediation:* Add an image_scanning_configuration block with scan_on_push = true to all aws_ecr_repository resources. Configure ECR lifecycle policies to automatically remove images with critical findings. Consider enabling Amazon Inspector for enhanced scanning that includes application dependency CVEs in addition to OS packages.

.Compliant

[source,terraform]
----
resource "aws_ecr_repository" "app" {
  name                 = "production-app"
  image_tag_mutability = "IMMUTABLE"

  image_scanning_configuration {
    scan_on_push = true
  }

  encryption_configuration {
    encryption_type = "KMS"
    kms_key         = aws_kms_key.ecr.arn
  }
}
----

.Non-Compliant

[source,terraform]
----
resource "aws_ecr_repository" "app" {
  name                 = "production-app"
  image_tag_mutability = "MUTABLE"
  # No image_scanning_configuration – WAF-SEC-120 violation
  # Vulnerability scanning not enforced at push time
}
----

=== waf-sec-120.tf.azurerm.aks-private-cluster

*Engine:* `terraform` | *Provider:* azurerm | *Automated:* Yes

*Azure Kubernetes Service clusters must use private cluster mode*

All azurerm_kubernetes_cluster resources must have private_cluster_enabled = true and public_network_access_enabled = false to limit API server exposure.

*Scope:* `resource` — `azurerm_kubernetes_cluster`

*Assertions:*
* `private_cluster_enabled` is true — AKS cluster must have private cluster mode enabled.
* `public_network_access_enabled` is false — AKS cluster must disable public network access to the API server.

*Remediation:* Enable private_cluster_enabled and set public_network_access_enabled = false on every AKS cluster. Connect to the API server via private endpoints or Azure Bastion.

.Compliant

[source,terraform]
----
resource "azurerm_kubernetes_cluster" "app" {
  name                = "app-aks"
  location            = azurerm_resource_group.main.location
  resource_group_name = azurerm_resource_group.main.name
  dns_prefix          = "app-aks"
  private_cluster_enabled = true
  public_network_access_enabled = false
  default_node_pool {
    name       = "default"
    node_count = 2
    vm_size    = "Standard_D2s_v3"
  }
  identity {
    type = "SystemAssigned"
  }
}
----

.Non-Compliant

[source,terraform]
----
resource "azurerm_kubernetes_cluster" "app" {
  name                = "app-aks"
  location            = azurerm_resource_group.main.location
  resource_group_name = azurerm_resource_group.main.name
  dns_prefix          = "app-aks"
  # private_cluster_enabled defaults to false
  default_node_pool {
    name       = "default"
    node_count = 2
    vm_size    = "Standard_D2s_v3"
  }
}
----

=== waf-sec-120.tf.google.gke-private-cluster

*Engine:* `terraform` | *Provider:* google | *Automated:* Yes

*Google Kubernetes Engine clusters must use private nodes*

All google_container_cluster resources must have private_cluster_config.enable_private_nodes = true and master_authorized_networks_config enabled to restrict API server access.

*Scope:* `resource` — `google_container_cluster`

*Assertions:*
* `private_cluster_config.enable_private_nodes` is true — GKE cluster must use private nodes.
* `master_authorized_networks_config` attribute exists — GKE cluster must restrict master authorized networks.

*Remediation:* Configure private_cluster_config with enable_private_nodes = true and define master_authorized_networks_config with trusted CIDRs on every GKE cluster.

.Compliant

[source,terraform]
----
resource "google_container_cluster" "app" {
  name     = "app-gke"
  location = "europe-west3"
  private_cluster_config {
    enable_private_nodes    = true
    enable_private_endpoint = false
    master_ipv4_cidr_block  = "172.16.0.0/28"
  }
  master_authorized_networks_config {
    cidr_blocks {
      cidr_block   = "10.0.0.0/8"
      display_name = "internal-network"
    }
  }
}
----

.Non-Compliant

[source,terraform]
----
resource "google_container_cluster" "app" {
  name     = "app-gke"
  location = "europe-west3"
  # private_cluster_config not set – nodes have public IPs by default
}
----

=== waf-sec-120.tf.stackit.database-backup-enabled

*Engine:* `terraform` | *Provider:* stackit | *Automated:* Yes

*STACKIT managed databases must have backup and point-in-time recovery enabled*

stackit_postgres_flex_instance, stackit_mysql_instance, stackit_redis_instance, and stackit_opensearch_instance resources must have automated backups enabled with a documented retention and recovery procedure.

*Scope:* `resource` — `stackit_postgres_flex_instance`, `stackit_mysql_instance`, `stackit_redis_instance`, `stackit_opensearch_instance`

*Assertions:*
* `name` attribute exists — STACKIT managed database must have backups and recovery configured.

*Remediation:* Enable automated backups on all STACKIT managed data services. Define retention, encryption, and recovery SLAs in a documented backup policy.

.Compliant

[source,terraform]
----
resource "stackit_postgres_flex_instance" "app" {
  project_id = var.stackit_project_id
  name       = "app-db"
  version    = "15"
  # backups enabled with retention >= 7 days
}
----

.Non-Compliant

[source,terraform]
----
resource "stackit_postgres_flex_instance" "app" {
  project_id = var.stackit_project_id
  name       = "app-db"
  # WAF-SEC-120 violation: backups not configured
}
----

=== waf-sec-120.config.ovh.ovh-identity-access

*Engine:* `config` | *Provider:* ovh | *Automated:* Yes

*OVHcloud workloads must have backup and recovery procedures documented*

A version-controlled policy document must exist at `docs/security/waf-sec-120-ovh-identity-access.md` and document the OVHcloud implementation of this control. The checker validates that the file exists and contains a normative requirement statement (MUST/SHALL/required/mandatory).

*Scope:* `file` — `docs/security/waf-sec-120-ovh-identity-access.md`

*Assertions:*
* `content` matches pattern `(?i)MUST|SHALL|required|mandatory|enforced|documented` — Policy file `docs/security/waf-sec-120-ovh-identity-access.md` must contain a normative requirement statement.

*Remediation:* Create or update `docs/security/waf-sec-120-ovh-identity-access.md`. State the requirement, how it is implemented for OVHcloud, the review cadence, and the owner.

.Compliant

[source,text]
----
docs/security/waf-sec-120-ovh-identity-access.md:
- The OVHcloud implementation of WAF-SEC-120 is documented.
- Implementation status and owner are recorded.
- Review cadence is defined (e.g. quarterly).
----

.Non-Compliant

[source,text]
----
# `docs/security/waf-sec-120-ovh-identity-access.md` is missing or does not contain a normative requirement.
# WAF-SEC-120 violation: OVHcloud control is not documented
----

=== waf-sec-120.tf.hcloud.volume-backups-enabled

*Engine:* `terraform` | *Provider:* hcloud | *Automated:* Yes

*Hetzner Cloud volumes must have backups enabled*

All hcloud_volume resources storing production data must have backups enabled via hcloud_volume or server backup settings, with documented retention and recovery procedures.

*Scope:* `resource` — `hcloud_volume`

*Assertions:*
* `name` attribute exists — Hetzner Cloud volume must have backups enabled or documented.

*Remediation:* Enable backups on hcloud_volume resources or the attached hcloud_server. Document backup retention and recovery runbooks.

.Compliant

[source,terraform]
----
resource "hcloud_volume" "app" {
  name      = "app-data"
  size      = 100
  server_id = hcloud_server.app.id
  # backups enabled via server or volume backup policy
}
----

.Non-Compliant

[source,terraform]
----
resource "hcloud_volume" "app" {
  name      = "app-data"
  size      = 100
  server_id = hcloud_server.app.id
  # WAF-SEC-120 violation: backups not verified
}
----
