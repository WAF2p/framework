= WAF-SEC-030 – Encryption at Rest with CMK
:page-toc: right
:control-id: WAF-SEC-030
:pillar: security
:severity: high
:category: identity-access
:automatable: High
:description: All data stores containing sensitive or classified data MUST be encrypted at rest using customer-managed keys (CMK) stored in AWS KMS. Automatic key rotation MUST be enabled for all CMKs. Encryption using only provider-managed keys (SSE-S3/AES256) is NOT sufficient for sensitive, PII, financial, or regulated data. [.metadata]
*Pillar:* Security | *Severity:* High | *Category:* Identity Access | *Automatable:* High

== Description

All data stores containing sensitive or classified data MUST be encrypted at rest using customer-managed keys (CMK) stored in AWS KMS. Automatic key rotation MUST be enabled for all CMKs. Encryption using only provider-managed keys (SSE-S3/AES256) is NOT sufficient for sensitive, PII, financial, or regulated data. KMS key deletion windows MUST be set to a minimum of 7 days. KMS key policies MUST restrict access to explicitly authorized principals only.

== Rationale

[cols="1,3"]
|===
|Risk |Description

|*Risk* |Sensitive data is exposed if storage or transport lacks strong encryption.

|*Risk* |Compromised keys or weak key rotation extend the blast radius of a breach.

|===

== Requirements

* All data stores containing sensitive or classified data MUST be encrypted at rest using customer-managed keys (CMK) stored in AWS KMS.
* Automatic key rotation MUST be enabled for all CMKs.
* KMS key deletion windows MUST be set to a minimum of 7 days.
* KMS key policies MUST restrict access to explicitly authorized principals only.

== Implementation Guidance

1. Implement the required configuration as code in Terraform or equivalent IaC.
2. Add an automated check to CI/CD so deviations are caught before deployment.

== Checks

=== waf-sec-030.tf.aws.rds-encryption-enabled

*Engine:* `terraform` | *Provider:* aws | *Automated:* Yes

*RDS instances and clusters must be encrypted at rest with a CMK*

All RDS database instances and Aurora clusters must have storage_encrypted = true and must reference a customer-managed KMS key via kms_key_id.

*Scope:* `resource` — `aws_db_instance`, `aws_rds_cluster`

*Assertions:*
* `storage_encrypted` is true — RDS instance/cluster must have storage encryption enabled (storage_encrypted = true).
* `kms_key_id` attribute exists — RDS instance/cluster must use a customer-managed KMS key (kms_key_id must be set).

*Remediation:* Set storage_encrypted = true and kms_key_id = aws_kms_key.rds_key.arn on the aws_db_instance or aws_rds_cluster resource. Note: enabling encryption on an existing unencrypted RDS instance requires creating an encrypted snapshot and restoring to a new instance. Plan for a maintenance window.

.Compliant

[source,terraform]
----
resource "aws_kms_key" "rds" {
  description             = "CMK for RDS encryption"
  enable_key_rotation     = true
  deletion_window_in_days = 30
}
resource "aws_db_instance" "main" {
  identifier        = "app-db-prod"
  engine            = "postgres"
  instance_class    = "db.t3.medium"
  storage_encrypted = true
  kms_key_id        = aws_kms_key.rds.arn
  # ... other required attributes
}
----

.Non-Compliant

[source,terraform]
----
resource "aws_db_instance" "main" {
  identifier        = "app-db-prod"
  engine            = "postgres"
  instance_class    = "db.t3.medium"
  storage_encrypted = false  # WAF-SEC-030 violation
  # kms_key_id not set – using default AWS-managed key
}
----

=== waf-sec-030.tf.aws.kms-key-rotation

*Engine:* `terraform` | *Provider:* aws | *Automated:* Yes

*KMS keys must have automatic rotation enabled and a sufficient deletion window*

All customer-managed KMS keys must have enable_key_rotation = true and deletion_window_in_days >= 7 to ensure keys are regularly rotated and accidental deletion can be recovered.

*Scope:* `resource` — `aws_kms_key`

*Assertions:*
* `enable_key_rotation` is true — KMS key must have automatic rotation enabled (enable_key_rotation = true).
* `deletion_window_in_days` greater than or equal `7` — KMS key deletion window must be at least 7 days to allow recovery from accidental deletion.

*Remediation:* Set enable_key_rotation = true on all aws_kms_key resources. Set deletion_window_in_days to at least 7 (recommend 30 for production keys). Note: key rotation does not apply to asymmetric keys or keys in external key stores; those require separate rotation procedures.

.Compliant

[source,terraform]
----
resource "aws_kms_key" "app_data" {
  description             = "CMK for application data encryption"
  enable_key_rotation     = true
  deletion_window_in_days = 30
  tags = {
    owner       = "platform-team"
    environment = "production"
  }
}
----

.Non-Compliant

[source,terraform]
----
resource "aws_kms_key" "app_data" {
  description             = "CMK for application data"
  enable_key_rotation     = false   # WAF-SEC-030 violation
  deletion_window_in_days = 3       # WAF-SEC-030 violation: below 7-day minimum
}
----

=== waf-sec-030.tf.azurerm.key-vault-key-expiration

*Engine:* `terraform` | *Provider:* azurerm | *Automated:* Yes

*Azure Key Vault keys used for encryption must have an expiration date*

All azurerm_key_vault_key resources that protect sensitive data must have expiration_date set to enforce key lifecycle and rotation.

*Scope:* `resource` — `azurerm_key_vault_key`

*Assertions:*
* `expiration_date` attribute exists — Key Vault key must have an expiration_date for lifecycle management.

*Remediation:* Set expiration_date on every azurerm_key_vault_key resource used for workload encryption. Establish a key rotation process that refreshes keys before expiration.

.Compliant

[source,terraform]
----
resource "azurerm_key_vault_key" "app" {
  name         = "app-encryption-key"
  key_vault_id = azurerm_key_vault.main.id
  key_type     = "RSA"
  key_size     = 2048
  expiration_date = "2026-01-01T00:00:00Z"
}
----

.Non-Compliant

[source,terraform]
----
resource "azurerm_key_vault_key" "app" {
  name         = "app-encryption-key"
  key_vault_id = azurerm_key_vault.main.id
  key_type     = "RSA"
  key_size     = 2048
  # expiration_date not set
}
----

=== waf-sec-030.tf.azurerm.key-vault-purge-protection

*Engine:* `terraform` | *Provider:* azurerm | *Automated:* Yes

*Azure Key Vault must have purge protection and soft delete enabled*

All azurerm_key_vault resources must have purge_protection_enabled = true and soft_delete_retention_days >= 7 to protect against accidental or malicious key destruction.

*Scope:* `resource` — `azurerm_key_vault`

*Assertions:*
* `purge_protection_enabled` is true — Key Vault purge protection must be enabled.
* `soft_delete_retention_days` greater than or equal `7` — Key Vault soft delete retention must be at least 7 days.

*Remediation:* Set purge_protection_enabled = true and soft_delete_retention_days to at least 7 on every azurerm_key_vault resource that stores workload keys.

.Compliant

[source,terraform]
----
resource "azurerm_key_vault" "main" {
  name                        = "workload-keyvault"
  location                    = azurerm_resource_group.main.location
  resource_group_name         = azurerm_resource_group.main.name
  tenant_id                   = data.azurerm_client_config.current.tenant_id
  sku_name                    = "standard"
  soft_delete_retention_days  = 7
  purge_protection_enabled    = true
}
----

.Non-Compliant

[source,terraform]
----
resource "azurerm_key_vault" "main" {
  name                        = "workload-keyvault"
  location                    = azurerm_resource_group.main.location
  resource_group_name         = azurerm_resource_group.main.name
  tenant_id                   = data.azurerm_client_config.current.tenant_id
  sku_name                    = "standard"
  # purge_protection_enabled defaults to false
}
----

=== waf-sec-030.tf.google.sql-cmek-encryption

*Engine:* `terraform` | *Provider:* google | *Automated:* Yes

*Cloud SQL instances must be encrypted with a customer-managed key*

All google_sql_database_instance resources must reference a customer-managed encryption key via encryption_key_name.

*Scope:* `resource` — `google_sql_database_instance`

*Assertions:*
* `settings.encryption_key_name` attribute exists — Cloud SQL instance must use a customer-managed encryption key (CMEK).

*Remediation:* Set encryption_key_name to a Cloud KMS key for every google_sql_database_instance that stores sensitive or regulated data.

.Compliant

[source,terraform]
----
resource "google_sql_database_instance" "main" {
  name             = "app-db"
  database_version = "POSTGRES_15"
  region           = "europe-west3"
  settings {
    tier = "db-custom-2-7680"
    encryption_key_name = google_kms_crypto_key.db_key.id
  }
}
----

.Non-Compliant

[source,terraform]
----
resource "google_sql_database_instance" "main" {
  name             = "app-db"
  database_version = "POSTGRES_15"
  region           = "europe-west3"
  settings {
    tier = "db-custom-2-7680"
    # encryption_key_name not set – uses Google-managed key
  }
}
----

=== waf-sec-030.tf.google.kms-key-rotation

*Engine:* `terraform` | *Provider:* google | *Automated:* Yes

*Cloud KMS keys must have a rotation period configured*

All google_kms_crypto_key resources must have rotation_period set to enforce regular key rotation.

*Scope:* `resource` — `google_kms_crypto_key`

*Assertions:*
* `rotation_period` attribute exists — Cloud KMS key must have a rotation_period configured.

*Remediation:* Set rotation_period (e.g., "7776000s" for 90 days) on every google_kms_crypto_key resource used for workload encryption.

.Compliant

[source,terraform]
----
resource "google_kms_crypto_key" "app" {
  name            = "app-key"
  key_ring        = google_kms_key_ring.app.id
  rotation_period = "7776000s"
}
----

.Non-Compliant

[source,terraform]
----
resource "google_kms_crypto_key" "app" {
  name     = "app-key"
  key_ring = google_kms_key_ring.app.id
  # rotation_period not set
}
----

=== waf-sec-030.tf.stackit.resource-encryption-enabled

*Engine:* `terraform` | *Provider:* stackit | *Automated:* Yes

*STACKIT managed resources must use encryption at rest*

STACKIT resources that store data (e.g., stackit_postgres_flex_instance, stackit_redis_instance, stackit_opensearch_instance, stackit_mysql_instance) must have encryption at rest enabled or use a customer-managed key where supported.

*Scope:* `resource` — `stackit_postgres_flex_instance`, `stackit_mysql_instance`, `stackit_redis_instance`, `stackit_opensearch_instance`, `stackit_object_storage_bucket`

*Assertions:*
* `name` attribute exists — STACKIT data resource must be defined with encryption at rest enabled by default or explicitly configured.

*Remediation:* Enable encryption at rest on all STACKIT managed data services. Use customer-managed keys via stackit_object_storage_bucket or service-specific encryption settings where available.

.Compliant

[source,terraform]
----
resource "stackit_postgres_flex_instance" "app" {
  project_id = var.stackit_project_id
  name       = "app-db"
  version    = "15"
  # encryption enabled by default; CMK configured via STACKIT console/API
}
----

.Non-Compliant

[source,terraform]
----
resource "stackit_postgres_flex_instance" "app" {
  project_id = var.stackit_project_id
  name       = "app-db"
  # WAF-SEC-030 violation: encryption not verified or disabled
}
----

*Assertions:*

*Remediation:* Create or update `docs/security/waf-sec-030-ovh-identity-access.md`. State the requirement, how it is implemented for OVHcloud, the review cadence, and the owner.

=== waf-sec-030.tf.hcloud.volume-encryption

*Engine:* `terraform` | *Provider:* hcloud | *Automated:* Yes

*Hetzner Cloud volumes must be encrypted at rest*

All hcloud_volume resources attached to production servers must use Hetzner Cloud encryption at rest. Validate via the resource definition or a documented standard.

*Scope:* `resource` — `hcloud_volume`

*Assertions:*
* `name` attribute exists — Hetzner Cloud volume must exist and have encryption at rest enabled or documented.

*Remediation:* Create hcloud_volume resources with encryption enabled. For operating-system-level encryption, document LUKS/dm-crypt configuration in a version-controlled standard.

.Compliant

[source,terraform]
----
resource "hcloud_volume" "app" {
  name      = "app-data"
  size      = 100
  server_id = hcloud_server.app.id
  format    = "ext4"
  # Hetzner Cloud volume encryption at rest is enabled by default for new volumes
}
----

.Non-Compliant

[source,terraform]
----
resource "hcloud_volume" "app" {
  name      = "app-data"
  size      = 100
  server_id = hcloud_server.app.id
  # WAF-SEC-030 violation: encryption at rest not verified
}
----
