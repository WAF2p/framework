== Beschreibung

All container images deployed to production MUST use immutable tags to prevent post-push tampering. A Software Bill of Materials (SBOM) MUST be generated for all production container images and stored alongside the image in the registry. Third-party dependencies MUST be scanned for known CVEs before deployment using automated tooling in CI/CD pipelines. Container image signing MUST be implemented using Sigstore/Cosign or equivalent to verify image provenance and prevent deployment of unsigned or tampered images.

== Begründung

[cols="1,3"]
|===
|Risiko |Beschreibung

|*Risk* |Mutable tags allow production images to be overwritten and complicate rollbacks after incidents.

|*Risk* |Missing binary authorization lets compromised images deploy into production unnoticed.

|===

== Anforderungen

* All container images deployed to production MUST use immutable tags to prevent post-push tampering.
* A Software Bill of Materials (SBOM) MUST be generated for all production container images and stored alongside the image in the registry.
* Third-party dependencies MUST be scanned for known CVEs before deployment using automated tooling in CI/CD pipelines.
* Container image signing MUST be implemented using Sigstore/Cosign or equivalent to verify image provenance and prevent deployment of unsigned or tampered images.

== Implementierungsleitfaden

1. Document the requirement in a version-controlled policy or standard.
2. Assign ownership and establish a review cadence (e.g., quarterly).
3. Implement the required configuration as code in Terraform or equivalent IaC.

== Checks

=== waf-sec-110.tf.aws.ecr-immutable-tags

*Engine:* `terraform` | *Provider:* aws | *Automated:* Ja

*ECR repositories must enforce immutable image tags*

All aws_ecr_repository resources must have image_tag_mutability set to 'IMMUTABLE'. Mutable tags allow a tag to be overwritten with a different image after a security scan has passed, creating a window for supply chain injection that bypasses pre-deployment controls.

*Scope:* `resource` — `aws_ecr_repository`

*Assertions:*
* `image_tag_mutability` equals `IMMUTABLE` — ECR repository must use IMMUTABLE tag mutability to prevent post-push tag updates.

*Remediation:* Set image_tag_mutability = "IMMUTABLE" on all aws_ecr_repository resources. Update CI/CD pipelines to tag images with unique identifiers such as the Git commit SHA or a semantic version (e.g., v1.2.3-sha-abc1234) rather than mutable tags like 'latest'. Existing pipelines using 'latest' must be updated to use versioned tags before enabling immutability.

.Compliant

[source,terraform]
----
resource "aws_ecr_repository" "app" {
  name                 = "my-application"
  image_tag_mutability = "IMMUTABLE"

  image_scanning_configuration {
    scan_on_push = true
  }

  encryption_configuration {
    encryption_type = "KMS"
    kms_key         = aws_kms_key.ecr.arn
  }

  tags = {
    environment = "production"
    owner       = "platform-team"
  }
}
----

.Non-Compliant

[source,terraform]
----
resource "aws_ecr_repository" "app" {
  name                 = "my-application"
  image_tag_mutability = "MUTABLE"  # WAF-SEC-110 violation: allows tag overwrite
  # No image_scanning_configuration    # WAF-SEC-110 violation: scan-on-push required
}
----

=== waf-sec-110.tf.google.binary-authorization

*Engine:* `terraform` | *Provider:* google | *Automated:* Ja

*GCP Binary Authorization must require attestation for production deployments*

A google_binary_authorization_policy resource must define a default_admission_rule with evaluation_mode "REQUIRE_ATTESTATION" so that only signed, trusted container images can be deployed to production GKE clusters.

*Scope:* `resource` — `google_binary_authorization_policy`

*Assertions:*
* `default_admission_rule` attribute exists — Binary Authorization policy must define a default_admission_rule.

*Remediation:* Create a google_binary_authorization_policy with default_admission_rule evaluation_mode = "REQUIRE_ATTESTATION" and an attestation authority (google_binary_authorization_attestor) used by the CI/CD pipeline to sign images. Configure GKE clusters to enable Binary Authorization.

.Compliant

[source,terraform]
----
resource "google_binary_authorization_policy" "prod" {
  default_admission_rule {
    evaluation_mode  = "REQUIRE_ATTESTATION"
    enforcement_mode = "ENFORCED_BLOCK_AND_AUDIT_LOG"
    require_attestations_by = [
      google_binary_authorization_attestor.ci.id,
    ]
  }
}

resource "google_binary_authorization_attestor" "ci" {
  name = "ci-pipeline-attestor"
  attestation_authority_note {
    note_reference = google_container_analysis_note.ci.name
    public_keys {
      ascii_armored_pgp_public_key = file("ci-pipeline.pub")
    }
  }
}
----

.Non-Compliant

[source,terraform]
----
resource "google_binary_authorization_policy" "prod" {
  default_admission_rule {
    evaluation_mode  = "ALWAYS_ALLOW"  # WAF-SEC-110 violation: any image can deploy
    enforcement_mode = "ENFORCED_BLOCK_AND_AUDIT_LOG"
  }
}
----

=== waf-sec-110.tf.aws.ecr-scan-enabled

*Engine:* `terraform` | *Provider:* aws | *Automated:* Ja

*ECR repositories must have image scanning enabled on push*

All aws_ecr_repository resources must include an image_scanning_configuration block with scan_on_push = true to ensure every image pushed to the registry is automatically scanned for known CVEs before it can be deployed to production workloads.

*Scope:* `resource` — `aws_ecr_repository`

*Assertions:*
* `image_scanning_configuration` attribute exists — ECR repository must have image_scanning_configuration defined with scan_on_push enabled.

*Remediation:* Add an image_scanning_configuration block with scan_on_push = true to all aws_ecr_repository resources. For enhanced scanning including programming language libraries (not just OS packages), enable Amazon Inspector integration at the account level and configure ECR enhanced scanning via the AWS Inspector console or API. Integrate ECR scan result checks into CI/CD deployment gates.

.Compliant

[source,terraform]
----
resource "aws_ecr_repository" "app" {
  name                 = "my-application"
  image_tag_mutability = "IMMUTABLE"

  image_scanning_configuration {
    scan_on_push = true
  }
}
----

.Non-Compliant

[source,terraform]
----
resource "aws_ecr_repository" "app" {
  name                 = "my-application"
  image_tag_mutability = "IMMUTABLE"
  # Missing image_scanning_configuration – WAF-SEC-110 violation
  # Images pushed to this repository are not scanned for CVEs
}
----
