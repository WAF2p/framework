[.metadata]
*Pillar:* Security | *Severity:* High | *Category:* Identity Access | *Automatable:* High

== Description

AWS CloudTrail MUST be enabled as a multi-region trail with log file validation and global service event inclusion. GuardDuty MUST be enabled in all active AWS regions. AWS Security Hub or an equivalent SIEM MUST be enabled to aggregate and correlate security findings centrally. CloudTrail logs MUST be stored in a dedicated S3 bucket with server-side encryption and MFA delete enabled. Alerts MUST be configured for critical Security Hub findings and GuardDuty HIGH/CRITICAL severity findings. All security alerts MUST route to an on-call escalation channel with a defined response SLA.

== Rationale

[cols="1,3"]
|===
|Risk |Description

|*Risk* |Security incidents go undetected without centralised, tamper-proof audit logs.

|*Risk* |Forensic investigations are delayed or inconclusive when logs are missing.

|===

== Requirements

* AWS CloudTrail MUST be enabled as a multi-region trail with log file validation and global service event inclusion.
* GuardDuty MUST be enabled in all active AWS regions.
* AWS Security Hub or an equivalent SIEM MUST be enabled to aggregate and correlate security findings centrally.
* CloudTrail logs MUST be stored in a dedicated S3 bucket with server-side encryption and MFA delete enabled.
* Alerts MUST be configured for critical Security Hub findings and GuardDuty HIGH/CRITICAL severity findings.
* All security alerts MUST route to an on-call escalation channel with a defined response SLA.

== Implementation Guidance

1. Implement the required configuration as code in Terraform or equivalent IaC.
2. Add an automated check to CI/CD so deviations are caught before deployment.

== Checks

=== waf-sec-080.tf.aws.cloudtrail-multi-region

*Engine:* `terraform` | *Provider:* aws | *Automated:* Yes

*CloudTrail must be enabled as a multi-region trail with log file validation*

An aws_cloudtrail resource must exist with is_multi_region_trail = true, enable_log_file_validation = true, and include_global_service_events = true to ensure complete API activity coverage across all regions and global services.

*Scope:* `resource` — `aws_cloudtrail`

*Assertions:*
* `is_multi_region_trail` is true — CloudTrail must be a multi-region trail to capture API activity in all regions.
* `enable_log_file_validation` is true — CloudTrail log file validation must be enabled to detect log tampering.
* `include_global_service_events` is true — CloudTrail must include global service events (e.g., IAM API calls).

*Remediation:* Set is_multi_region_trail = true, enable_log_file_validation = true, and include_global_service_events = true on the aws_cloudtrail resource. Ensure the trail S3 bucket has SSE-KMS encryption and is not publicly accessible.

.Compliant

[source,terraform]
----
resource "aws_cloudtrail" "main" {
  name                          = "org-cloudtrail"
  s3_bucket_name                = aws_s3_bucket.cloudtrail_logs.id
  is_multi_region_trail         = true
  enable_log_file_validation    = true
  include_global_service_events = true
  kms_key_id                    = aws_kms_key.cloudtrail.arn
  tags = {
    owner       = "security-team"
    environment = "all"
  }
}
----

.Non-Compliant

[source,terraform]
----
resource "aws_cloudtrail" "main" {
  name                          = "org-cloudtrail"
  s3_bucket_name                = aws_s3_bucket.cloudtrail_logs.id
  is_multi_region_trail         = false  # WAF-SEC-080 violation
  enable_log_file_validation    = false  # WAF-SEC-080 violation
  include_global_service_events = false  # WAF-SEC-080 violation
}
----

=== waf-sec-080.tf.aws.guardduty-enabled

*Engine:* `terraform` | *Provider:* aws | *Automated:* Yes

*GuardDuty must be enabled in all active regions*

An aws_guardduty_detector resource must exist with enable = true in each active AWS region. GuardDuty provides continuous threat detection and is a foundational security detective control.

*Scope:* `resource` — `aws_guardduty_detector`

*Assertions:*
* `enable` is true — GuardDuty detector must be enabled (enable = true).

*Remediation:* Create an aws_guardduty_detector resource with enable = true in each active AWS region. For multi-account environments, configure GuardDuty at the organization level using aws_guardduty_organization_configuration to automatically enable GuardDuty in all existing and future member accounts.

.Compliant

[source,terraform]
----
resource "aws_guardduty_detector" "main" {
  enable = true
  datasources {
    s3_logs { enable = true }
    kubernetes { audit_logs { enable = true } }
    malware_protection { scan_ec2_instance_with_findings { ebs_volumes { enable = true } } }
  }
}
----

.Non-Compliant

[source,terraform]
----
resource "aws_guardduty_detector" "main" {
  enable = false  # WAF-SEC-080 violation: GuardDuty must be enabled
}
----

=== waf-sec-080.tf.aws.securityhub-enabled

*Engine:* `terraform` | *Provider:* aws | *Automated:* Yes

*AWS Security Hub must be enabled*

An aws_securityhub_account resource must exist to enable Security Hub in the account, providing centralized aggregation of security findings from GuardDuty, Amazon Inspector, AWS Config, Macie, and other integrated services.

*Scope:* `resource` — `aws_securityhub_account`

*Assertions:*
* `` block exists — AWS Security Hub must be enabled (aws_securityhub_account resource must exist).

*Remediation:* Add an aws_securityhub_account resource to the Terraform configuration. After enabling Security Hub, activate standards using aws_securityhub_standards_subscription: - arn:aws:securityhub:::ruleset/cis-aws-foundations-benchmark/v/1.4.0 - arn:aws:securityhub:REGION::standards/aws-foundational-security-best-practices/v/1.0.0

.Compliant

[source,terraform]
----
resource "aws_securityhub_account" "main" {}
resource "aws_securityhub_standards_subscription" "cis" {
  standards_arn = "arn:aws:securityhub:::ruleset/cis-aws-foundations-benchmark/v/1.4.0"
  depends_on    = [aws_securityhub_account.main]
}
resource "aws_securityhub_standards_subscription" "fsbp" {
  standards_arn = "arn:aws:securityhub:${data.aws_region.current.name}::standards/aws-foundational-security-best-practices/v/1.0.0"
  depends_on    = [aws_securityhub_account.main]
}
----

.Non-Compliant

[source,terraform]
----
# aws_securityhub_account resource absent – WAF-SEC-080 violation
# Security Hub is not enabled in this account
----

=== waf-sec-080.tf.azurerm.sentinel-enabled

*Engine:* `terraform` | *Provider:* azurerm | *Automated:* Yes

*Azure Sentinel must be onboarded to a Log Analytics workspace*

An azurerm_sentinel_log_analytics_workspace_onboarding resource must exist so that Azure Sentinel can centrally collect, detect, and investigate security events across the subscription.

*Scope:* `resource` — `azurerm_sentinel_log_analytics_workspace_onboarding`

*Assertions:*
* `workspace_id` attribute exists — Azure Sentinel onboarding must reference a Log Analytics workspace ID.

*Remediation:* Create a Log Analytics workspace and onboard it to Sentinel using azurerm_sentinel_log_analytics_workspace_onboarding. Configure data connectors for Azure Activity, Microsoft Entra ID, and any workload-specific sources.

.Compliant

[source,terraform]
----
resource "azurerm_log_analytics_workspace" "sec" {
  name                = "sec-workspace"
  location            = azurerm_resource_group.sec.location
  resource_group_name = azurerm_resource_group.sec.name
  sku                 = "PerGB2018"
}

resource "azurerm_sentinel_log_analytics_workspace_onboarding" "sec" {
  workspace_id = azurerm_log_analytics_workspace.sec.id
}
----

.Non-Compliant

[source,terraform]
----
# No azurerm_sentinel_log_analytics_workspace_onboarding resource exists.
# WAF-SEC-080 violation: Azure Sentinel is not enabled for threat detection
----

=== waf-sec-080.tf.google.logging-project-sink

*Engine:* `terraform` | *Provider:* google | *Automated:* Yes

*GCP audit logs must be exported to a persistent destination*

A google_logging_project_sink resource must exist to route GCP audit logs to Cloud Logging, BigQuery, Cloud Storage, or Pub/Sub for long-term retention and analysis.

*Scope:* `resource` — `google_logging_project_sink`

*Assertions:*
* `destination` attribute exists — GCP logging sink must define a persistent destination for audit logs.

*Remediation:* Create a google_logging_project_sink with filter including audit log events and destination pointing to a secure BigQuery dataset or Cloud Storage bucket. Ensure the sink service account has appropriate permissions.

.Compliant

[source,terraform]
----
resource "google_logging_project_sink" "audit" {
  name        = "audit-logs-to-bigquery"
  destination = "bigquery.googleapis.com/projects/${var.project_id}/datasets/audit_logs"
  filter      = "protoPayload.@type=\"type.googleapis.com/google.cloud.audit.AuditLog\""

  unique_writer_identity = true
}
----

.Non-Compliant

[source,terraform]
----
# No google_logging_project_sink routes audit logs to a persistent store.
# WAF-SEC-080 violation: GCP audit logs lack central export
----

=== waf-sec-080.tf.google.security-command-center

*Engine:* `terraform` | *Provider:* google | *Automated:* Yes

*Google Security Command Center must be enabled*

A google_security_center_notification_config or google_scc_notification_config resource must exist to enable Security Command Center findings and centralize threat detection across the GCP organization.

*Scope:* `resource` — `google_security_center_notification_config`, `google_scc_notification_config`

*Assertions:*
* `pubsub_topic` attribute exists — Security Command Center notification config must route findings to a Pub/Sub topic.

*Remediation:* Enable Security Command Center at the organization level and create a google_security_center_notification_config or google_scc_notification_config to route HIGH/CRITICAL findings to a Pub/Sub topic and on-call channel.

.Compliant

[source,terraform]
----
resource "google_security_center_notification_config" "high_critical" {
  config_id    = "high-critical-findings"
  organization = var.org_id
  pubsub_topic = google_pubsub_topic.scc.id

  streaming_config {
    filter = "severity = \"HIGH\" OR severity = \"CRITICAL\""
  }
}
----

.Non-Compliant

[source,terraform]
----
# No Security Command Center notification config exists.
# WAF-SEC-080 violation: GCP threat detection not centralized
----

=== waf-sec-080.config.ovh.ovh-identity-access

*Engine:* `config` | *Provider:* ovh | *Automated:* Yes

*OVHcloud workloads must centralise audit and security logs*

A version-controlled policy document must exist at `docs/security/waf-sec-080-ovh-identity-access.md` and document the OVHcloud implementation of this control. The checker validates that the file exists and contains a normative requirement statement (MUST/SHALL/required/mandatory).

*Scope:* `file` — `docs/security/waf-sec-080-ovh-identity-access.md`

*Assertions:*
* `content` matches pattern `(?i)MUST|SHALL|required|mandatory|enforced|documented` — Policy file `docs/security/waf-sec-080-ovh-identity-access.md` must contain a normative requirement statement.

*Remediation:* Create or update `docs/security/waf-sec-080-ovh-identity-access.md`. State the requirement, how it is implemented for OVHcloud, the review cadence, and the owner.

.Compliant

[source,text]
----
docs/security/waf-sec-080-ovh-identity-access.md:
- The OVHcloud implementation of WAF-SEC-080 is documented.
- Implementation status and owner are recorded.
- Review cadence is defined (e.g. quarterly).
----

=== waf-sec-080.tf.hcloud.server-backups-and-logs

*Engine:* `terraform` | *Provider:* hcloud | *Automated:* Yes

*Hetzner Cloud servers must have backup and log forwarding enabled*

Hetzner Cloud production servers must have backups enabled and forward security logs to a centralised store. Backup and log retention must be defined.

*Scope:* `resource` — `hcloud_server`

*Assertions:*
* `backups` is true — Hetzner Cloud production server must have backups enabled for log and state retention.

*Remediation:* Enable backups on hcloud_server resources and configure log forwarding via cloud-init or configuration management. Document retention and alerting.

.Compliant

[source,terraform]
----
resource "hcloud_server" "app" {
  name        = "app-server"
  server_type = "cx22"
  image       = "ubuntu-22.04"
  backups     = true
  # Log forwarding configured via cloud-init
}
----

.Non-Compliant

[source,terraform]
----
resource "hcloud_server" "app" {
  name        = "app-server"
  server_type = "cx22"
  image       = "ubuntu-22.04"
  backups     = false  # WAF-SEC-080 violation: backups disabled
}
----
