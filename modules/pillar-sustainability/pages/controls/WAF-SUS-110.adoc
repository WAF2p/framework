== Description

New workloads and data stores MUST document carbon intensity alongside latency, cost, and compliance factors when selecting regions. Region selection decisions MUST be captured in an Architecture Decision Record or equivalent register. Batch and non-latency-sensitive workloads SHOULD prefer lower-carbon regions where data residency allows. Carbon intensity assumptions MUST be revisited annually using current provider data.

== Rationale

[cols="1,3"]
|===
|Risk |Description

|*Risk* |Ignoring grid carbon intensity when selecting regions increases emissions without business justification.

|*Risk* |Undocumented region decisions prevent sustainability audits and optimization over time.

|===

== Requirements

* New workloads and data stores MUST document carbon intensity alongside latency, cost, and compliance factors when selecting regions.
* Region selection decisions MUST be captured in an Architecture Decision Record or equivalent register.
* Batch and non-latency-sensitive workloads SHOULD prefer lower-carbon regions where data residency allows.
* Carbon intensity assumptions MUST be revisited annually using current provider data.

== Implementation Guidance

. Document the requirement in a version-controlled policy, ADR, or standard.
. Assign ownership and establish a review cadence (e.g., quarterly).
. Implement the required configuration as code in Terraform or equivalent IaC.
