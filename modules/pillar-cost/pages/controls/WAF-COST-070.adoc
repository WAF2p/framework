== Description

Logging and observability resources MUST be organized in explicit retention tiers: Hot (7-30 days), Warm (30-90 days), Cold (90-365 days), Archive (>365 days). CloudWatch Log Groups MUST NOT have retention_in_days = 0 (infinite). Operational log groups MUST have retention_in_days <= 365. DEBUG-level logging in production is prohibited without Architecture Board justification. High-volume trace sampling MUST be configured for services with >1000 req/s.

== Rationale

[cols="1,3"]
|===
|Risk |Description

|*Risk* |Security incidents go undetected without centralised, tamper-proof audit logs.

|*Risk* |Forensic investigations are delayed or inconclusive when logs are missing.

|===

== Requirements

* Logging and observability resources MUST be organized in explicit retention tiers: Hot (7-30 days), Warm (30-90 days), Cold (90-365 days), Archive (>365 days).
* CloudWatch Log Groups MUST NOT have retention_in_days = 0 (infinite).
* Operational log groups MUST have retention_in_days <= 365.
* High-volume trace sampling MUST be configured for services with >1000 req/s.

== Implementation Guidance

1. Document the requirement in a version-controlled policy or standard.
2. Assign ownership and establish a review cadence (e.g., quarterly).
3. Implement the required configuration as code in Terraform or equivalent IaC.

== Checks

=== waf-cost-070.tf.aws.cloudwatch-retention-not-infinite

*Engine:* `terraform` | *Provider:* aws | *Automated:* Yes

*CloudWatch Log Groups must not use infinite retention (retention_in_days = 0)*

aws_cloudwatch_log_group resources must have retention_in_days set to a value > 0. The value 0 means infinite retention. Omitting retention_in_days also results in infinite retention. Both configurations constitute Architectural Cost Debt.

*Scope:* `resource` — `aws_cloudwatch_log_group`

*Assertions:*
* `retention_in_days` attribute exists — retention_in_days must be explicitly set. Missing value defaults to infinite retention.
* `retention_in_days` greater than or equal `1` — retention_in_days must be >= 1. Value 0 means infinite retention (cost debt).

*Remediation:* Set retention_in_days on all aws_cloudwatch_log_group resources. Recommended values by tier: operational=30, access=90, security-audit=365. Compliance-driven long retention: use S3 export + lifecycle instead of CloudWatch.

.Compliant

[source,terraform]
----
resource "aws_cloudwatch_log_group" "app_logs" {
  name              = "/app/production/payment-service"
  retention_in_days = 30
  tags = merge(module.mandatory_tags.tags, {
    log-tier = "hot"
    log-type = "operational"
  })
}
----

.Non-Compliant

[source,terraform]
----
resource "aws_cloudwatch_log_group" "app_logs" {
  name = "/app/production/payment-service"
  # retention_in_days omitted = infinite retention = violation
}
----

=== waf-cost-070.tf.aws.cloudwatch-operational-retention-max-365

*Engine:* `terraform` | *Provider:* aws | *Automated:* Yes

*Operational CloudWatch Log Groups should have retention <= 365 days*

CloudWatch Log Groups tagged as operational (log-type = operational or log-tier = hot/warm) should have retention_in_days <= 365. Long-term compliance logs should be exported to S3 with lifecycle policies, not stored in CloudWatch indefinitely.

*Scope:* `resource` — `aws_cloudwatch_log_group`

*Assertions:*
* `retention_in_days` less than or equal `365` — Operational log groups should have retention <= 365 days. Use S3 export for long-term retention.

*Remediation:* For operational logs needing > 365 days retention: configure CloudWatch Logs subscription to export to S3, then apply S3 lifecycle policies for long-term archive. This is significantly cheaper than retaining in CloudWatch.

.Compliant

[source,terraform]
----
resource "aws_cloudwatch_log_group" "audit_logs" {
  name              = "/app/production/audit"
  retention_in_days = 90  # Within CloudWatch; exported to S3 via subscription for archival
  tags = merge(module.mandatory_tags.tags, {
    log-tier = "warm"
    log-type = "audit"
  })
}
# S3 export subscription configured separately with lifecycle to Glacier
----

.Non-Compliant

[source,terraform]
----
resource "aws_cloudwatch_log_group" "everything" {
  name              = "/app/production/all"
  retention_in_days = 2555  # 7 years in CloudWatch = very expensive
  # Should be: 90d in CloudWatch, then S3 export with Glacier lifecycle
}
----

=== waf-cost-070.tf.azurerm.log-analytics-retention-explicit

*Engine:* `terraform` | *Provider:* azurerm | *Automated:* Yes

*Azure Log Analytics workspaces must have explicit retention days configured*

Every azurerm_log_analytics_workspace resource must define retention_in_days with a finite value. Omitting the value or setting it to 0 results in indefinite retention and unbounded observability cost.

*Scope:* `resource` — `azurerm_log_analytics_workspace`

*Assertions:*
* `retention_in_days` attribute exists — Azure Log Analytics workspace must define retention_in_days.
* `retention_in_days` greater than or equal `1` — retention_in_days must be >= 1. Use Azure Storage archive for long-term retention.

*Remediation:* Set retention_in_days on every azurerm_log_analytics_workspace. Use tiered retention: operational logs 30 days, audit logs 365 days. Archive older data to Azure Storage via diagnostic settings and lifecycle policies.

.Compliant

[source,terraform]
----
resource "azurerm_log_analytics_workspace" "ops" {
  name                = "ops-workspace"
  location            = var.location
  resource_group_name = azurerm_resource_group.main.name
  sku                 = "PerGB2018"
  retention_in_days   = 30
  tags = {
    log-tier = "hot"
  }
}
----

.Non-Compliant

[source,terraform]
----
resource "azurerm_log_analytics_workspace" "ops" {
  name                = "ops-workspace"
  location            = var.location
  resource_group_name = azurerm_resource_group.main.name
  # retention_in_days omitted = default indefinite retention
}
----

=== waf-cost-070.tf.google.logging-bucket-retention

*Engine:* `terraform` | *Provider:* google | *Automated:* Yes

*GCP logging buckets must have explicit retention days configured*

Every google_logging_project_sink destination bucket or google_storage_bucket used for centralized logs must have a lifecycle_rule or retention_policy enforcing finite retention. Indefinite log storage is classified as Architectural Cost Debt.

*Scope:* `resource` — `google_storage_bucket`

*Assertions:*
* `lifecycle_rule` attribute exists — GCP log bucket must define lifecycle rules with finite retention.

*Remediation:* Define lifecycle_rules on log destination google_storage_bucket resources to transition or delete old logs. Set retention_days on google_logging_project_bucket_config resources.

.Compliant

[source,terraform]
----
resource "google_storage_bucket" "logs" {
  name          = "${var.project_id}-logs"
  location      = var.region
  storage_class = "STANDARD"

  lifecycle_rule {
    action {
      type = "Delete"
    }
    condition {
      age = 90
    }
  }
}
----

.Non-Compliant

[source,terraform]
----
resource "google_storage_bucket" "logs" {
  name     = "${var.project_id}-logs"
  location = var.region
  # No lifecycle rules – logs accumulate indefinitely
}
----
