== Beschreibung

Monthly engineering-level FinOps reviews MUST take place for all production workloads. Quarterly Architecture Board reviews covering cost debt and strategic cost decisions MUST occur. Review outputs (action items with owner and due date) MUST be documented in writing and accessible in the team's task tracking system. Reviews are mandatory, not optional – absence of reviews is a control failure.

== Begründung

[cols="1,3"]
|===
|Risiko |Beschreibung

|*Risk* |Uncontrolled cloud spend erodes budget and project viability.

|*Risk* |High lock-in or debt decisions are made without financial impact visibility.

|===

== Anforderungen

* Monthly engineering-level FinOps reviews MUST take place for all production workloads.
* Quarterly Architecture Board reviews covering cost debt and strategic cost decisions MUST occur.
* Review outputs (action items with owner and due date) MUST be documented in writing and accessible in the team's task tracking system.

== Implementierungsleitfaden

1. Document the requirement in a version-controlled policy or standard.
2. Assign ownership and establish a review cadence (e.g., quarterly).

== Checks

=== waf-cost-060.tf.any.finops-review-tag-current

*Engine:* `terraform` | *Provider:* any | *Automated:* Ja

*Workload resources should have current 'last-finops-review' tag*

Workload infrastructure resources should carry a 'last-finops-review' tag with the date (YYYY-MM-DD) of the last FinOps review. A stale review tag (> 45 days old) indicates the review cadence is not being maintained. This tag is a lightweight operational proof of an active review process.

*Scope:* `resource` — `aws_instance`, `aws_eks_cluster`, `aws_rds_cluster`, `azurerm_kubernetes_cluster`, `azurerm_virtual_machine_scale_set`, `google_container_cluster`, `stackit_project`, `ovh_cloud_project`, `hcloud_server`

*Assertions:*
* `tags` key exists — Resource is missing 'last-finops-review' tag. Monthly FinOps reviews required.

*Remediation:* After each monthly FinOps review, update the 'last-finops-review' tag on workload resources to the current date. This can be automated in CI as part of the review process. Value format: YYYY-MM-DD.

.Compliant

[source,terraform]
----
resource "aws_eks_cluster" "main" {
  name     = "payment-service-prod"
  role_arn = aws_iam_role.eks.arn

  tags = merge(module.mandatory_tags.tags, {
    last-finops-review   = "2025-03-01"
    rightsizing-reviewed = "2025-03-01"
  })

  version = "1.29"
}
----

.Non-Compliant

[source,terraform]
----
resource "aws_eks_cluster" "main" {
  name     = "payment-service-prod"
  role_arn = aws_iam_role.eks.arn
  # Missing last-finops-review tag – no evidence of review process
}
----
