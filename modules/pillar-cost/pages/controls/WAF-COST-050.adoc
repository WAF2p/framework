== Beschreibung

Every Architecture Decision Record (ADR) covering infrastructure changes MUST include a structured Cost Impact Assessment section. The assessment MUST cover: TCO estimate (EUR/year), lock-in risk score (1-5), data transfer cost estimate, operational effort (FTE/year), exit cost estimate, and 3-year NPV. ADRs with lock-in risk score >= 4 require Architecture Board approval before implementation. This control is the primary prevention mechanism for Architectural Cost Debt.

== Begründung

[cols="1,3"]
|===
|Risiko |Beschreibung

|*Risk* |Architecture decisions without cost consideration lead to lock-in and unaccountable spending.

|*Risk* |Missing lock-in assessment complicates future contract negotiations and cloud migration.

|===

== Anforderungen

* Every Architecture Decision Record (ADR) covering infrastructure changes MUST include a structured Cost Impact Assessment section.
* The assessment MUST cover: TCO estimate (EUR/year), lock-in risk score (1-5), data transfer cost estimate, operational effort (FTE/year), exit cost estimate, and 3-year NPV.

== Implementierungsleitfaden

1. Document the requirement in a version-controlled policy or standard.
2. Assign ownership and establish a review cadence (e.g., quarterly).

== Checks

=== waf-cost-050.tf.any.high-lockin-resource-tagged

*Engine:* `terraform` | *Provider:* any | *Automated:* Ja

*High lock-in resources must be tagged with lock-in risk score*

Resources from services with inherently high vendor lock-in (proprietary streaming, proprietary database services, complex managed services) should be tagged with 'lock-in-risk' to document that the lock-in was consciously evaluated. This check validates that the tag exists on known high-lock-in resource types.

*Scope:* `resource` — `aws_kinesis_stream`, `aws_kinesis_firehose_delivery_stream`, `aws_redshift_cluster`, `aws_neptune_cluster`, `aws_msk_cluster`, `azurerm_service_bus_namespace`, `azurerm_eventhub_namespace`, `azurerm_synapse_workspace`, `google_spanner_instance`, `google_bigquery_dataset`, `stackit_opensearch_instance`, `stackit_redis_instance`, `stackit_mysql_instance`, `ovh_dedicated_server`, `hcloud_server`

*Assertions:*
* `tags` key exists — High lock-in resource must have 'lock-in-risk' tag (value: 1-5) documenting conscious evaluation.

*Remediation:* Add 'lock-in-risk' tag (value: 1-5) to document that vendor lock-in was consciously evaluated. Tag value 4 or 5 requires an ADR with Architecture Board approval. See docs/adr/ for the ADR template with Cost Impact Assessment section.

.Compliant

[source,terraform]
----
resource "aws_kinesis_stream" "events" {
  name        = "payment-events"
  shard_count = 4

  tags = merge(module.mandatory_tags.tags, {
    lock-in-risk = "4"  # High lock-in; ADR-0042 documents cost impact assessment
    adr-reference = "ADR-0042"
  })
}
----

.Non-Compliant

[source,terraform]
----
resource "aws_kinesis_stream" "events" {
  name        = "payment-events"
  shard_count = 4
  tags = {
    cost-center = "data-team"
    # Missing lock-in-risk tag – no evidence of lock-in evaluation
  }
}
----

*Remediation:* Create or update `docs/cost/waf-cost-050-cost-governance.md`. State the requirement, how it is implemented for provider-agnostic, the review cadence, and the owner.
