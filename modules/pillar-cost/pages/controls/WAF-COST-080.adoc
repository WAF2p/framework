= WAF-COST-080 – Commitment & Reserved Capacity Planning
:page-toc: right
:control-id: WAF-COST-080
:pillar: cost
:severity: medium
:category: data-governance

[.metadata]
*Säule:* Cost | *Schweregrad:* Mittel | *Kategorie:* Data Governance | *Automatisierbar:* High

== Beschreibung

Compute resources with sustained utilization >= 70% over 30 days MUST be covered by Reserved Instances or Savings Plans. All persistent on-demand compute resources MUST carry a 'capacity-commitment' tag documenting their reservation status and the date of the last commitment review. Spot/Preemptible Instances are the preferred option for variable and interruptible workloads.

== Begründung

[cols="1,3"]
|===
|Risiko |Beschreibung

|*Risk* |High sustained load without capacity planning leads to expensive on-demand resources and budget variance.

|*Risk* |Missing reserved-instance or savings-plan documentation prevents optimization opportunities.

|===

== Anforderungen

* Compute resources with sustained utilization >= 70% over 30 days MUST be covered by Reserved Instances or Savings Plans.
* All persistent on-demand compute resources MUST carry a 'capacity-commitment' tag documenting their reservation status and the date of the last commitment review.

== Checks

=== waf-cost-080.tf.aws.ec2-capacity-commitment-tag

*Engine:* `terraform` | *Provider:* aws | *Automated:* Ja

*EC2 instances must declare their capacity commitment status*

All EC2 instances must carry a 'capacity-commitment' tag documenting whether the instance is covered by a reservation, savings plan, spot pricing, or on-demand. This tag proves active commitment management and enables automated coverage reporting.

*Scope:* `resource` — `aws_instance`, `aws_launch_template`

*Assertions:*
* `tags` key exists — EC2 instance missing 'capacity-commitment' tag. Reservation status must be declared.
* `tags.capacity-commitment` in `['reserved', 'savings-plan', 'spot', 'on-demand', 'reviewed']` — capacity-commitment must be: reserved, savings-plan, spot, on-demand, or reviewed.

*Remediation:* Add 'capacity-commitment' tag to all EC2 instances. Value 'reserved' or 'savings-plan' = commitment exists. Value 'on-demand' = no commitment, flagged for review. Value 'reviewed' = reviewed and consciously left on-demand (needs date + justification).

.Compliant

[source,terraform]
----
# Baseline instance with savings plan coverage
resource "aws_instance" "app" {
  ami           = data.aws_ami.ubuntu.id
  instance_type = "c5.2xlarge"
  tags = merge(module.mandatory_tags.tags, {
    rightsizing-reviewed = "2025-03-01"
    capacity-commitment  = "savings-plan"
    commitment-type      = "compute-savings-plan-1yr"
    commitment-expiry    = "2026-03-01"
  })
}

# Spot instance for CI/CD
resource "aws_instance" "ci_runner" {
  ami                    = data.aws_ami.ubuntu.id
  instance_type          = "c5.xlarge"
  instance_market_options {
    market_type = "spot"
  }
  tags = merge(module.mandatory_tags.tags, {
    capacity-commitment = "spot"
  })
}
----

.Non-Compliant

[source,terraform]
----
resource "aws_instance" "app" {
  ami           = data.aws_ami.ubuntu.id
  instance_type = "c5.2xlarge"
  tags = {
    cost-center = "fintech-platform"
    # Missing capacity-commitment – commitment status unknown
  }
}
----

=== waf-cost-080.tf.azurerm.vm-commitment-tag

*Engine:* `terraform` | *Provider:* azurerm | *Automated:* Ja

*Azure VMs must declare their capacity commitment status*

All Azure Virtual Machines must carry a 'capacity-commitment' tag documenting whether the VM is covered by a Reserved VM Instance, Azure Savings Plan, Spot pricing, or On-Demand. This enables automated coverage gap detection.

*Scope:* `resource` — `azurerm_linux_virtual_machine`, `azurerm_windows_virtual_machine`, `azurerm_virtual_machine_scale_set`

*Assertions:*
* `tags` key exists — Azure VM missing 'capacity-commitment' tag.

*Remediation:* Add 'capacity-commitment' tag to all Azure VM resources. Use Azure Advisor to identify baseline VMs that should have Reserved VM Instances.

.Compliant

[source,terraform]
----
resource "azurerm_linux_virtual_machine" "app" {
  name                = "vm-payment-app"
  resource_group_name = azurerm_resource_group.main.name
  location            = var.location
  size                = "Standard_D4s_v3"
  tags = merge(local.mandatory_tags, {
    "capacity-commitment" = "reserved"
    "commitment-type"     = "1yr-no-upfront"
  })
}
----

.Non-Compliant

[source,terraform]
----
resource "azurerm_linux_virtual_machine" "app" {
  name     = "vm-payment-app"
  location = var.location
  size     = "Standard_D8s_v3"
  # Missing: capacity-commitment tag
}
----

=== waf-cost-080.tf.google.vm-capacity-commitment-label

*Engine:* `terraform` | *Provider:* google | *Automated:* Ja

*GCP compute instances must declare capacity commitment status*

All persistent GCP Compute Engine instances and GKE node pools must carry a 'capacity-commitment' label documenting whether the resource is covered by Committed Use Discounts, Spot/Preemptible pricing, or On-Demand.

*Scope:* `resource` — `google_compute_instance`, `google_container_node_pool`

*Assertions:*
* `labels` key exists — GCP compute instance missing 'capacity-commitment' label.

*Remediation:* Add 'capacity-commitment' label to all google_compute_instance and google_container_node_pool resources. Use CUD analysis to identify baseline workloads that should have Committed Use Discounts.

.Compliant

[source,terraform]
----
resource "google_compute_instance" "app" {
  name         = "vm-payment-app"
  machine_type = "e2-standard-4"
  zone         = var.zone

  labels = merge(module.mandatory_tags.labels, {
    capacity-commitment = "cud-1yr"
    commitment-expiry   = "2026-03-01"
  })
}
----

.Non-Compliant

[source,terraform]
----
resource "google_compute_instance" "app" {
  name         = "vm-payment-app"
  machine_type = "e2-standard-4"
  zone         = var.zone
  # Missing capacity-commitment label – on-demand assumed
}
----
