*Säule:* Agentic | *Schweregrad:* Hoch | *Kategorie:* Logging Monitoring | *Automatisierbar:* High

== Beschreibung

Fail-safe, alignment, and verification mechanisms MUST be in place. Content filters MUST be configured to block inappropriate content. Action boundaries MUST prevent agents from performing unauthorized actions. Human-in-the-loop MUST be configured for sensitive decisions. Guardrails MUST align with organizational values.

== Begründung

[cols="1,3"]
|===
|Risiko |Beschreibung

|*Risk* |Misaligned agents can optimize for the wrong objectives and cause business or safety harm.

|*Risk* |Missing verification loops let erroneous agent outputs reach production systems.

|===

== Anforderungen

* Fail-safe, alignment, and verification mechanisms MUST be in place.
* Content filters MUST be configured to block inappropriate content.
* Action boundaries MUST prevent agents from performing unauthorized actions.
* Human-in-the-loop MUST be configured for sensitive decisions.
* Guardrails MUST align with organizational values.

== Implementierungsleitfaden

1. Document the requirement in a version-controlled policy or standard.
2. Assign ownership and establish a review cadence (e.g., quarterly).
3. Implement the required configuration as code in Terraform or equivalent IaC.

== Reifegrade

[cols="1,2,4"]
|===
|Level |Name |Kriterien

|L1 |Ad hoc – control not consistently applied |* Manual evidence exists for some workloads, but coverage is unknown.

|L2 |Standardised – policy defined and communicated |* A version-controlled policy, ADR, or standard describes the requirement.

|L3 |Integrated – automated validation in CI/CD |* Terraform checks run automatically on pull requests and report results.

|L4 |Auditable – metrics and exceptions tracked |* Control coverage, failures, and approved exceptions are reported quarterly.

== Checks

=== waf-agn-050.tf.aws.content-filters-enabled

*Engine:* `terraform` | *Provider:* aws | *Automated:* Ja

*AWS Bedrock agents must have content filters configured*

AWS Bedrock agents must have content filtering enabled via guardrails. Filters must block harmful, offensive, or inappropriate content according to organizational policy.

*Scope:* `resource` — `aws_bedrock_guardrail`, `aws_bedrockagent`

*Assertions:*
* `name` not empty — Content filters (guardrails) must be configured.

*Remediation:* Create and configure AWS Bedrock guardrails with content filtering. Define content policies for hate speech, violence, sexual content, and harmful activity. Apply guardrails to all agents.

.Compliant

[source,terraform]
----
resource "aws_bedrock_guardrail" "organizational_guardrail" {
  name = "organizational-guardrail"

  blocked_input_messages = [{
    text = "hate-speech"
  }]

  blocked_output_messages = [{
    text = "hate-speech"
  }]

  # Content filters configured
}

resource "aws_bedrockagent" "filtered_agent" {
  agent_name = "content-filtered-agent"

  guardrail_configuration {
    guardrail_arn = aws_bedrock_guardrail.organizational_guardrail.arn
    guardrail_version = "DRAFT"
  }
}
----

.Non-Compliant

[source,terraform]
----
resource "aws_bedrockagent" "unfiltered" {
  agent_name = "no-content-filter"
  # No guardrail configured
  # WAF-AGN-050 Violation
}
----

=== waf-agn-050.tf.aws.action-boundaries-configured

*Engine:* `terraform` | *Provider:* aws | *Automated:* Ja

*Agent action boundaries must be configured*

Agents must have action boundaries defined via IAM roles and tool schemas. Agents must not be able to perform actions outside their scope. Maximum token limits and output lengths must be configured.

*Scope:* `resource` — `aws_iam_role`, `aws_bedrockagent`

*Assertions:*
* `name` not empty — Action boundaries (IAM policies) must be configured.

*Remediation:* Configure IAM roles with least-privilege permissions for agent actions. Define strict tool schemas limiting what tools agents can use. Set output token limits and input length constraints in agent configuration.

.Compliant

[source,terraform]
----
resource "aws_iam_role" "agent_role" {
  name = "agent-role"

  assume_role_policy = jsonencode({
    Version = "2012-10-17"
    Statement = [{
      Effect = "Allow"
      Principal = {
        Service = "bedrock.amazonaws.com"
      }
      Action = "sts:AssumeRole"
    }]
  })
}

resource "aws_iam_role_policy" "agent_limits" {
  name = "agent-limits"
  role = aws_iam_role.agent_role.id

  policy = jsonencode({
    Version = "2012-10-17"
    Statement = [{
      Effect = "Allow"
      Action = [
        "s3:GetObject",
        "s3:ListBucket"
      ]
      Resource = [
        "arn:aws:s3:::allowed-bucket/*"
      ]
    }]
  })
}
----

.Non-Compliant

[source,terraform]
----
resource "aws_iam_role" "unlimited_role" {
  name = "unlimited-agent-role"
  # No policy restrictions
  # WAF-AGN-050 Violation
}
----

=== waf-agn-050.tf.aws.human-in-the-loop-configured

*Engine:* `terraform` | *Provider:* aws | *Automated:* Ja

*Human-in-the-loop must be configured for sensitive decisions*

For high-risk agent decisions (financial, legal, personal data), human approval MUST be required. The human-in-the-loop workflow must be configured via AWS Bedrock or external approval system.

*Scope:* `resource` — `aws_bedrockagent`

*Assertions:*
* `agent_name` not empty — Human-in-the-loop must be configured for sensitive decisions.

*Remediation:* Configure human-in-the-loop approval workflows for sensitive agent actions. Use AWS Bedrock’s approval feature or integrate with an external approval system (ServiceNow, Jira, custom). Define decision types requiring human review.

.Compliant

[source,terraform]
----
resource "aws_bedrockagent" "hitable_agent" {
  agent_name = "human-in-loop-agent"

  human_interaction_configuration {
    human_interpretation_prompt = "Review agent decision for accuracy"
    human_interpretation_timeout = 3600
    human_interpretation_output_context_name = "approval"
  }
}
----

.Non-Compliant

[source,terraform]
----
resource "aws_bedrockagent" "no_huawei" {
  agent_name = "fully-automated-agent"
  # No human-in-the-loop for sensitive decisions
  # WAF-AGN-050 Violation
}
----

=== waf-agn-050.tf.azurerm.content-safety-policy

*Engine:* `terraform` | *Provider:* azurerm | *Automated:* Ja

*Azure AI Content Safety must have fail-safe filters configured*

Azure AI Content Safety accounts must have content filters configured to block hate, violence, sexual, and self-harm content for agent outputs.

*Scope:* `resource` — `azurerm_cognitive_account`

*Assertions:*
* `kind` equals `ContentSafety` — A Content Safety cognitive account must exist for fail-safe filtering.
* `sku_name` not empty — Content Safety account must have a configured SKU.

*Remediation:* Deploy azurerm_cognitive_account with kind "ContentSafety" and configure content filter policies. Apply filters to agent deployments.

.Compliant

[source,terraform]
----
resource "azurerm_cognitive_account" "content_safety" {
  name                = "content-safety-account"
  location            = azurerm_resource_group.main.location
  resource_group_name = azurerm_resource_group.main.name
  kind                = "ContentSafety"
  sku_name            = "S0"
}

# Content filter policy applied at application level or via azurerm_cognitive_account_content_filter
----

.Non-Compliant

[source,terraform]
----
resource "azurerm_cognitive_account" "content_safety" {
  name                = "content-safety-account"
  location            = azurerm_resource_group.main.location
  resource_group_name = azurerm_resource_group.main.name
  kind                = "ContentSafety"
  sku_name            = "S0"
  # No content filter policy applied
  # WAF-AGN-050 Violation
}
----

=== waf-agn-050.tf.google.vertex-safety-filters

*Engine:* `terraform` | *Provider:* google | *Automated:* Ja

*GCP Vertex AI agents must have safety filters configured*

GCP Vertex AI agents must have safety filter settings configured to block harmful content categories and prevent unauthorized actions.

*Scope:* `resource` — `google_vertex_ai_agent`

*Assertions:*
* `safety_settings` attribute exists — Vertex AI agent must have safety_settings configured.

*Remediation:* Configure google_vertex_ai_agent with safety_settings block defining thresholds for HATE_SPEECH, HARASSMENT, SEXUALLY_EXPLICIT, and DANGEROUS_CONTENT.

.Compliant

[source,terraform]
----
resource "google_vertex_ai_agent" "safe_agent" {
  display_name = "safe-agent"

  safety_settings {
    category  = "HATE_SPEECH"
    threshold = "BLOCK_LOW_AND_ABOVE"
  }

  safety_settings {
    category  = "DANGEROUS_CONTENT"
    threshold = "BLOCK_MEDIUM_AND_ABOVE"
  }
}
----

.Non-Compliant

[source,terraform]
----
resource "google_vertex_ai_agent" "unsafe_agent" {
  display_name = "unsafe-agent"
  # No safety_settings configured
  # WAF-AGN-050 Violation
}
----
