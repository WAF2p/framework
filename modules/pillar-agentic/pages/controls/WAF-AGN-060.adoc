= WAF-AGN-060 – Multi-Agent Orchestration
:page-toc: right
:control-id: WAF-AGN-060
:pillar: agentic
:severity: medium
:category: orchestration
:automated: medium
:description: WAF++ Agentic – Viele Agenten müssen koordiniert werden. Orchestrierung muss effektiv sein.

[.metadata]
*Pillar:* Agentic | *Severity:* Medium | *Category:* Orchestration | *Automatisierbar:* Medium

== Beschreibung

Viele Agenten müssen koordiniert werden. Agent-Orchestrierung muss Coordinator/Manager-Pattern oder Mesh-Architekturen verwenden. Event-basierte Kommunikation muss für Agenten-Messaging konfiguriert sein. Failure Recovery und Agent-Health-Monitoring müssen in place sein.

== Begründung

Unkoordinierte Multi-Agent-Systeme erzeugen mehrere Probleme:

*Redundante Arbeit:* Mehrere Agenten arbeiten an derselben Aufgabe ohne Koordination und verschwenden Ressourcen.

*Konfliktakte:* Agenten können widersprüchliche Aktionen ohne Koordination ausführen.

*Performance-Probleme:* Fehlendes Lastbalancing führt dazu, dass einige Agenten überlastet sind, während andere untätig sind.

*Versagens-Propagierung:* Wenn ein Agent ausfällt, können abhängige Agenten ohne Recovery ebenfalls ausfallen.

*Keine Sichtbarkeit:* Es ist schwer, die Gesamtsystemgesundheit ohne Orchestrierung zu überwachen.

== Anforderungen

* Coordinator/Manager-Pattern muss für Agent-Orchestrierung verwendet werden
* Event-basierte Kommunikation (SNS, SQS, EventBridge) muss konfiguriert sein
* Failure Recovery-Mechanismen müssen in place sein
* Agent-Health-Monitoring muss konfiguriert sein
* Dead Letter Queues müssen für gescheiterte Nachrichten konfiguriert sein

== Implementierungshinweise

. *Coordinator-Pattern entwerfen:* Ein Manager-Agent delegiert Aufgaben an spezialisierte Worker
. *Event-Kanäle verwenden:* SNS-Themen, SQS-Warteschlangen und EventBridge-Regeln konfigurieren
. *Retry-Logik implementieren:* Nachrichten-Retries mit exponentiellem Backoff konfigurieren
. *Dead Letter Queues einrichten:* DLQ für Nachrichten konfigurieren, die wiederholt fehlschlagen
. *Agent-Health überwachen:* Alarms für Agenten-Ausfälle und Latenz-Spikes konfigurieren

== Reifegradstufen

[cols="1,2,3"]
|===
|Level |Name |Kriterien

|*1*
|Keine Orchestrierung
|Agenten operieren unabhängig ohne Koordination. Kein Failover.

|*2*
|Manuelle Koordination
|Einige manuelle Orchestrierung über externe Systeme.

|*3*
|Event-basierte Koordination
|Agenten kommunizieren über Events. Basic Failover konfiguriert.

|*4*
|Automatisierte Orchestrierung
|Dynamische Task-Zuweisung. Automatisches Failover und Skalierung.

|*5*
|Selbstheilendes System
|Orchestrierer lernt aus Versagen und verbessert sich automatisch.

|===

== Terraform Checks

=== waf-agn-060.tf.aws.coordinator-agent-configured
*Prüft:* Multi-Agent-Systeme haben Coordinator/Manager konfiguriert.

[cols="1,1"]
|===
|Compliant |Nicht compliant

a|[source,hcl]
----
resource "aws_bedrockagent" "coordinator" {
  agent_name = "agent-coordinator"
  # Verwaltet mehrere Worker-Agenten
}

resource "aws_bedrockagent" "worker_analysis" {
  agent_name = "analysis-worker"
  # Arbeitet unter Coordinator-Anleitung
}

resource "aws_bedrockagent" "worker_research" {
  agent_name = "research-worker"
  # Arbeitet unter Coordinator-Anleitung
}

resource "aws_lambda_function" "agent_coordinator" {
  function_name = "agent-coordinator-function"
  # Koordiniert Agenten-Kommunikation
}
----
|Kein Coordinator definiert
|===

=== waf-agn-060.tf.aws.event-based-communication
*Prüft:* Agenten-Kommunikation verwendet event-basiertes Messaging (SNS, SQS, EventBridge).

[cols="1,1"]
|===
|Compliant |Nicht compliant

a|[source,hcl]
----
resource "aws_sns_topic" "agent_events" {
  name = "agent-events"
}

resource "aws_sqs_queue" "agent_queue" {
  name = "agent-messages"
}

resource "aws_sns_topic_subscription" "agent_subscription" {
  topic_arn = aws_sns_topic.agent_events.arn
  protocol  = "sqs"
  endpoint  = aws_sqs_queue.agent_queue.arn
}

resource "aws_bedrockagent" "event_agent" {
  agent_name = "event-based-agent"
}
----
|Keine Event-Kommunikation
|===
