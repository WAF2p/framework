= WAF-AGN-070 – Agent Observability
:page-toc: right
:control-id: WAF-AGN-070
:pillar: agentic
:severity: medium
:category: logging-monitoring
:automatable: High
:description: Agent activities must be visible and measurable. Telemetry MUST be collected for all agents including tokens, latency, GPU utilization, and decision metrics. Metrics MUST be ingested into a monitoring system. Distributed tracing MUST link agent operations end-to-end.

[.metadata]
*Säule:* Agentic | *Schweregrad:* Mittel | *Kategorie:* Logging Monitoring | *Automatisierbar:* High

== Beschreibung

Agent activities must be visible and measurable. Telemetry MUST be collected for all agents including tokens, latency, GPU utilization, and decision metrics. Metrics MUST be ingested into a monitoring system. Distributed tracing MUST link agent operations end-to-end.

== Begründung

[cols="1,3"]
|===
|Risiko |Beschreibung

|*Risk* |Invisible agent activity delays detection of misuse, drift, or attacks.

|*Risk* |Without metrics, agent behavior cannot be governed or continuously improved.

|===

== Anforderungen

* Agent activities must be visible and measurable.
* Telemetry MUST be collected for all agents including tokens, latency, GPU utilization, and decision metrics.
* Metrics MUST be ingested into a monitoring system.
* Distributed tracing MUST link agent operations end-to-end.

== Implementierungsleitfaden

1. Document the requirement in a version-controlled policy or standard.
2. Assign ownership and establish a review cadence (e.g., quarterly).
3. Implement the required configuration as code in Terraform or equivalent IaC.

== Checks

=== waf-agn-070.tf.aws.metrics-configured

*Engine:* `terraform` | *Provider:* aws | *Automated:* Ja

*Agent metrics must be configured (tokens, latency, GPU)*

Agent telemetry must include token counts, inference latency, GPU utilization, and error rates. Metrics must be exported to CloudWatch or a third-party monitoring system.

*Scope:* `resource` — `aws_cloudwatch_metric_alarm`, `aws_bedrockagent`

*Assertions:*
* `alarm_name` not empty — Metrics alarms must be configured for agent monitoring.

*Remediation:* Configure Bedrock metrics export to CloudWatch. Use CloudWatch Insights to query agent metrics. Set up dashboards for token usage, latency, and error rates. Configure alarms for anomalies.

.Compliant

[source,terraform]
----
resource "aws_cloudwatch_metric_alarm" "agent_latency" {
  alarm_name          = "agent-latency-alarm"
  comparison_operator = "GreaterThanThreshold"
  evaluation_periods  = 2
  metric_name         = "Latency"
  namespace           = "AWS/Bedrock"
  period              = 60
  statistic           = "Average"
  threshold           = 5000
  unit                = "Milliseconds"
  alarm_description   = "Agent latency exceeds 5 seconds"
}

resource "aws_cloudwatch_metric_alarm" "agent_tokens" {
  alarm_name          = "agent-token-alarm"
  comparison_operator = "GreaterThanThreshold"
  evaluation_periods  = 1
  metric_name         = "TokenCount"
  namespace           = "AWS/Bedrock"
  period              = 300
  statistic           = "Sum"
  threshold           = 100000
  unit                = "Count"
  alarm_description   = "Agent token usage exceeds limit"
}
----

.Non-Compliant

[source,terraform]
----
# No metrics configured
# WAF-AGN-070 Violation
# No visibility into agent performance
----

=== waf-agn-070.tf.aws.distributed-tracing-enabled

*Engine:* `terraform` | *Provider:* aws | *Automated:* Ja

*Distributed tracing must be enabled for agent operations*

Agent operations must be traced using AWS X-Ray. Traces must include agent ID, operation type, latency, input/output size, and decision path. X-Ray must link to CloudWatch Logs for full context.

*Scope:* `resource` — `aws_lambda_function`, `aws_bedrockagent`

*Assertions:*
* `environment.variables.AWS_XRAY_TRACING_NAME` not empty — Distributed tracing (X-Ray) must be enabled.

*Remediation:* Enable X-Ray tracing for Bedrock invocations. Use AWS SDK with X-Ray integration. Instrument agent code with X-Ray SDK for custom segments. Configure trace sampling.

.Compliant

[source,terraform]
----
resource "aws_lambda_function" "agent_traced" {
  function_name = "agent-traced"
  environment {
    variables = {
      AWS_XRAY_TRACING_NAME = "agent-service"
      AWS_XRAY_DAEMON_ADDRESS = "127.0.0.1:2000"
    }
  }
}

resource "aws_cloudwatch_log_group" "agent_trace_logs" {
  name = "/aws/lambda/agent-traced"
}
----

.Non-Compliant

[source,terraform]
----
resource "aws_lambda_function" "agent_untraced" {
  function_name = "agent-untraced"
  # No X-Ray tracing
  # WAF-AGN-070 Violation
}
----

=== waf-agn-070.tf.aws.log-integration-configured

*Engine:* `terraform` | *Provider:* aws | *Automated:* Ja

*Agent logs must be integrated with monitoring system*

Agent logs must be integrated with a centralized monitoring system. Logs must include agent ID, session ID, timestamp, operation type, input/output size, and result status.

*Scope:* `resource` — `aws_cloudwatch_log_group`, `aws_cloudwatch_log_metric_filter`

*Assertions:*
* `name` not empty — Log integration with monitoring must be configured.

*Remediation:* Configure CloudWatch Logs Insights queries for agent log analysis. Set up dashboards showing agent health, error rates, and performance trends. Configure alarms for error patterns.

.Compliant

[source,terraform]
----
resource "aws_cloudwatch_log_group" "agent_logs" {
  name = "/aws/bedrock/agent-logs"

  retention_in_days = 90
}

resource "aws_cloudwatch_log_metric_filter" "agent_errors" {
  name = "agent-error-metric"

  pattern = "{ $.level = \"error\" || $.error != null }"

  log_group_name = aws_cloudwatch_log_group.agent_logs.name

  metric_transformations {
    metric_name      = "AgentErrors"
    metric_namespace = "AgentMonitoring"
    metric_value     = "1"
  }
}
----

.Non-Compliant

[source,terraform]
----
resource "aws_cloudwatch_log_group" "agent_logs" {
  name = "/aws/bedrock/agent-logs"
  # No metric filter configured
  # WAF-AGN-070 Violation
}
----

=== waf-agn-070.tf.azurerm.app-insights-agent

*Engine:* `terraform` | *Provider:* azurerm | *Automated:* Ja

*Azure Application Insights must monitor agent operations*

Azure AI agent components must be monitored via Application Insights to collect latency, token usage, error rates, and distributed traces.

*Scope:* `resource` — `azurerm_application_insights`, `azurerm_linux_function_app`

*Assertions:*
* `workspace_id` not empty — Application Insights must be linked to a Log Analytics workspace.
* `app_settings.APPINSIGHTS_INSTRUMENTATIONKEY` attribute exists — Agent host must reference Application Insights instrumentation key.

*Remediation:* Deploy azurerm_application_insights and connect it to agent hosting services (App Service, Container Apps, Functions).

.Compliant

[source,terraform]
----
resource "azurerm_application_insights" "agent_ai" {
  name                = "agent-insights"
  location            = azurerm_resource_group.main.location
  resource_group_name = azurerm_resource_group.main.name
  workspace_id        = azurerm_log_analytics_workspace.ai_logs.id
  application_type    = "web"
}

resource "azurerm_linux_function_app" "agent_host" {
  name                = "agent-function"
  location            = azurerm_resource_group.main.location
  resource_group_name = azurerm_resource_group.main.name
  service_plan_id     = azurerm_service_plan.agent_plan.id

  app_settings = {
    "APPINSIGHTS_INSTRUMENTATIONKEY" = azurerm_application_insights.agent_ai.instrumentation_key
  }
}
----

.Non-Compliant

[source,terraform]
----
resource "azurerm_linux_function_app" "agent_host" {
  name = "agent-function"
  # No Application Insights integration
  # WAF-AGN-070 Violation
}
----

=== waf-agn-070.tf.google.monitoring-agent

*Engine:* `terraform` | *Provider:* google | *Automated:* Ja

*GCP Cloud Monitoring must collect agent telemetry*

GCP Vertex AI / Cloud Run agent services must have monitoring dashboards and alerting policies for latency, errors, and token usage.

*Scope:* `resource` — `google_monitoring_alert_policy`

*Assertions:*
* `conditions` attribute exists — Cloud Monitoring alert policy must define conditions for agent metrics.
* `notification_channels` attribute exists — Alert policy must route to notification channels.

*Remediation:* Configure google_monitoring_alert_policy resources for agent services and google_monitoring_dashboard for agent metrics.

.Compliant

[source,terraform]
----
resource "google_monitoring_alert_policy" "agent_latency" {
  display_name = "Agent high latency"
  combiner     = "OR"

  conditions {
    display_name = "Latency > 5s"
    condition_threshold {
      filter          = "resource.type="cloud_run_revision" AND metric.type="run.googleapis.com/request_latencies""
      duration        = "60s"
      comparison      = "COMPARISON_GT"
      threshold_value = 5000
    }
  }

  notification_channels = [google_monitoring_notification_channel.team.id]
}
----

.Non-Compliant

[source,terraform]
----
resource "google_cloud_run_service" "agent" {
  name     = "agent-service"
  location = "europe-west3"
  # No Cloud Monitoring alert policies configured
  # WAF-AGN-070 Violation
}
----
