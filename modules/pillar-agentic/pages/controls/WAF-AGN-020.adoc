[.metadata]
*Pillar:* Agentic | *Severity:* High | *Category:* Agentic Governance | *Automatable:* High

== Description

Not every agent should be able to use every tool. Tool use must be approved, logged, and limited. Agents MUST have explicit tool definitions with approved lists. All tool calls MUST be logged with context, input, output, and timestamp. Rate limits and sandboxing MUST be applied to prevent abuse.

== Rationale

[cols="1,3"]
|===
|Risk |Description

|*Risk* |Overly broad tool permissions allow agents to perform destructive or unauthorized operations.

|*Risk* |Missing permission boundaries at the tool level enable privilege escalation in automated workflows.

|===

== Requirements

* Not every agent should be able to use every tool.
* Tool use must be approved, logged, and limited.
* Agents MUST have explicit tool definitions with approved lists.
* All tool calls MUST be logged with context, input, output, and timestamp.
* Rate limits and sandboxing MUST be applied to prevent abuse.

== Implementation Guidance

1. Document the requirement in a version-controlled policy or standard.
2. Assign ownership and establish a review cadence (e.g., quarterly).
3. Implement the required configuration as code in Terraform or equivalent IaC.

== Checks

=== waf-agn-020.tf.aws.bedrock-agent-tools-approved

*Engine:* `terraform` | *Provider:* aws | *Automated:* Yes

*AWS Bedrock agents must have approved tool definitions*

AWS Bedrock agents must have explicit tool definitions in their tool schema. Wildcard or unrestricted tools are prohibited. All tools must be from an approved list.

*Scope:* `resource` — `aws_bedrockagent`

*Assertions:*
* `tool_schema.tools` attribute exists — Agent must have explicit tool definitions.
* `tool_schema.tools` json not contains pattern pattern `"name":\\s*"\*"` — Tools must not use wildcard names like "*". Define specific tools only.

*Remediation:* Define explicit tools in the aws_bedrockagent resource tool_schema. Use the 'tools' block to specify each allowed tool with name, description, and input schema. Do not use wildcard definitions.

.Compliant

[source,terraform]
----
resource "aws_bedrockagent" "support_agent" {
  agent_name = "customer-support"

  tool_schema {
    tools = [{
      name = "lookup_customer"
      description = "Look up customer by email"
      input_schema = jsonencode({
        type = "object"
        properties = {
          email = { type = "string" }
        }
        required = ["email"]
      })
    }, {
      name = "check_order_status"
      description = "Check order status"
      input_schema = jsonencode({
        type = "object"
        properties = {
          order_id = { type = "string" }
        }
        required = ["order_id"]
      })
    }]
  }
}
----

.Non-Compliant

[source,terraform]
----
resource "aws_bedrockagent" "bad_agent" {
  agent_name = "unrestricted-agent"

  tool_schema {
    tools = [{
      name = "*"
      description = "Allow all tools"
      # WAF-AGN-020 Violation: wildcard tool definition
    }]
  }
}
----

=== waf-agn-020.tf.azurerm.ai-tool-filter

*Engine:* `terraform` | *Provider:* azurerm | *Automated:* Yes

*Azure AI services must have content filters and tool restrictions configured*

Azure AI services deployments must have content filters and tool usage restrictions configured. Only approved tool functions should be exposed to agents.

*Scope:* `resource` — `azurerm_cognitive_account`, `azurerm_cognitive_deployment`

*Assertions:*
* `network_acls` attribute exists — Azure AI services account must have network ACLs restricting access.
* `sku_name` not empty — Azure AI deployment must have a configured SKU.

*Remediation:* Configure azurerm_cognitive_account with network ACLs and content filters. Use azurerm_cognitive_deployment with strict model settings. Document approved tools in ADR.

.Compliant

[source,terraform]
----
resource "azurerm_cognitive_account" "ai" {
  name                = "ai-services-account"
  location            = azurerm_resource_group.main.location
  resource_group_name = azurerm_resource_group.main.name
  kind                = "OpenAI"
  sku_name            = "S0"

  network_acls {
    default_action = "Deny"
    ip_rules       = ["10.0.0.0/24"]
  }
}

resource "azurerm_cognitive_deployment" "agent" {
  name                 = "agent-deployment"
  cognitive_account_id = azurerm_cognitive_account.ai.id
  model {
    format  = "OpenAI"
    name    = "gpt-4o"
    version = "2024-08-06"
  }
  sku {
    name = "Standard"
    capacity = 1
  }
}
----

.Non-Compliant

[source,terraform]
----
resource "azurerm_cognitive_account" "ai" {
  name                = "ai-services-account"
  location            = azurerm_resource_group.main.location
  resource_group_name = azurerm_resource_group.main.name
  kind                = "OpenAI"
  sku_name            = "S0"
  # No network ACLs or content filters configured
  # WAF-AGN-020 Violation
}
----

=== waf-agn-020.tf.google.vertex-agent-tools-approved

*Engine:* `terraform` | *Provider:* google | *Automated:* Yes

*Google Vertex AI agents must have approved tool definitions*

Google Vertex AI agents must have explicit tool function declarations. All tools must reference pre-approved functions with defined schemas.

*Scope:* `resource` — `google_vertex_ai_agent`

*Assertions:*
* `function_declarations` not empty — Agent must have explicit function declarations.

*Remediation:* Define function_declarations in the vertex_ai_agent configuration with specific function names, descriptions, and parameter schemas. Do not use generic or wildcard function definitions.

.Compliant

[source,terraform]
----
resource "google_vertex_ai_agent" "data_analyst" {
  display_name = "data-analyst-agent"

  function_declarations = [{
    name = "query_database"
    description = "Query the analytics database"
    parameters = {
      type = "OBJECT"
      properties = {
        query = {
          type = "STRING"
          description = "SQL query to execute"
        }
      }
      required = ["query"]
    }
  }]
}
----

.Non-Compliant

[source,terraform]
----
resource "google_vertex_ai_agent" "unrestricted" {
  display_name = "unrestricted-agent"

  function_declarations = [{
    name = "any_function"
    description = "Any function allowed"
    # WAF-AGN-020 Violation: too permissive
  }]
}
----

=== waf-agn-020.tf.aws.tool-call-logging-enabled

*Engine:* `terraform` | *Provider:* aws | *Automated:* Yes

*AWS Bedrock tool calls must be logged*

All tool calls made by AWS Bedrock agents MUST be logged to CloudWatch Logs with timestamp, agent ID, tool name, input, output, and duration.

*Scope:* `resource` — `aws_bedrockagent`, `aws_cloudwatch_log_group`

*Assertions:*
* `name` not empty — Tool call logging must be configured with a log group.

*Remediation:* Configure CloudWatch logging for Bedrock agents. Enable 'Inference logs' in the Bedrock console or via API. Create a log group at /aws/bedrock/inference-logs.

.Compliant

[source,terraform]
----
resource "aws_cloudwatch_log_group" "bedrock_logs" {
  name = "/aws/bedrock/inference-logs"
}

resource "aws_bedrockagent" "agent" {
  agent_name = "loggable-agent"
  # Tool call logging enabled via CloudWatch
}
----

.Non-Compliant

[source,terraform]
----
resource "aws_bedrockagent" "no_logging" {
  agent_name = "no-logging-agent"
  # No CloudWatch log group configured
  # WAF-AGN-020 Violation: no tool call logging
}
----

=== waf-agn-020.tf.aws.tool-rate-limits-configured

*Engine:* `terraform` | *Provider:* aws | *Automated:* Yes

*Tool call rate limits must be configured for agents*

Agents MUST have rate limiting configured to prevent abuse. Maximum tokens per minute and requests per minute should be defined.

*Scope:* `resource` — `aws_bedrockagent`

*Assertions:*
* `agent_name` not empty — Agent must have rate limiting configuration.

*Remediation:* Configure rate limits in the Bedrock agent configuration. Use AWS SDK or Console to set maxTokensPerMinute and maxRequestsPerMinute for each agent.

.Compliant

[source,terraform]
----
resource "aws_bedrockagent" "rate_limited_agent" {
  agent_name = "rate-limited"

  agent_resource_role_arn = aws_iam_role.bedrock.arn

  instruction = "You are a helpful assistant."

  # Rate limiting via IAM policy or external service
  # Tools should be rate-limited via API Gateway or similar
}
----

.Non-Compliant

[source,terraform]
----
resource "aws_bedrockagent" "unlimited" {
  agent_name = "unlimited-agent"
  # No rate limiting configured
  # WAF-AGN-020 Violation
}
----
