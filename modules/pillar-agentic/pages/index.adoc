= Agentic (Säule: Agentic)
:page-navtitle: Agentic
:page-toc: right
:description: WAF++ Säule Agentic – Design und Governance von autonomen KI-Agenten als integraler Bestandteil der Cloud-Architektur.

*Agentic* bezeichnet den Einsatz autonomer oder semi-autonomer KI-Agenten, die Aufgaben planen, Werkzeuge nutzen und Entscheidungen treffen können – oft über längere Zeiträume und multi-step Prozesse hinweg.

== Was bedeutet Agentic im WAF++?

Die Agentic-Säule des WAF++ adressiert die architektonischen und operativen Anforderungen an:

* *Autonome Agenten*: Einzelne KI-Agenten mit eigener Planungs- und Entscheidungskompetenz
* *Multi-Agenten-Systeme*: Kooperierende oder konkurrierende Agenten mit gemeinsamen Zielen
* *Agent Orchestration*: Koordination über Agenten hinweg (Manager/Worker, Swarm, Mesh)
* *Human-in-the-Loop*: Schnittstellen zwischen menschlichen Entscheidern und Agenten
* *Agent Safety*: Guardrails, Verification, Alignment und Fail-Safe-Mechanismen

== Agentic-Prinzipien

Die Agentic-Säule wird von fünf Grundprinzipien geleitet:

[cols="1,3"]
|===
|1. Agent-Identity First |Jeder Agent muss identifizierbar, authentifizierbar und nachvollziehbar sein.

|2. Tool Use Governance |Nicht jeder Agent darf jedes Werkzeug nutzen. Werkzeugnutzung muss genehmigt, protokolliert und begrenzt sein.

|3. Reasoning Transparency |Entscheidungen müssen nachvollziehbar sein – nicht als Black Box.

|4. Human-in-the-Loop by Design |Sensible Entscheidungen erfordern menschliche Oversight.

|5. Agent Debt Tracking |Limitationen, Wissenslücken und technische Schulden müssen sichtbar sein.

|===

== Architektur-Patterns

Drei primäre Pattern für agentic Systeme:

[cols="1,2,3"]
|===
|Pattern |Beschreibung |Wann verwenden

|*Single Agent*
|Ein autonomer Agent mit klarem Verantwortungsbereich
|Einfache Aufgaben, frühe Experimente

|*Swarm*
|Viele homogene Agenten mit gemeinsamem Ziel
|Paralleler Processing, skalierbare Workloads

|*Mesh*
|Heterogene Agenten mit spezialisierten Fähigkeiten
|Komplexe Workflows mit mehreren Expertisen

|===

== Verwandte Säulen

Die Agentic-Säule interagiert mit allen anderen WAF++-Säulen:

[cols="1,3"]
|===
|Säule |Interaktion mit Agentic

|*Operational Excellence*
|Observability (OpsEx) ermöglicht Agenten-Monitoring. Runbooks (OpsEx) leiten Agentenverhalten.

|*Reliability*
|SLOs (Reliability) überwachen Agenten-Performance. Agenten-Ausfälle trigger SLO-Burn-Rate-Alarms.

|*Security*
|Guardrails (Agentic) erzwingen Security-Richtlinien. Security-Controls werden via Agenten-Tool-Use angewendet.

|*Cost*
|Agenten-Operationen (Agentic) beeinflussen Cloud-Kosten. Cost-Controls (Cost) gelten für Agenten-Compute.

|*Architecture*
|Agenten-Architekturen (Agentic) beeinflussen System-Design. Architektur-Entscheidungen wirken sich auf Agenten-Fähigkeiten aus.

|*Governance*
|Agent Debt Register (Agentic) informiert Governance-Priorisierung. Controls werden mit Compliance-Frameworks abgebildet.

|*Sustainability*
|Agenten-Effizienz (Agentic) beeinflusst den CO2-Fußabdruck. Modellauswahl wirkt sich auf Umweltauswirkungen aus.

|*Efficiency*
|Agenten-Caching und -Optimierung (Agentic) verbessern Efficiency. Efficiency-Controls gelten für Agenten-Operationen.

|===
