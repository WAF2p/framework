== Beschreibung

All production services MUST expose health check endpoints and configure readiness and liveness probes. Load balancers and orchestrators MUST use health checks to route traffic only to healthy instances. Kubernetes workloads MUST define readinessProbe and livenessProbe. AWS load balancers MUST have health check paths configured. Health check intervals, thresholds, and timeout values MUST be explicitly defined – no reliance on cloud provider defaults.

== Begründung

[cols="1,3"]
|===
|Risiko |Beschreibung

|*Risk* |Services without health checks are not recognized as failed by load balancers and keep receiving traffic.

|*Risk* |Missing state-check endpoints delay detection of partial outages.

|===

== Anforderungen

* All production services MUST expose health check endpoints and configure readiness and liveness probes.
* Load balancers and orchestrators MUST use health checks to route traffic only to healthy instances.
* Kubernetes workloads MUST define readinessProbe and livenessProbe.
* AWS load balancers MUST have health check paths configured.
* Health check intervals, thresholds, and timeout values MUST be explicitly defined – no reliance on cloud provider defaults.

== Implementierungsleitfaden

1. Implement the required configuration as code in Terraform or equivalent IaC.
2. Add an automated check to CI/CD so deviations are caught before deployment.

== Checks

=== waf-rel-020.tf.aws.alb-target-group-health-check

*Engine:* `terraform` | *Provider:* aws | *Automated:* Ja

*AWS ALB target group must have explicit health check configuration*

AWS Application Load Balancer target groups must define an explicit health_check block with a non-default path, interval, timeout, and healthy/unhealthy thresholds.

*Scope:* `resource` — `aws_lb_target_group`

*Assertions:*
* `health_check` attribute exists — Target group must define a health_check block.
* `health_check.path` not empty — Health check path must be explicitly defined (not default '/').
* `health_check.interval` attribute exists — Health check interval must be explicitly defined.
* `health_check.healthy_threshold` attribute exists — Healthy threshold must be explicitly defined.

*Remediation:* Add a health_check block to the aws_lb_target_group resource. Define path, interval, timeout, healthy_threshold, and unhealthy_threshold explicitly.

.Compliant

[source,terraform]
----
resource "aws_lb_target_group" "api" {
  name     = "payment-api-tg"
  port     = 8080
  protocol = "HTTP"
  vpc_id   = var.vpc_id

  health_check {
    enabled             = true
    path                = "/health/ready"
    interval            = 15
    timeout             = 5
    healthy_threshold   = 2
    unhealthy_threshold = 3
    matcher             = "200"
  }
}
----

.Non-Compliant

[source,terraform]
----
resource "aws_lb_target_group" "api" {
  name     = "payment-api-tg"
  port     = 8080
  protocol = "HTTP"
  vpc_id   = var.vpc_id
  # Missing: health_check block – uses cloud defaults
  # WAF-REL-020 violation
}
----

=== waf-rel-020.tf.azurerm.lb-probe

*Engine:* `terraform` | *Provider:* azurerm | *Automated:* Ja

*Azure Load Balancer must have a health probe configured*

Azure Load Balancer or Application Gateway backends must have explicit health probes defined with non-default paths and intervals.

*Scope:* `resource` — `azurerm_lb_probe`, `azurerm_application_gateway`

*Assertions:*
* `name` not empty — Health probe must have a name.
* `protocol` not empty — Health probe protocol must be specified.
* `request_path` not empty — Health probe request path must be explicitly configured.

*Remediation:* Define an azurerm_lb_probe resource with protocol, port, request_path, interval_in_seconds, and number_of_probes configured.

.Compliant

[source,terraform]
----
resource "azurerm_lb_probe" "api_health" {
  loadbalancer_id     = azurerm_lb.main.id
  name                = "api-health-probe"
  protocol            = "Http"
  port                = 8080
  request_path        = "/health/ready"
  interval_in_seconds = 15
  number_of_probes    = 2
}
----

.Non-Compliant

[source,terraform]
----
resource "azurerm_lb_probe" "probe" {
  loadbalancer_id = azurerm_lb.main.id
  name            = "probe"
  protocol        = "Tcp"
  port            = 80
  # Missing: request_path – TCP probe does not validate application health
}
----

=== waf-rel-020.tf.google.compute-health-check

*Engine:* `terraform` | *Provider:* google | *Automated:* Ja

*GCP Compute health check must be configured for managed instance groups*

GCP managed instance groups and load balancers must use explicit health checks with HTTP paths and defined thresholds.

*Scope:* `resource` — `google_compute_health_check`, `google_compute_backend_service`

*Assertions:*
* `name` not empty — Health check must have a name.
* `http_health_check` attribute exists — HTTP health check configuration must be defined.
* `check_interval_sec` attribute exists — Health check interval must be explicitly defined.

*Remediation:* Define a google_compute_health_check with http_health_check specifying the request_path, check_interval_sec, timeout_sec, and thresholds.

.Compliant

[source,terraform]
----
resource "google_compute_health_check" "api" {
  name                = "payment-api-health"
  check_interval_sec  = 15
  timeout_sec         = 5
  healthy_threshold   = 2
  unhealthy_threshold = 3

  http_health_check {
    port         = 8080
    request_path = "/health/ready"
  }
}
----

.Non-Compliant

[source,terraform]
----
resource "google_compute_health_check" "api" {
  name = "health-check"
  tcp_health_check {
    port = 80
  }
  # Missing: http_health_check with request_path
  # Missing: explicit thresholds and intervals
}
----
