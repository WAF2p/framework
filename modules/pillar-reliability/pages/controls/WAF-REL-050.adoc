== Description

All inter-service and downstream HTTP/gRPC calls MUST define explicit timeout values. Critical service dependencies MUST implement circuit breaker patterns. Retry logic MUST use exponential backoff with jitter. Connection pools MUST have defined maximum sizes. Services MUST implement bulkhead isolation for different dependency classes. No service may rely on default (infinite or undefined) timeouts for external calls.

== Rationale

[cols="1,3"]
|===
|Risk |Description

|*Risk* |Unbounded timeouts and retries cascade failures into downstream systems and extend outages.

|*Risk* |Missing circuit breakers let workloads remain in perpetual failure states when downstream breaks.

|===

== Requirements

* All inter-service and downstream HTTP/gRPC calls MUST define explicit timeout values.
* Critical service dependencies MUST implement circuit breaker patterns.
* Retry logic MUST use exponential backoff with jitter.
* Connection pools MUST have defined maximum sizes.
* Services MUST implement bulkhead isolation for different dependency classes.

== Implementation Guidance

1. Implement the required configuration as code in Terraform or equivalent IaC.
2. Add an automated check to CI/CD so deviations are caught before deployment.

== Checks

=== waf-rel-050.tf.aws.alb-idle-timeout

*Engine:* `terraform` | *Provider:* aws | *Automated:* Yes

*AWS ALB idle timeout must be explicitly configured*

ALB idle_timeout must be set to a value appropriate for the workload, not relying on the default 60 seconds which may be too long or too short.

*Scope:* `resource` — `aws_lb`

*Assertions:*
* `idle_timeout` attribute exists — ALB idle_timeout must be explicitly configured, not using default.
* `load_balancer_type` equals `application` — This check applies to Application Load Balancers.

*Remediation:* Set idle_timeout on the aws_lb resource. Typical values: 30s for APIs, 300s for file uploads. Align with client-side timeout configuration.

.Compliant

[source,terraform]
----
resource "aws_lb" "api" {
  name               = "payment-api-alb"
  internal           = false
  load_balancer_type = "application"
  security_groups    = [aws_security_group.alb.id]
  subnets            = var.public_subnet_ids
  idle_timeout       = 30

  tags = var.mandatory_tags
}
----

.Non-Compliant

[source,terraform]
----
resource "aws_lb" "api" {
  name               = "payment-api-alb"
  internal           = false
  load_balancer_type = "application"
  security_groups    = [aws_security_group.alb.id]
  subnets            = var.public_subnet_ids
  # Missing: idle_timeout – using AWS default of 60s
  # WAF-REL-050 violation
}
----

=== waf-rel-050.tf.azurerm.app-gateway-timeout

*Engine:* `terraform` | *Provider:* azurerm | *Automated:* Yes

*Azure Application Gateway backend settings must define explicit timeouts*

Azure Application Gateway backend HTTP settings must define request_timeout_in_seconds rather than relying on defaults.

*Scope:* `resource` — `azurerm_application_gateway`

*Assertions:*
* `backend_http_settings` attribute exists — Application Gateway must define backend_http_settings.
* `backend_http_settings.request_timeout_in_seconds` attribute exists — Backend HTTP settings must define explicit request_timeout_in_seconds.

*Remediation:* Set request_timeout_in_seconds in the backend_http_settings block. Recommended values: 30 for APIs, 120 for batch operations.

.Compliant

[source,terraform]
----
resource "azurerm_application_gateway" "main" {
  name                = "payment-appgw"
  resource_group_name = azurerm_resource_group.main.name
  location            = azurerm_resource_group.main.location

  backend_http_settings {
    name                  = "api-backend-settings"
    cookie_based_affinity = "Disabled"
    port                  = 8080
    protocol              = "Http"
    request_timeout_in_seconds = 30
  }
  # ... other required blocks
}
----

.Non-Compliant

[source,terraform]
----
resource "azurerm_application_gateway" "main" {
  name                = "payment-appgw"
  resource_group_name = azurerm_resource_group.main.name
  location            = azurerm_resource_group.main.location

  backend_http_settings {
    name                  = "api-backend-settings"
    cookie_based_affinity = "Disabled"
    port                  = 8080
    protocol              = "Http"
    # Missing: request_timeout_in_seconds
    # WAF-REL-050 violation
  }
}
----

=== waf-rel-050.tf.google.cloud-run-timeout

*Engine:* `terraform` | *Provider:* google | *Automated:* Yes

*GCP Cloud Run services must define explicit request timeout*

GCP Cloud Run service templates must define timeout_seconds to prevent runaway requests from consuming resources indefinitely.

*Scope:* `resource` — `google_cloud_run_service`, `google_cloud_run_v2_service`

*Assertions:*
* `template.spec.timeout_seconds` attribute exists — Cloud Run service must define timeout_seconds in the template spec.

*Remediation:* Set timeout_seconds in the template.spec block of google_cloud_run_service. Default is 300s; set to the appropriate value for your workload latency SLO.

.Compliant

[source,terraform]
----
resource "google_cloud_run_service" "api" {
  name     = "payment-api"
  location = var.region

  template {
    spec {
      timeout_seconds = 30
      containers {
        image = var.container_image
        resources {
          limits = { cpu = "1000m", memory = "512Mi" }
        }
      }
    }
  }
}
----

.Non-Compliant

[source,terraform]
----
resource "google_cloud_run_service" "api" {
  name     = "payment-api"
  location = var.region

  template {
    spec {
      # Missing: timeout_seconds – using default 300s
      # WAF-REL-050 violation
      containers {
        image = var.container_image
      }
    }
  }
}
----
