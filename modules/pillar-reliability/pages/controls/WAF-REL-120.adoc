== Beschreibung

Critical user journeys MUST continue in a degraded mode when non-essential dependencies fail. Fallback behavior, default responses, and feature degradation order MUST be documented. Degradation paths MUST be tested in staging and during chaos experiments. Non-critical features MUST be tiered so lower-priority functions can be disabled first.

== Begründung

[cols="1,3"]
|===
|Risiko |Beschreibung

|*Risk* |Hard dependencies on non-essential services turn partial failures into total outages.

|*Risk* |Untested fallback paths often fail when first invoked during a real incident.

|===

== Anforderungen

* Critical user journeys MUST continue in a degraded mode when non-essential dependencies fail.
* Fallback behavior, default responses, and feature degradation order MUST be documented.
* Degradation paths MUST be tested in staging and during chaos experiments.
* Non-critical features MUST be tiered so lower-priority functions can be disabled first.

== Implementierungsleitfaden

. Document the requirement in a version-controlled policy, ADR, or standard.
. Assign ownership and establish a review cadence (e.g., quarterly).
. Implement the required configuration as code in Terraform or equivalent IaC.
