== Beschreibung

All production stateful and stateless workloads MUST be deployed across a minimum of two Availability Zones (AZs). Databases, caches, and message queues MUST use multi-AZ configurations with automatic failover. Load balancers MUST span at least two AZs. Auto-scaling groups and Kubernetes clusters MUST distribute nodes and pods across AZs. Single-AZ deployments in production are not acceptable without explicit documented risk acceptance.

== Begründung

[cols="1,3"]
|===
|Risiko |Beschreibung

|*Risk* |Single-AZ deployments become completely unreachable during zone failures.

|*Risk* |Missing multi-AZ strategies violate availability requirements for critical workloads.

|===

== Anforderungen

* All production stateful and stateless workloads MUST be deployed across a minimum of two Availability Zones (AZs).
* Databases, caches, and message queues MUST use multi-AZ configurations with automatic failover.
* Load balancers MUST span at least two AZs.
* Auto-scaling groups and Kubernetes clusters MUST distribute nodes and pods across AZs.

== Implementierungsleitfaden

1. Implement the required configuration as code in Terraform or equivalent IaC.
2. Add an automated check to CI/CD so deviations are caught before deployment.

== Checks

=== waf-rel-030.tf.aws.rds-multi-az

*Engine:* `terraform` | *Provider:* aws | *Automated:* Ja

*AWS RDS instances must have Multi-AZ enabled*

Production RDS instances must have multi_az = true to enable automatic failover to a standby replica in a different AZ on failure.

*Scope:* `resource` — `aws_db_instance`

*Assertions:*
* `multi_az` is true — RDS instance must have multi_az = true for production availability.

*Remediation:* Set multi_az = true on the aws_db_instance resource. This creates a synchronous standby replica in a different AZ. Failover is automatic and typically completes within 1-2 minutes.

.Compliant

[source,terraform]
----
resource "aws_db_instance" "main" {
  identifier        = "payment-db-prod"
  engine            = "postgres"
  engine_version    = "15.4"
  instance_class    = "db.t3.medium"
  allocated_storage = 100
  multi_az          = true
  db_subnet_group_name = aws_db_subnet_group.main.name
  tags = var.mandatory_tags
}
----

.Non-Compliant

[source,terraform]
----
resource "aws_db_instance" "main" {
  identifier        = "payment-db-prod"
  engine            = "postgres"
  instance_class    = "db.t3.medium"
  allocated_storage = 100
  multi_az          = false  # WAF-REL-030 violation
  db_subnet_group_name = aws_db_subnet_group.main.name
}
----

=== waf-rel-030.tf.aws.autoscaling-multi-az

*Engine:* `terraform` | *Provider:* aws | *Automated:* Ja

*AWS Auto Scaling Group must span at least 2 availability zones*

Auto Scaling Groups in production must reference subnets in at least 2 different AZs to ensure compute redundancy.

*Scope:* `resource` — `aws_autoscaling_group`

*Assertions:*
* `vpc_zone_identifier` not empty — Auto Scaling Group must specify VPC subnets across multiple AZs.
* `min_size` greater than or equal `1` — Auto Scaling Group minimum size must be at least 2 for HA.

*Remediation:* Set vpc_zone_identifier to a list containing subnet IDs from at least 2 AZs. Increase min_size to 2 to ensure at least one instance per AZ during failures.

.Compliant

[source,terraform]
----
resource "aws_autoscaling_group" "api" {
  name               = "payment-api-asg"
  min_size           = 2
  max_size           = 10
  desired_capacity   = 2
  vpc_zone_identifier = [
    aws_subnet.private_az1.id,
    aws_subnet.private_az2.id,
  ]
}
----

.Non-Compliant

[source,terraform]
----
resource "aws_autoscaling_group" "api" {
  name               = "payment-api-asg"
  min_size           = 1
  max_size           = 4
  desired_capacity   = 1
  vpc_zone_identifier = [aws_subnet.private_az1.id]
  # Single AZ – WAF-REL-030 violation
}
----

=== waf-rel-030.tf.azurerm.db-availability-zone

*Engine:* `terraform` | *Provider:* azurerm | *Automated:* Ja

*Azure database services must use zone-redundant configuration*

Azure SQL Database, PostgreSQL Flexible Server, and other managed databases must use zone_redundant = true or configure standby_availability_zone.

*Scope:* `resource` — `azurerm_postgresql_flexible_server`, `azurerm_mssql_database`, `azurerm_mysql_flexible_server`

*Assertions:*
* `high_availability` attribute exists — Database must define high_availability block with zone-redundant configuration.

*Remediation:* Add a high_availability block with mode = "ZoneRedundant" and configure standby_availability_zone to a different zone than the primary.

.Compliant

[source,terraform]
----
resource "azurerm_postgresql_flexible_server" "main" {
  name                = "payment-db-prod"
  resource_group_name = azurerm_resource_group.main.name
  location            = azurerm_resource_group.main.location
  version             = "15"
  sku_name            = "GP_Standard_D2s_v3"
  availability_zone   = "1"

  high_availability {
    mode                      = "ZoneRedundant"
    standby_availability_zone = "2"
  }
}
----

.Non-Compliant

[source,terraform]
----
resource "azurerm_postgresql_flexible_server" "main" {
  name                = "payment-db-prod"
  resource_group_name = azurerm_resource_group.main.name
  location            = azurerm_resource_group.main.location
  version             = "15"
  sku_name            = "GP_Standard_D2s_v3"
  # Missing: high_availability – single zone deployment
}
----

=== waf-rel-030.tf.google.sql-availability-type

*Engine:* `terraform` | *Provider:* google | *Automated:* Ja

*GCP Cloud SQL must use REGIONAL availability type*

GCP Cloud SQL instances must use availability_type = REGIONAL for automatic failover across zones in the same region.

*Scope:* `resource` — `google_sql_database_instance`

*Assertions:*
* `settings.availability_type` equals `REGIONAL` — Cloud SQL must use REGIONAL availability type, not ZONAL.

*Remediation:* Set availability_type = "REGIONAL" in the settings block of google_sql_database_instance to enable automatic failover to a different zone.

.Compliant

[source,terraform]
----
resource "google_sql_database_instance" "main" {
  name             = "payment-db-prod"
  database_version = "POSTGRES_15"
  settings {
    tier              = "db-custom-2-7680"
    availability_type = "REGIONAL"
    backup_configuration {
      enabled    = true
      start_time = "02:00"
    }
  }
}
----

.Non-Compliant

[source,terraform]
----
resource "google_sql_database_instance" "main" {
  name             = "payment-db-prod"
  database_version = "POSTGRES_15"
  settings {
    tier              = "db-custom-2-7680"
    availability_type = "ZONAL"  # WAF-REL-030 violation
  }
}
----
