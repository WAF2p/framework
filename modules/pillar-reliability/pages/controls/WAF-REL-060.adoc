== Description

Every production workload MUST have a documented Incident Response (IR) plan with defined severity levels, escalation paths, and on-call rotations. Runbooks MUST exist for all critical alerts and MUST be version-controlled. Runbooks MUST be linked directly from alert notifications. Post-incident reviews MUST be conducted within 5 business days and findings MUST be tracked as actionable items. Mean Time to Recovery (MTTR) MUST be measured per incident.

== Rationale

[cols="1,3"]
|===
|Risk |Description

|*Risk* |Missing incident-response plans lead to panicked ad-hoc reactions and longer MTTR.

|*Risk* |Unclear escalation paths delay involving the right experts.

|===

== Requirements

* Every production workload MUST have a documented Incident Response (IR) plan with defined severity levels, escalation paths, and on-call rotations.
* Runbooks MUST exist for all critical alerts and MUST be version-controlled.
* Runbooks MUST be linked directly from alert notifications.
* Post-incident reviews MUST be conducted within 5 business days and findings MUST be tracked as actionable items.
* Mean Time to Recovery (MTTR) MUST be measured per incident.

== Implementation Guidance

1. Document the requirement in a version-controlled policy or standard.
2. Assign ownership and establish a review cadence (e.g., quarterly).
3. Implement the required configuration as code in Terraform or equivalent IaC.

== Checks

=== waf-rel-060.tf.aws.sns-topic-alarm-action

*Engine:* `terraform` | *Provider:* aws | *Automated:* Yes

*AWS CloudWatch alarms must route to SNS topics for on-call notification*

CloudWatch alarms for production services must have alarm_actions pointing to SNS topics that are connected to on-call notification systems.

*Scope:* `resource` — `aws_cloudwatch_metric_alarm`

*Assertions:*
* `alarm_actions` not empty — CloudWatch alarm must have alarm_actions configured for on-call notification.
* `ok_actions` not empty — CloudWatch alarm must have ok_actions to notify when alert resolves.

*Remediation:* Add alarm_actions and ok_actions pointing to an SNS topic. The SNS topic should be subscribed to by PagerDuty, OpsGenie, or email for on-call notification.

.Compliant

[source,terraform]
----
resource "aws_cloudwatch_metric_alarm" "api_errors" {
  alarm_name          = "payment-api-error-rate"
  comparison_operator = "GreaterThanThreshold"
  evaluation_periods  = 3
  metric_name         = "5XXError"
  namespace           = "AWS/ApiGateway"
  period              = 60
  statistic           = "Sum"
  threshold           = 10
  alarm_actions       = [aws_sns_topic.oncall_critical.arn]
  ok_actions          = [aws_sns_topic.oncall_critical.arn]
  alarm_description   = "SEV2: Payment API error rate > 1%. Runbook: https://wiki/runbooks/payment-api-errors"
}
----

.Non-Compliant

[source,terraform]
----
resource "aws_cloudwatch_metric_alarm" "api_errors" {
  alarm_name          = "payment-api-error-rate"
  comparison_operator = "GreaterThanThreshold"
  evaluation_periods  = 3
  metric_name         = "5XXError"
  namespace           = "AWS/ApiGateway"
  period              = 60
  statistic           = "Sum"
  threshold           = 10
  # Missing: alarm_actions – alert fires but no one is notified
  # WAF-REL-060 violation
}
----

=== waf-rel-060.tf.azurerm.action-group-configured

*Engine:* `terraform` | *Provider:* azurerm | *Automated:* Yes

*Azure Monitor action groups must have webhook or email receivers configured*

Azure Monitor action groups used by metric alerts must have at least one email_receiver or webhook_receiver configured for on-call notification.

*Scope:* `resource` — `azurerm_monitor_action_group`

*Assertions:*
* `short_name` not empty — Action group must have a short_name for SMS/voice notifications.
* `email_receiver` attribute exists — Action group must have at least one email_receiver or webhook_receiver.

*Remediation:* Add email_receiver or webhook_receiver blocks to the azurerm_monitor_action_group. For PagerDuty or OpsGenie integration, use webhook_receiver pointing to their API URL.

.Compliant

[source,terraform]
----
resource "azurerm_monitor_action_group" "oncall" {
  name                = "oncall-critical"
  resource_group_name = azurerm_resource_group.main.name
  short_name          = "oncall"

  email_receiver {
    name          = "on-call-team"
    email_address = var.oncall_email
  }

  webhook_receiver {
    name        = "pagerduty"
    service_uri = var.pagerduty_webhook_url
  }
}
----

.Non-Compliant

[source,terraform]
----
resource "azurerm_monitor_action_group" "alerts" {
  name                = "alerts"
  resource_group_name = azurerm_resource_group.main.name
  short_name          = "alerts"
  # Missing: no receivers configured – alerts fire silently
  # WAF-REL-060 violation
}
----

=== waf-rel-060.tf.google.monitoring-notification-channel

*Engine:* `terraform` | *Provider:* google | *Automated:* Yes

*GCP alert policies must have notification channels configured*

GCP Monitoring alert policies must reference at least one notification channel to ensure on-call teams are notified during incidents.

*Scope:* `resource` — `google_monitoring_alert_policy`

*Assertions:*
* `notification_channels` not empty — Alert policy must reference at least one notification channel.
* `display_name` not empty — Alert policy must have a descriptive display name including service context.

*Remediation:* Add notification_channels to the google_monitoring_alert_policy referencing configured google_monitoring_notification_channel resources.

.Compliant

[source,terraform]
----
resource "google_monitoring_notification_channel" "pagerduty" {
  display_name = "PagerDuty On-Call"
  type         = "pagerduty"
  labels = {
    service_key = var.pagerduty_service_key
  }
}

resource "google_monitoring_alert_policy" "api_error_rate" {
  display_name          = "Payment API – Error Rate SEV2"
  combiner              = "OR"
  notification_channels = [google_monitoring_notification_channel.pagerduty.name]
  conditions {
    display_name = "Error rate > 1%"
    condition_threshold {
      filter          = "resource.type=\"cloud_run_revision\" AND metric.type=\"run.googleapis.com/request_count\""
      comparison      = "COMPARISON_GT"
      threshold_value = 100
      duration        = "60s"
    }
  }
}
----

.Non-Compliant

[source,terraform]
----
resource "google_monitoring_alert_policy" "api_errors" {
  display_name = "Errors"
  combiner     = "OR"
  conditions {
    display_name = "Error count high"
    condition_threshold {
      filter          = "metric.type=\"logging.googleapis.com/user/errors\""
      comparison      = "COMPARISON_GT"
      threshold_value = 100
      duration        = "60s"
    }
  }
  # Missing: notification_channels – WAF-REL-060 violation
}
----
