= WAF-REL-040 – Backup & Recovery Validation
:page-toc: right

[.metadata]
*Säule:* Reliability | *Schweregrad:* Kritisch | *Kategorie:* Secret Management | *Automatisierbar:* High

== Beschreibung

All production databases, object stores, and stateful services MUST have automated backup configurations with defined retention periods. Backup configurations MUST specify RPO-aligned retention. Recovery procedures MUST be tested at minimum quarterly through documented restore exercises. Backups MUST be stored in a separate account, region, or vault from the primary data source. Point-in-time recovery (PITR) MUST be enabled for all production databases. Untested backups are not backups.

== Begründung

[cols="1,3"]
|===
|Risiko |Beschreibung

|*Risk* |Databases without backups or with too short retention cannot be recovered from corruption.

|*Risk* |Missing point-in-time recovery significantly extends recovery time from logical errors.

|===

== Anforderungen

* All production databases, object stores, and stateful services MUST have automated backup configurations with defined retention periods.
* Backup configurations MUST specify RPO-aligned retention.
* Recovery procedures MUST be tested at minimum quarterly through documented restore exercises.
* Backups MUST be stored in a separate account, region, or vault from the primary data source.
* Point-in-time recovery (PITR) MUST be enabled for all production databases.

== Implementierungsleitfaden

1. Document the requirement in a version-controlled policy or standard.
2. Assign ownership and establish a review cadence (e.g., quarterly).
3. Implement the required configuration as code in Terraform or equivalent IaC.

== Checks

=== waf-rel-040.tf.aws.rds-backup-retention

*Engine:* `terraform` | *Provider:* aws | *Automated:* Ja

*AWS RDS must have backup retention >= 7 days with PITR enabled*

Production RDS instances must have backup_retention_period of at least 7 days to enable point-in-time recovery across a full week of transactions.

*Scope:* `resource` — `aws_db_instance`, `aws_rds_cluster`

*Assertions:*
* `backup_retention_period` greater than or equal `1` — RDS backup retention must be at least 7 days for production.
* `deletion_protection` is true — RDS deletion protection must be enabled to prevent accidental deletion.

*Remediation:* Set backup_retention_period >= 7 on the aws_db_instance resource. Enable deletion_protection = true to prevent accidental deletion. Configure backup_window to a low-traffic maintenance window.

.Compliant

[source,terraform]
----
resource "aws_db_instance" "main" {
  identifier             = "payment-db-prod"
  engine                 = "postgres"
  instance_class         = "db.t3.medium"
  allocated_storage      = 100
  backup_retention_period = 14
  backup_window          = "02:00-03:00"
  deletion_protection    = true
  copy_tags_to_snapshot  = true
}
----

.Non-Compliant

[source,terraform]
----
resource "aws_db_instance" "main" {
  identifier             = "payment-db-prod"
  engine                 = "postgres"
  instance_class         = "db.t3.medium"
  allocated_storage      = 100
  backup_retention_period = 1   # WAF-REL-040 violation
  deletion_protection    = false # WAF-REL-040 violation
}
----

=== waf-rel-040.tf.aws.s3-versioning

*Engine:* `terraform` | *Provider:* aws | *Automated:* Ja

*AWS S3 buckets with production data must have versioning enabled*

S3 buckets storing production data must have versioning enabled to allow recovery from accidental deletion or overwrite.

*Scope:* `resource` — `aws_s3_bucket_versioning`

*Assertions:*
* `versioning_configuration.status` equals `Enabled` — S3 bucket versioning must be Enabled for production data buckets.

*Remediation:* Add an aws_s3_bucket_versioning resource referencing the bucket with versioning_configuration { status = "Enabled" }.

.Compliant

[source,terraform]
----
resource "aws_s3_bucket_versioning" "data" {
  bucket = aws_s3_bucket.production_data.id
  versioning_configuration {
    status = "Enabled"
  }
}
----

.Non-Compliant

[source,terraform]
----
resource "aws_s3_bucket_versioning" "data" {
  bucket = aws_s3_bucket.production_data.id
  versioning_configuration {
    status = "Suspended"  # WAF-REL-040 violation
  }
}
----

=== waf-rel-040.tf.azurerm.postgresql-backup

*Engine:* `terraform` | *Provider:* azurerm | *Automated:* Ja

*Azure PostgreSQL Flexible Server must have backup retention >= 7 days*

Azure PostgreSQL Flexible Server must configure backup_retention_days of at least 7 for production workloads.

*Scope:* `resource` — `azurerm_postgresql_flexible_server`, `azurerm_mysql_flexible_server`

*Assertions:*
* `backup_retention_days` greater than or equal `7` — Database backup retention must be at least 7 days.
* `geo_redundant_backup_enabled` is true — Geo-redundant backup must be enabled for cross-region recovery.

*Remediation:* Set backup_retention_days >= 7 and geo_redundant_backup_enabled = true on the azurerm_postgresql_flexible_server resource.

.Compliant

[source,terraform]
----
resource "azurerm_postgresql_flexible_server" "main" {
  name                         = "payment-db-prod"
  resource_group_name          = azurerm_resource_group.main.name
  location                     = "westeurope"
  version                      = "15"
  backup_retention_days        = 14
  geo_redundant_backup_enabled = true
  sku_name                     = "GP_Standard_D2s_v3"
}
----

.Non-Compliant

[source,terraform]
----
resource "azurerm_postgresql_flexible_server" "main" {
  name                         = "payment-db-prod"
  resource_group_name          = azurerm_resource_group.main.name
  location                     = "westeurope"
  version                      = "15"
  backup_retention_days        = 1   # WAF-REL-040 violation
  geo_redundant_backup_enabled = false # WAF-REL-040 violation
  sku_name                     = "GP_Standard_D2s_v3"
}
----

=== waf-rel-040.tf.google.sql-backup-config

*Engine:* `terraform` | *Provider:* google | *Automated:* Ja

*GCP Cloud SQL must have automated backups and PITR enabled*

GCP Cloud SQL instances must have automated backups enabled with point-in-time recovery enabled for production databases.

*Scope:* `resource` — `google_sql_database_instance`

*Assertions:*
* `settings.backup_configuration.enabled` is true — Cloud SQL automated backups must be enabled.
* `settings.backup_configuration.point_in_time_recovery_enabled` is true — Cloud SQL point-in-time recovery must be enabled.

*Remediation:* Set enabled = true and point_in_time_recovery_enabled = true in the backup_configuration block of the google_sql_database_instance settings.

.Compliant

[source,terraform]
----
resource "google_sql_database_instance" "main" {
  name             = "payment-db-prod"
  database_version = "POSTGRES_15"
  settings {
    tier = "db-custom-2-7680"
    backup_configuration {
      enabled                        = true
      start_time                     = "02:00"
      point_in_time_recovery_enabled = true
      transaction_log_retention_days = 7
      retained_backups               = 14
      retention_unit                 = "COUNT"
    }
  }
}
----

.Non-Compliant

[source,terraform]
----
resource "google_sql_database_instance" "main" {
  name             = "payment-db-prod"
  database_version = "POSTGRES_15"
  settings {
    tier = "db-custom-2-7680"
    backup_configuration {
      enabled = false  # WAF-REL-040 violation
    }
  }
}
----
