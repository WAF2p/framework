== Description

A formally documented break-glass procedure MUST exist defining trigger criteria, approval workflow, activation steps, and post-incident review requirements. All break-glass actions MUST be fully logged via CloudTrail (or equivalent) with log file validation enabled. Root account and emergency admin activities MUST trigger real-time alerts. Post-incident reviews MUST be documented and linked to the activation event.

== Rationale

[cols="1,3"]
|===
|Risk |Description

|*Risk* |Emergency access procedures without documentation lead to unauthorized break-glass actions in a crisis.

|*Risk* |Missing break-glass processes extend recovery time during severe incidents.

|===

== Requirements

* A formally documented break-glass procedure MUST exist defining trigger criteria, approval workflow, activation steps, and post-incident review requirements.
* All break-glass actions MUST be fully logged via CloudTrail (or equivalent) with log file validation enabled.
* Root account and emergency admin activities MUST trigger real-time alerts.
* Post-incident reviews MUST be documented and linked to the activation event.

== Implementation Guidance

1. Implement the required configuration as code in Terraform or equivalent IaC.
2. Add an automated check to CI/CD so deviations are caught before deployment.

== Checks

=== waf-sov-070.tf.aws.cloudtrail-enabled-all-regions

*Engine:* `terraform` | *Provider:* aws | *Automated:* Yes

*CloudTrail must be multi-region with log file validation*

At least one CloudTrail must be configured with is_multi_region_trail = true and enable_log_file_validation = true to capture all API activity and detect log tampering.

*Scope:* `resource` — `aws_cloudtrail`

*Assertions:*
* `is_multi_region_trail` is true — CloudTrail must be multi-region to capture break-glass events from all regions.
* `enable_log_file_validation` is true — CloudTrail log file validation must be enabled to detect tampering.
* `include_global_service_events` is true — CloudTrail must include global service events (IAM, STS, etc.).

*Remediation:* Set is_multi_region_trail = true, enable_log_file_validation = true, and include_global_service_events = true on CloudTrail.

.Compliant

[source,terraform]
----
resource "aws_cloudtrail" "sovereign" {
  name                          = "sovereign-audit-trail"
  s3_bucket_name                = aws_s3_bucket.cloudtrail.id
  is_multi_region_trail         = true
  enable_log_file_validation    = true
  include_global_service_events = true
  cloud_watch_logs_group_arn    = "${aws_cloudwatch_log_group.cloudtrail.arn}:*"
  cloud_watch_logs_role_arn     = aws_iam_role.cloudtrail_cw.arn
}
----

.Non-Compliant

[source,terraform]
----
resource "aws_cloudtrail" "trail" {
  name           = "my-trail"
  s3_bucket_name = "my-logs"
  # Defaults: single region, no validation, no CloudWatch
}
----

=== waf-sov-070.tf.aws.cloudtrail-s3-bucket-not-public

*Engine:* `terraform` | *Provider:* aws | *Automated:* Yes

*CloudTrail S3 bucket must not be publicly accessible*

The S3 bucket storing CloudTrail logs must have public access blocked. Public CloudTrail logs expose the full API activity of the account.

*Scope:* `resource` — `aws_s3_bucket_public_access_block`

*Assertions:*
* `block_public_acls` is true — CloudTrail S3 bucket must block public ACLs.
* `block_public_policy` is true — CloudTrail S3 bucket must block public bucket policy.
* `ignore_public_acls` is true — CloudTrail S3 bucket must ignore public ACLs.
* `restrict_public_buckets` is true — CloudTrail S3 bucket must restrict public buckets.

*Remediation:* Create an aws_s3_bucket_public_access_block resource for the CloudTrail bucket with all four settings set to true.

.Compliant

[source,terraform]
----
resource "aws_s3_bucket_public_access_block" "cloudtrail" {
  bucket                  = aws_s3_bucket.cloudtrail.id
  block_public_acls       = true
  block_public_policy     = true
  ignore_public_acls      = true
  restrict_public_buckets = true
}
----

.Non-Compliant

[source,terraform]
----
resource "aws_s3_bucket_public_access_block" "cloudtrail" {
  bucket            = aws_s3_bucket.cloudtrail.id
  block_public_acls = true
  # Other settings missing – defaults to false
}
----

=== waf-sov-070.tf.aws.cloudwatch-alarm-root-login

*Engine:* `terraform` | *Provider:* aws | *Automated:* Yes

*CloudWatch alarm must exist for root account sign-in*

A CloudWatch metric filter and alarm must be configured to detect and alert on any root account API call or console sign-in. Root usage outside a documented break-glass process is a critical sovereignty violation.

*Scope:* `resource` — `aws_cloudwatch_metric_alarm`

*Assertions:*
* `log_group_name` has associated resource — No CloudWatch alarm found monitoring root account activity.

*Remediation:* Create a CloudWatch metric filter matching root API calls and an alarm that notifies a security SNS topic when the metric is triggered.

.Compliant

[source,terraform]
----
resource "aws_cloudwatch_log_metric_filter" "root_usage" {
  name           = "root-account-usage"
  pattern        = "{$.userIdentity.type = Root && $.userIdentity.invokedBy NOT EXISTS && $.eventType != AwsServiceEvent}"
  log_group_name = aws_cloudwatch_log_group.cloudtrail.name
  metric_transformation {
    name      = "RootAccountUsageCount"
    namespace = "CloudTrailMetrics"
    value     = "1"
  }
}
resource "aws_cloudwatch_metric_alarm" "root_usage" {
  alarm_name          = "root-account-usage"
  comparison_operator = "GreaterThanOrEqualToThreshold"
  evaluation_periods  = "1"
  metric_name         = "RootAccountUsageCount"
  namespace           = "CloudTrailMetrics"
  period              = "60"
  statistic           = "Sum"
  threshold           = "1"
  alarm_actions       = [aws_sns_topic.security_alerts.arn]
}
----

.Non-Compliant

[source,terraform]
----
# No metric filter or alarm for root account activity
----

=== waf-sov-070.tf.aws.cloudwatch-alarm-iam-policy-changes

*Engine:* `terraform` | *Provider:* aws | *Automated:* Yes

*CloudWatch alarm must exist for IAM policy changes*

Unauthorized IAM policy changes can escalate privileges or disable sovereignty controls. An alarm must detect and alert on IAM policy creation, modification, or deletion events.

*Scope:* `resource` — `aws_cloudwatch_log_metric_filter`

*Assertions:*
* `pattern` matches pattern `CreatePolicy|DeletePolicy|AttachRolePolicy|DetachRolePolicy` — No CloudWatch metric filter found monitoring IAM policy changes.

*Remediation:* Create metric filters for IAM policy changes (CreatePolicy, DeletePolicy, AttachRolePolicy, DetachRolePolicy) with associated CloudWatch alarms.

*Engine:* `terraform` | *Provider:* aws | *Automated:* Yes

The S3 bucket storing CloudTrail logs should have access logging enabled to detect unauthorized access attempts to the audit logs themselves.

*Scope:* `resource` — `aws_s3_bucket_logging`

*Assertions:*
* `s3_bucket_name` has associated resource — CloudTrail S3 bucket should have an aws_s3_bucket_logging resource configured.

*Remediation:* Create an aws_s3_bucket_logging resource for the CloudTrail bucket targeting a separate access logs bucket.

=== waf-sov-070.config.azurerm.break-glass-policy

*Engine:* `config` | *Provider:* azurerm | *Automated:* Yes

*Azure break-glass procedure must be documented*

A version-controlled policy document must exist at docs/sovereign/waf-sov-070-azurerm-break-glass.md and document the Azure break-glass procedure including triggers, approvers, credentials, and revocation steps.

*Scope:* `file` — `docs/sovereign/waf-sov-070-azurerm-break-glass.md`

*Assertions:*
* `content` matches pattern `(?i)MUST|SHALL|required|mandatory|enforced|documented` — Azure break-glass policy file must contain a normative requirement statement.

*Remediation:* Create or update docs/sovereign/waf-sov-070-azurerm-break-glass.md. State triggers, approvers, emergency account details, audit trail, and periodic test schedule.

.Compliant

[source,text]
----
docs/sovereign/waf-sov-070-azurerm-break-glass.md:
- Break-glass triggers are defined (e.g., PIM outage, global admin lockout).
- Two cloud-only emergency accounts are created with strong authentication.
- Credential storage and revocation steps are documented.
----

.Non-Compliant

[source,text]
----
# docs/sovereign/waf-sov-070-azurerm-break-glass.md is missing or does not contain a normative requirement.
