== Beschreibung

Keys for sensitive and classified data MUST be generated and stored in Hardware Security Modules (HSM) or sovereign managed key services. Key operations MUST enforce role separation, dual control, and audit logging. Key import, export, and backup MUST follow documented and approved procedures. Cloud provider managed keys alone MUST NOT be used for sovereign data classes.

== Begründung

[cols="1,3"]
|===
|Risiko |Beschreibung

|*Risk* |Provider-managed keys may be accessible to cloud operators or subject to foreign jurisdiction.

|*Risk* |Missing HSM backing weakens key protection and complicates compliance with sovereignty requirements.

|===

== Anforderungen

* Keys for sensitive and classified data MUST be generated and stored in Hardware Security Modules (HSM) or sovereign managed key services.
* Key operations MUST enforce role separation, dual control, and audit logging.
* Key import, export, and backup MUST follow documented and approved procedures.
* Cloud provider managed keys alone MUST NOT be used for sovereign data classes.

== Implementierungsleitfaden

. Document the requirement in a version-controlled policy, ADR, or standard.
. Assign ownership and establish a review cadence (e.g., quarterly).
. Implement the required configuration as code in Terraform or equivalent IaC.
