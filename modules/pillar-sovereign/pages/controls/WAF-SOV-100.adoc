== Beschreibung

A documented exit plan MUST exist covering data export procedures, IaC portability strategy, dependency replacement mapping, timeline, and cost estimates. Exit/restore drills MUST be performed at least annually to validate that the exit plan is executable. IaC must use open standards and provider-agnostic patterns where feasible to reduce proprietary lock-in. S3 bucket lifecycle policies MUST be configured to support data retention and deletion requirements.

== Begründung

[cols="1,3"]
|===
|Risiko |Beschreibung

|*Risk* |Missing exit plans lead to data lock-in and blocked cloud migrations.

|*Risk* |Undocumented export procedures extend migration time and increase regulatory risk.

|===

== Anforderungen

* A documented exit plan MUST exist covering data export procedures, IaC portability strategy, dependency replacement mapping, timeline, and cost estimates.
* Exit/restore drills MUST be performed at least annually to validate that the exit plan is executable.
* IaC must use open standards and provider-agnostic patterns where feasible to reduce proprietary lock-in.
* S3 bucket lifecycle policies MUST be configured to support data retention and deletion requirements.

== Implementierungsleitfaden

1. Document the requirement in a version-controlled policy or standard.
2. Assign ownership and establish a review cadence (e.g., quarterly).

== Checks

=== waf-sov-100.tf.aws.s3-lifecycle-policy-defined

*Engine:* `terraform` | *Provider:* aws | *Automated:* Ja

*S3 buckets storing sovereign data must have lifecycle policies*

S3 buckets containing sovereign data must have lifecycle rules defined to enforce data retention, transition to cheaper storage tiers, and scheduled deletion per the data residency policy.

*Scope:* `resource` — `aws_s3_bucket`

*Assertions:*
* `id` has associated resource — S3 bucket has no lifecycle configuration. Data retention and deletion cannot be automated.

*Remediation:* Create an aws_s3_bucket_lifecycle_configuration resource defining transition and expiration rules consistent with your data retention policy.

.Compliant

[source,terraform]
----
resource "aws_s3_bucket_lifecycle_configuration" "sovereign_data" {
  bucket = aws_s3_bucket.data.id
  rule {
    id     = "sovereign-retention-policy"
    status = "Enabled"
    transition {
      days          = 90
      storage_class = "STANDARD_IA"
    }
    transition {
      days          = 365
      storage_class = "GLACIER"
    }
    expiration {
      days = 2555  # 7 years for financial data
    }
  }
}
----

.Non-Compliant

[source,terraform]
----
resource "aws_s3_bucket" "data" {
  bucket = "sovereign-data"
  # No lifecycle configuration
}
----

=== waf-sov-100.tf.aws.s3-versioning-for-data-portability

*Engine:* `terraform` | *Provider:* aws | *Automated:* Ja

*S3 buckets with sovereign data should have versioning enabled*

S3 bucket versioning supports data portability by preserving historical versions of objects, enabling point-in-time exports during exit procedures.

*Scope:* `resource` — `aws_s3_bucket_versioning`

*Assertions:*
* `versioning_configuration.status` equals `Enabled` — S3 bucket versioning must be Enabled for sovereign data portability.

*Remediation:* Enable versioning on S3 buckets containing sovereign data.

=== waf-sov-100.tf.any.resource-tag-portability

*Engine:* `terraform` | *Provider:* any | *Automated:* Ja

*Data resources should have portability metadata tags*

Data resources should be tagged with 'portability-class' and 'data-export-enabled' to support automated export orchestration during exit procedures.

*Scope:* `resource` — `aws_s3_bucket`, `aws_rds_instance`, `aws_rds_cluster`, `aws_dynamodb_table`, `azurerm_storage_account`, `azurerm_sql_database`, `google_storage_bucket`, `google_sql_database_instance`, `stackit_container_registry`, `stackit_mysql_instance`, `stackit_opensearch_instance`, `stackit_redis_instance`, `ovh_cloud_project`, `ovh_vps`, `hcloud_server`, `hcloud_volume`

*Assertions:*
* `tags` key exists — Resource is missing 'portability-class' tag needed for exit orchestration.

*Remediation:* Add 'portability-class' tag with values: portable | proprietary-limited | proprietary-locked. Aim to eliminate 'proprietary-locked' resources or document their alternatives.

.Compliant

[source,terraform]
----
resource "aws_rds_instance" "app" {
  tags = {
    portability-class    = "portable"          # PostgreSQL – open standard
    data-export-enabled  = "true"
    data-residency       = "eu-only"
  }
}
----

.Non-Compliant

[source,terraform]
----
resource "aws_rds_instance" "app" {
  tags = {
    environment = "production"
    # No portability metadata
  }
}
----

=== waf-sov-100.tf.any.no-proprietary-lock-in-patterns

*Engine:* `terraform` | *Provider:* aws | *Automated:* Ja

*Flag use of high-lock-in proprietary data services*

Certain AWS services have limited or no export capability and represent high lock-in risk. Their use should be flagged for review and documented in the dependency replacement map.

*Scope:* `resource` — `aws_cloudsearch_domain`, `aws_mq_broker`, `aws_redshift_cluster`

*Assertions:*
* `tags` key exists — High-lock-in service used without documented exit strategy. Add 'exit-strategy-documented' tag.

*Remediation:* Add an 'exit-strategy-documented' tag referencing the exit plan section covering this service. Maintain a documented replacement alternative.

=== waf-sov-100.tf.aws.rds-deletion-protection

*Engine:* `terraform` | *Provider:* aws | *Automated:* Ja

*RDS production instances must have deletion protection enabled*

RDS instances tagged as production must have deletion_protection = true to prevent accidental destruction of sovereign data during exit procedures or infrastructure changes.

*Scope:* `resource` — `aws_db_instance`, `aws_rds_cluster`

*Assertions:*
* `deletion_protection` is true — RDS deletion_protection must be enabled to prevent accidental data loss.

*Remediation:* Set deletion_protection = true on all production RDS instances and clusters.

.Compliant

[source,terraform]
----
resource "aws_db_instance" "sovereign" {
  deletion_protection = true
  # ...
}
----

.Non-Compliant

[source,terraform]
----
resource "aws_db_instance" "sovereign" {
  deletion_protection = false  # Data can be deleted without confirmation
}
----
