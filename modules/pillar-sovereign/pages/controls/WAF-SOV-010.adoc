= WAF-SOV-010 – Data Residency Policy Defined
:page-toc: right
:control-id: WAF-SOV-010
:pillar: sovereign
:severity: high
:category: identity-access
:automatable: High
:description: A documented data-residency policy MUST exist that explicitly defines allowed regions, data classifications, and storage rules for all data types: primary data, replicas, backups, logs, traces, metrics, and metadata. The policy MUST be version-controlled and technically reflected in IaC defaults and variable validation.

[.metadata]
*Säule:* Sovereign | *Schweregrad:* Hoch | *Kategorie:* Identity Access | *Automatisierbar:* High

== Beschreibung

A documented data-residency policy MUST exist that explicitly defines allowed regions, data classifications, and storage rules for all data types: primary data, replicas, backups, logs, traces, metrics, and metadata. The policy MUST be version-controlled and technically reflected in IaC defaults and variable validation.

== Begründung

[cols="1,3"]
|===
|Risiko |Beschreibung

|*Risk* |Data may leave approved jurisdictions and violate regulatory requirements.

|*Risk* |Vendor lock-in reduces future portability and sovereignty options.

|===

== Anforderungen

* A documented data-residency policy MUST exist that explicitly defines allowed regions, data classifications, and storage rules for all data types: primary data, replicas, backups, logs, traces, metrics, and metadata.
* The policy MUST be version-controlled and technically reflected in IaC defaults and variable validation.

== Implementierungsleitfaden

1. Document the requirement in a version-controlled policy or standard.
2. Assign ownership and establish a review cadence (e.g., quarterly).
3. Implement the required configuration as code in Terraform or equivalent IaC.

== Reifegrade

[cols="1,2,4"]
|===
|Level |Name |Kriterien

|L1 |Ad hoc – control not consistently applied |* Manual evidence exists for some workloads, but coverage is unknown.

|L2 |Standardised – policy defined and communicated |* A version-controlled policy, ADR, or standard describes the requirement.

|L3 |Integrated – automated validation in CI/CD |* Terraform checks run automatically on pull requests and report results.

|L4 |Auditable – metrics and exceptions tracked |* Control coverage, failures, and approved exceptions are reported quarterly.

|L5 |Optimised – continuous improvement based on data |* Control effectiveness is measured and iteratively improved.

== Checks

=== waf-sov-010.tf.any.resource-tag-data-residency

*Engine:* `terraform` | *Provider:* any | *Automated:* Ja

*Data resources must carry 'data-residency' tag*

Primary data resources (object storage, relational DB, NoSQL, data warehouses) must be tagged with 'data-residency' to indicate the jurisdiction constraint for that resource.

*Scope:* `resource` — `aws_s3_bucket`, `aws_rds_instance`, `aws_rds_cluster`, `aws_dynamodb_table`, `aws_elasticache_cluster`, `aws_elasticsearch_domain`, `aws_opensearch_domain`, `azurerm_storage_account`, `azurerm_sql_database`, `azurerm_cosmosdb_account`, `google_storage_bucket`, `google_sql_database_instance`, `google_bigtable_instance`, `stackit_container_registry`, `stackit_mysql_instance`, `stackit_opensearch_instance`, `stackit_redis_instance`, `stackit_secret_manager`, `ovh_cloud_project`, `ovh_vps`, `ovh_dedicated_server`, `ovh_ip_loadbalancing`, `hcloud_server`, `hcloud_volume`, `hcloud_network`, `hcloud_load_balancer`, `hcloud_dns_record`

*Assertions:*
* `tags` key exists — Resource is missing the 'data-residency' tag required by sovereignty policy.
* `tags` key exists — Resource is missing the 'data-class' tag required by data classification policy.

*Remediation:* Add 'data-residency' and 'data-class' tags to all data-storing resources. Acceptable values for 'data-residency': eu-only, de-only, ch-only, at-only, global-approved. Acceptable values for 'data-class': pii, health, financial, operational, public, restricted.

.Compliant

[source,terraform]
----
# AWS
resource "aws_s3_bucket" "customer_data" {
  bucket = "acme-customer-data-prod"
  tags = {
    data-class      = "pii"
    data-residency  = "eu-only"
    environment     = "production"
    owner           = "platform-team"
  }
}

# Azure
resource "azurerm_storage_account" "customer_data" {
  name             = "acmestorage"
  resource_group_name = azurerm_resource_group.main.name
  location         = "germanywestcentral"
  tags = {
    data-class      = "pii"
    data-residency  = "eu-only"
    environment     = "production"
    owner           = "platform-team"
  }
}

# GCP
resource "google_storage_bucket" "customer_data" {
  name     = "acme-customer-data-prod"
  location = "europe-west3"
  labels = {
    data-class      = "pii"
    data-residency  = "eu-only"
    environment     = "production"
    owner           = "platform-team"
  }
}

# StackIT (SchwarzIT)
resource "stackit_container_registry" "customer_data" {
  project_id = stackit_project.main.id
  name       = "acme-registry"
  labels = {
    data-class      = "pii"
    data-residency  = "eu-only"
  }
}

# OVH
resource "ovh_cloud_project" "customer_data" {
  description = "Sovereign workload"
  tags        = ["data-residency=eu-only", "data-class=pii"]
}

# Hetzner Cloud
resource "hcloud_server" "customer_data" {
  name        = "sovereign-server"
  server_type = "cx22"
  location    = "fsn1"
  labels = {
    data-class      = "pii"
    data-residency  = "eu-only"
  }
}
----

.Non-Compliant

[source,terraform]
----
resource "aws_s3_bucket" "customer_data" {
  bucket = "acme-customer-data-prod"
  # Missing data-residency and data-class tags
  tags = {
    environment = "production"
  }
}
----

=== waf-sov-010.tf.aws.provider-region-explicit

*Engine:* `terraform` | *Provider:* aws | *Automated:* Ja

*AWS provider must have 'region' explicitly set*

AWS provider blocks must have an explicit 'region' attribute set to prevent unintended deployments to non-sovereign regions via environment variable fallback.

*Scope:* `provider` — `aws`

*Assertions:*
* `region` attribute exists — AWS provider block is missing explicit 'region' attribute.
* `region` not empty — AWS provider 'region' must not be empty.

*Remediation:* Set 'region' explicitly in all AWS provider blocks. Use a variable with a validation block to restrict to approved regions.

.Compliant

[source,terraform]
----
variable "aws_region" {
  type    = string
  default = "eu-central-1"
  validation {
    condition     = contains(["eu-central-1", "eu-west-1"], var.aws_region)
    error_message = "Region must be in approved sovereign EU list."
  }
}
provider "aws" {
  region = var.aws_region
}
----

.Non-Compliant

[source,terraform]
----
provider "aws" {
  # No region set – defaults to AWS_DEFAULT_REGION env var
}
----

=== waf-sov-010.tf.azurerm.location-explicit

*Engine:* `terraform` | *Provider:* azurerm | *Automated:* Ja

*Azure resource groups must have 'location' explicitly set*

Azure resource groups (and key resources) must have an explicit 'location' attribute rather than inheriting from parent or relying on environment defaults.

*Scope:* `resource` — `azurerm_resource_group`, `azurerm_storage_account`, `azurerm_sql_server`, `azurerm_kubernetes_cluster`

*Assertions:*
* `location` attribute exists — Azure resource is missing explicit 'location' attribute.
* `location` not empty — Azure resource 'location' must not be empty.

*Remediation:* Set 'location' explicitly on all Azure resources. Use a variable with a validation block to restrict to approved Azure regions.

.Compliant

[source,terraform]
----
variable "azure_location" {
  type    = string
  default = "germanywestcentral"
  validation {
    condition     = contains(["germanywestcentral", "westeurope", "northeurope"], var.azure_location)
    error_message = "Location must be an approved sovereign Azure region."
  }
}
resource "azurerm_resource_group" "main" {
  name     = "rg-sovereign-prod"
  location = var.azure_location
}
----

.Non-Compliant

[source,terraform]
----
resource "azurerm_resource_group" "main" {
  name     = "rg-sovereign-prod"
  # No location set
}
----

=== waf-sov-010.tf.google.region-explicit

*Engine:* `terraform` | *Provider:* google | *Automated:* Ja

*GCP resources must have 'region' or 'location' explicitly set*

GCP resources must have 'region' or 'location' explicitly set to prevent unintended deployment to non-sovereign regions via provider-level defaults.

*Scope:* `resource` — `google_storage_bucket`, `google_sql_database_instance`, `google_compute_instance`, `google_container_cluster`, `google_bigquery_dataset`

*Assertions:*
* `location` attribute exists or fallback (fallback `region`) — GCP resource is missing explicit 'region' or 'location' attribute.

*Remediation:* Set 'location' or 'region' explicitly on all GCP data resources. Use a variable with validation to restrict to approved GCP regions.

.Compliant

[source,terraform]
----
variable "gcp_region" {
  type    = string
  default = "europe-west3"
  validation {
    condition     = startswith(var.gcp_region, "europe-")
    error_message = "Only European GCP regions are approved for sovereign workloads."
  }
}
resource "google_storage_bucket" "data" {
  name     = "acme-sovereign-data"
  location = var.gcp_region
}
----

.Non-Compliant

[source,terraform]
----
resource "google_storage_bucket" "data" {
  name = "acme-sovereign-data"
  # No location set – defaults to provider default
}
----

=== waf-sov-010.config.ovh.data-residency-policy

*Engine:* `config` | *Provider:* ovh | *Automated:* Ja

*OVHcloud data-residency policy must be documented*

OVHcloud public-cloud resources do not expose a native region attribute consistently across all resource types. A version-controlled policy document must therefore define the approved OVHcloud regions, data classifications, and implementation rules for sovereign workloads.

*Scope:* `file` — `docs/sovereign/waf-sov-010-ovh-data-residency.md`

*Assertions:*
* `content` matches pattern `(?i)MUST|SHALL|required|mandatory|documented|approved` — OVHcloud data-residency policy file must contain a normative requirement statement.

*Remediation:* Create or update `docs/sovereign/waf-sov-010-ovh-data-residency.md`. State the approved OVHcloud regions, data-class handling, review cadence, and owner.

.Compliant

[source,text]
----
docs/sovereign/waf-sov-010-ovh-data-residency.md:

- Approved OVHcloud regions are documented (e.g. DE-FRA, DE-EDE, EU-CY).
- Data-class and data-residency handling for OVHcloud is defined.
- Owner and review cadence are recorded.
----

.Non-Compliant

[source,text]
----
# `docs/sovereign/waf-sov-010-ovh-data-residency.md` is missing
# WAF-SOV-010 violation: OVHcloud data-residency policy is not documented
----
