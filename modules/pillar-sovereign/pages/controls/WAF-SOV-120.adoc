== Beschreibung

A current data processing agreement (DPA) or order processing agreement (AVV) MUST exist for each sub-processor handling personal or regulated data. Sub-processor lists MUST be maintained and reviewed at least annually. DPA terms MUST cover data location, security measures, breach notification, deletion, and audit rights. Changes to sub-processors MUST follow a documented approval workflow.

== Begründung

[cols="1,3"]
|===
|Risiko |Beschreibung

|*Risk* |Missing DPAs violate GDPR Article 28 and similar processor accountability requirements.

|*Risk* |Undocumented sub-processors increase supply-chain risk and prevent effective exit management.

|===

== Anforderungen

* A current data processing agreement (DPA) or order processing agreement (AVV) MUST exist for each sub-processor handling personal or regulated data.
* Sub-processor lists MUST be maintained and reviewed at least annually.
* DPA terms MUST cover data location, security measures, breach notification, deletion, and audit rights.
* Changes to sub-processors MUST follow a documented approval workflow.

== Implementierungsleitfaden

. Document the requirement in a version-controlled policy, ADR, or standard.
. Assign ownership and establish a review cadence (e.g., quarterly).
. Implement the required configuration as code in Terraform or equivalent IaC.
