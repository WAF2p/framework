[.metadata]
*Säule:* Sovereign | *Schweregrad:* Kritisch | *Kategorie:* Identity Access | *Automatisierbar:* High

== Beschreibung

Deployments MUST be restricted to approved sovereign regions through policy-as-code and IaC guardrails. Region constraints must be technically enforced—not merely documented. Violations must be blocked in CI or flagged as critical policy exceptions requiring explicit documented approval.

== Begründung

[cols="1,3"]
|===
|Risiko |Beschreibung

|*Risk* |Data may leave approved jurisdictions and violate regulatory requirements.

|*Risk* |Vendor lock-in reduces future portability and sovereignty options.

|===

== Anforderungen

* Deployments MUST be restricted to approved sovereign regions through policy-as-code and IaC guardrails.
* Region constraints must be technically enforced—not merely documented.
* Violations must be blocked in CI or flagged as critical policy exceptions requiring explicit documented approval.

== Implementierungsleitfaden

1. Implement the required configuration as code in Terraform or equivalent IaC.
2. Add an automated check to CI/CD so deviations are caught before deployment.

== Checks

=== waf-sov-020.tf.aws.provider-region-in-allowed-list

*Engine:* `terraform` | *Provider:* aws | *Automated:* Ja

*AWS provider region must be explicitly set*

Every AWS provider block must have a 'region' attribute explicitly set. Relying on AWS_DEFAULT_REGION environment variables or provider defaults is prohibited for sovereign workloads.

*Scope:* `provider` — `aws`

*Assertions:*
* `region` attribute exists — AWS provider block is missing an explicit 'region' attribute.

*Remediation:* Add 'region = var.aws_region' to all AWS provider blocks.

.Compliant

[source,terraform]
----
provider "aws" {
  region = var.aws_region
}
----

.Non-Compliant

[source,terraform]
----
provider "aws" {
  # region sourced from AWS_DEFAULT_REGION – not sovereign-safe
}
----

---

=== waf-sov-020.tf.aws.region-variable-validation

*Engine:* `terraform` | *Provider:* aws | *Automated:* Ja

*AWS region variable must have a validation constraint*

Any Terraform variable whose name contains 'region' or 'location' must have a validation block to restrict values to the organization's approved region list.

*Scope:* `variable`

*Assertions:*
* `validation` block exists — Region/location variable is missing a 'validation' block to restrict to approved values.

*Remediation:* Add a validation block to region variables that uses 'contains()' or 'startswith()' to restrict values to the approved list.

.Compliant

[source,terraform]
----
variable "aws_region" {
  type        = string
  description = "AWS region for sovereign deployments"
  default     = "eu-central-1"
  validation {
    condition     = contains(["eu-central-1", "eu-west-1", "eu-north-1"], var.aws_region)
    error_message = "Must be an approved sovereign EU region."
  }
}
----

.Non-Compliant

[source,terraform]
----
variable "aws_region" {
  type        = string
  default     = "us-east-1"
  # No validation – any region is accepted
}
----

---

=== waf-sov-020.tf.aws.no-hardcoded-non-sovereign-region

*Engine:* `terraform` | *Provider:* aws | *Automated:* Ja

*No hardcoded non-sovereign AWS region in resource or provider blocks*

Hardcoded AWS region strings referencing non-sovereign regions (e.g., us-east-1, ap-southeast-1) are forbidden in provider, resource, and data source blocks.

*Scope:* `any` Terraform block

*Assertions:*
* `region` not matches pattern `^(us-|ap-|sa-|ca-|me-|af-)` — Hardcoded non-sovereign AWS region detected. Only EU/approved regions are permitted.

*Remediation:* Replace hardcoded region values with variable references that have validation constraints.

.Compliant

[source,terraform]
----
provider "aws" {
  region = var.aws_region  # validated to eu-central-1 or eu-west-1
}
----

.Non-Compliant

[source,terraform]
----
provider "aws" {
  region = "us-east-1"  # Non-sovereign region hardcoded
}
----

---
