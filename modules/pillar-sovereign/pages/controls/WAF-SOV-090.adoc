== Description

Outbound network traffic MUST be controlled using a default-deny or strict allow-list policy. Security groups must not permit unrestricted egress (0.0.0.0/0) without explicit justification. VPC endpoints MUST be used for access to cloud provider APIs to keep traffic on the sovereign network. Data exfiltration detection MUST be established to alert on anomalous outbound data volumes or unexpected destinations.

== Rationale

[cols="1,3"]
|===
|Risk |Description

|*Risk* |Open outbound traffic enables data exfiltration and command-and-control communication.

|*Risk* |Missing default-deny network rules let attackers reach external services unhindered.

|===

== Requirements

* Outbound network traffic MUST be controlled using a default-deny or strict allow-list policy.
* Security groups must not permit unrestricted egress (0.0.0.0/0) without explicit justification.
* VPC endpoints MUST be used for access to cloud provider APIs to keep traffic on the sovereign network.
* Data exfiltration detection MUST be established to alert on anomalous outbound data volumes or unexpected destinations.

2. Implement the control in the relevant tooling or process.

== Checks

=== waf-sov-090.tf.aws.no-unrestricted-egress

*Engine:* `terraform` | *Provider:* aws | *Automated:* Yes

*Security groups must not allow unrestricted egress to 0.0.0.0/0*

AWS security group rules with type=egress and cidr_blocks containing 0.0.0.0/0 or ::/0 should not exist without documented justification. Unrestricted egress enables data exfiltration and violates the principle of least-privilege networking.

*Scope:* `resource` — `aws_security_group_rule`, `aws_security_group`

*Assertions:*
* `egress.cidr_blocks` not contains `0.0.0.0/0` — Security group allows unrestricted outbound access to 0.0.0.0/0. Restrict to specific destinations.
* `egress.ipv6_cidr_blocks` not contains `::/0` — Security group allows unrestricted outbound access to ::/0 (all IPv6).

*Remediation:* Replace 0.0.0.0/0 egress rules with specific CIDR ranges or prefix lists. Use VPC endpoints for cloud service access to eliminate the need for internet egress.

.Compliant

[source,terraform]
----
resource "aws_security_group" "app" {
  name   = "app-sg"
  vpc_id = aws_vpc.main.id
  egress {
    from_port   = 443
    to_port     = 443
    protocol    = "tcp"
    cidr_blocks = ["10.0.0.0/8"]  # Internal only
  }
  # Outbound internet requires Network Firewall / explicit destination
}
----

.Non-Compliant

[source,terraform]
----
resource "aws_security_group" "app" {
  name   = "app-sg"
  vpc_id = aws_vpc.main.id
  egress {
    from_port   = 0
    to_port     = 0
    protocol    = "-1"
    cidr_blocks = ["0.0.0.0/0"]  # Unrestricted outbound
  }
}
----

=== waf-sov-090.tf.aws.vpc-endpoint-s3

*Engine:* `terraform` | *Provider:* aws | *Automated:* Yes

*VPC must have a gateway endpoint for S3*

VPCs containing sovereign workloads should have a gateway endpoint for S3 to ensure S3 API traffic stays on the AWS network backbone, not the public internet. This is both a sovereignty and cost optimization control.

*Scope:* `resource` — `aws_vpc`

*Assertions:*
* `id` has associated resource — VPC does not have an S3 VPC endpoint. S3 traffic traverses the public internet.

*Remediation:* Create an aws_vpc_endpoint resource for S3 (gateway type) in each VPC containing sovereign workloads.

.Compliant

[source,terraform]
----
resource "aws_vpc_endpoint" "s3" {
  vpc_id            = aws_vpc.main.id
  service_name      = "com.amazonaws.${var.aws_region}.s3"
  vpc_endpoint_type = "Gateway"
  route_table_ids   = [aws_route_table.private.id]
  policy            = data.aws_iam_policy_document.s3_endpoint_policy.json
}
----

.Non-Compliant

[source,terraform]
----
resource "aws_vpc" "main" {
  cidr_block = "10.0.0.0/16"
  # No S3 VPC endpoint – all S3 traffic via public internet
}
----

=== waf-sov-090.tf.aws.vpc-flow-logs-enabled

*Engine:* `terraform` | *Provider:* aws | *Automated:* Yes

*VPC flow logs must be enabled for egress forensics*

Every aws_vpc must have VPC flow logs enabled to capture network traffic metadata. This is required for forensic investigation of data exfiltration events and for compliance with audit logging requirements.

*Scope:* `resource` — `aws_vpc`

*Assertions:*
* `id` has associated resource — VPC does not have flow logs enabled. Network traffic cannot be audited.

*Remediation:* Create an aws_flow_log resource for each VPC targeting an approved log destination (S3 in sovereign region or CloudWatch with retention policy set).

=== waf-sov-090.tf.aws.network-acl-no-open-egress

*Engine:* `terraform` | *Provider:* aws | *Automated:* Yes

*Network ACLs should not have open egress rules on all ports*

Network ACL egress rules allowing all traffic (port 0-65535) to 0.0.0.0/0 provide no meaningful defense-in-depth for data exfiltration scenarios.

*Scope:* `resource` — `aws_network_acl_rule`

*Assertions:*
* `egress` not in `['0.0.0.0/0']` — Network ACL has unrestricted egress rule on all ports to 0.0.0.0/0.

*Remediation:* Restrict network ACL egress rules to specific port ranges and destination CIDRs.

=== waf-sov-090.tf.azurerm.nsg-no-open-outbound

*Engine:* `terraform` | *Provider:* azurerm | *Automated:* Yes

*Azure NSG must not allow unrestricted outbound traffic*

Azure Network Security Groups must not have outbound security rules allowing all traffic (Any/Any) to destination '*' (any destination).

*Scope:* `resource` — `azurerm_network_security_rule`

*Assertions:*
* `destination_address_prefix` not equals `*` — Azure NSG rule must not allow traffic to any destination (*).

*Remediation:* Replace wildcard destination address prefix ('*') with specific CIDRs or service tags.

=== waf-sov-090.tf.google.firewall-no-open-egress

*Engine:* `terraform` | *Provider:* google | *Automated:* Yes

*GCP firewall rules must not allow unrestricted outbound traffic*

GCP compute firewall rules with direction = EGRESS must not allow destination_ranges of 0.0.0.0/0 unless explicitly tagged and justified. Default-deny egress policies should be enforced at the VPC level.

*Scope:* `resource` — `google_compute_firewall`

*Assertions:*
* `direction` equals `EGRESS` — Only egress firewall rules are checked for unrestricted outbound.
* `destination_ranges` not contains `0.0.0.0/0` — GCP egress firewall rule must not allow unrestricted 0.0.0.0/0 destinations.

*Remediation:* Avoid 0.0.0.0/0 destination_ranges in egress firewall rules. Use google_compute_firewall_policy rules with priority to deny all egress by default and allow only specific destinations/ports.

.Compliant

[source,terraform]
----
resource "google_compute_firewall" "deny_egress" {
  name          = "deny-all-egress"
  network       = google_compute_network.main.id
  direction     = "EGRESS"
  priority      = 1000
  deny {
    protocol = "all"
  }
  destination_ranges = ["10.0.0.0/8"]
}
----

.Non-Compliant

[source,terraform]
----
resource "google_compute_firewall" "bad_egress" {
  name               = "allow-all-egress"
  network            = google_compute_network.main.id
  direction          = "EGRESS"
  allow {
    protocol = "all"
  }
  destination_ranges = ["0.0.0.0/0"]
}
----
