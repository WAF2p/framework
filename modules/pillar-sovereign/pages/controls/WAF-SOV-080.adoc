== Beschreibung

An inventory of all dependencies and subprocessors MUST be maintained: managed cloud services, third-party SaaS tools, CI/CD platforms, observability providers, and data processors. Changes to this inventory MUST be version-controlled, reviewed, and approved. Provider version constraints in Terraform MUST be pinned to prevent silent upgrades. Module sources MUST reference approved registries with version-locked references.

== Begründung

[cols="1,3"]
|===
|Risiko |Beschreibung

|*Risk* |Incomplete sub-processor inventories violate processor transparency obligations.

|*Risk* |Missing dependency assessments complicate exit management and emergency planning.

|===

== Anforderungen

* An inventory of all dependencies and subprocessors MUST be maintained: managed cloud services, third-party SaaS tools, CI/CD platforms, observability providers, and data processors.
* Changes to this inventory MUST be version-controlled, reviewed, and approved.
* Provider version constraints in Terraform MUST be pinned to prevent silent upgrades.
* Module sources MUST reference approved registries with version-locked references.

== Implementierungsleitfaden

1. Document the requirement in a version-controlled policy or standard.
2. Assign ownership and establish a review cadence (e.g., quarterly).

== Checks

=== waf-sov-080.tf.any.required-providers-version-pinned

*Engine:* `terraform` | *Provider:* any | *Automated:* Ja

*All required_providers must have version constraints pinned*

Every entry in the terraform required_providers block must specify a version constraint. Unpinned providers allow silent upgrades that may change behavior, introduce breaking changes, or alter sovereign controls without review.

*Scope:* `terraform`

*Assertions:*
* `version` attribute exists — One or more required_providers entries are missing version constraints.
* `version` not matches pattern `^>= 0\\.0\\.0$` — Provider version constraint is too broad (>= 0.0.0). Use a tightly bounded constraint.

*Remediation:* Add version constraints to all required_providers using the ~> operator for compatible version pinning (e.g., ~> 5.0 for AWS provider v5.x).

.Compliant

[source,terraform]
----
terraform {
  required_version = ">= 1.6.0"
  required_providers {
    aws = {
      source  = "hashicorp/aws"
      version = "~> 5.40"
    }
    azurerm = {
      source  = "hashicorp/azurerm"
      version = "~> 3.100"
    }
  }
}
----

.Non-Compliant

[source,terraform]
----
terraform {
  required_providers {
    aws = {
      source = "hashicorp/aws"
      # No version constraint – any version accepted
    }
  }
}
----

=== waf-sov-080.tf.any.required-terraform-version

*Engine:* `terraform` | *Provider:* any | *Automated:* Ja

*Terraform required_version must be set*

The 'terraform' block must include a required_version constraint to ensure reproducible behavior across environments and prevent use of incompatible Terraform versions.

*Scope:* `terraform`

*Assertions:*
* `required_version` attribute exists — terraform block is missing required_version constraint.

*Remediation:* Add required_version = ">= 1.x.x" to the terraform configuration block.

.Compliant

[source,terraform]
----
terraform {
  required_version = ">= 1.6.0, < 2.0.0"
}
----

.Non-Compliant

[source,terraform]
----
terraform {
  # No required_version set
}
----

=== waf-sov-080.tf.any.module-source-version-pinned

*Engine:* `terraform` | *Provider:* any | *Automated:* Ja

*Terraform module sources must reference a pinned version*

Terraform modules sourced from the Terraform Registry must specify a 'version' attribute. Git-sourced modules must reference a specific tag or commit hash, not a branch reference.

*Scope:* `module`

*Assertions:*
* `version` matches pattern `\?(ref|version)=` — Registry module must specify a pinned 'version'.
* `source` not matches pattern `\\?ref=main|\\?ref=master|\\?ref=develop` — Git module source must reference a specific tag or commit hash, not a branch.

*Remediation:* Pin module versions explicitly. For registry modules: use version = "x.y.z". For git modules: use ?ref=v1.2.3 with a semver tag.

.Compliant

[source,terraform]
----
module "vpc" {
  source  = "terraform-aws-modules/vpc/aws"
  version = "5.5.3"
}
module "internal_module" {
  source = "git::https://git.example.com/modules/vpc.git?ref=v2.1.0"
}
----

.Non-Compliant

[source,terraform]
----
module "vpc" {
  source = "terraform-aws-modules/vpc/aws"
  # No version pinned
}
module "internal_module" {
  source = "git::https://git.example.com/modules/vpc.git?ref=main"
  # Branch reference – mutable
}
----

=== waf-sov-080.tf.any.no-untrusted-registry-modules

*Engine:* `terraform` | *Provider:* any | *Automated:* Ja

*Terraform module sources must use approved registries or internal git*

Module sources must reference the official Terraform Registry (registry.terraform.io), an approved internal module registry, or a verified internal git repository. Arbitrary public git repositories without version pinning are not permitted.

*Scope:* `module`

*Assertions:*
* `source` not matches pattern `^github\\.com/(?!hashicorp/).*\\.git$` — Module source references an unapproved public GitHub repository without registry validation.

*Remediation:* Migrate to official Terraform Registry modules (registry.terraform.io) or publish internal modules to your private registry.
