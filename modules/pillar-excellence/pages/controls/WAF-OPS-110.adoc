== Beschreibung

Kubernetes and container workloads SHOULD be deployed via GitOps controllers that reconcile desired state from Git. GitOps repositories MUST enforce peer review, branch protection, and signed commits. Controllers MUST report sync status, drift, and errors to observability systems. Manual imperative changes to clusters MUST be reconciled or rejected.

== Begründung

[cols="1,3"]
|===
|Risiko |Beschreibung

|*Risk* |Imperative cluster changes bypass audit trails and create drift between environments.

|*Risk* |Missing GitOps reconciliation leaves clusters in undocumented, non-reproducible states.

|===

== Anforderungen

* Kubernetes and container workloads SHOULD be deployed via GitOps controllers that reconcile desired state from Git.
* GitOps repositories MUST enforce peer review, branch protection, and signed commits.
* Controllers MUST report sync status, drift, and errors to observability systems.
* Manual imperative changes to clusters MUST be reconciled or rejected.

== Implementierungsleitfaden

. Document the requirement in a version-controlled policy, ADR, or standard.
. Assign ownership and establish a review cadence (e.g., quarterly).
. Implement the required configuration as code in Terraform or equivalent IaC.
