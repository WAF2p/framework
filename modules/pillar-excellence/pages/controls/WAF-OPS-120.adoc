== Description

Risky or customer-visible feature rollouts MUST use feature flags with defined targeting and kill-switch capability. Feature flag configurations MUST be version-controlled and auditable. Flag lifecycle MUST be managed so temporary flags are removed after rollout completes. Critical paths MUST support immediate disablement without requiring a full deployment.

== Rationale

[cols="1,3"]
|===
|Risk |Description

|*Risk* |Releases without feature flags force rollbacks for every production issue, increasing MTTR.

|*Risk* |Orphaned feature flags create technical debt and unpredictable code paths.

|===

== Requirements

* Risky or customer-visible feature rollouts MUST use feature flags with defined targeting and kill-switch capability.
* Feature flag configurations MUST be version-controlled and auditable.
* Flag lifecycle MUST be managed so temporary flags are removed after rollout completes.
* Critical paths MUST support immediate disablement without requiring a full deployment.

== Implementation Guidance

. Document the requirement in a version-controlled policy, ADR, or standard.
. Assign ownership and establish a review cadence (e.g., quarterly).
. Implement the required configuration as code in Terraform or equivalent IaC.
