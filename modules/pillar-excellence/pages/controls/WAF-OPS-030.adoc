== Description

Every production workload MUST emit structured logs, expose metrics, and support distributed tracing. An observability stack MUST be configured with centralized log aggregation, a metrics collection system, and distributed tracing. Logs MUST be structured (JSON), include trace IDs and request IDs, and be routed to a centralized platform with defined retention periods.

== Rationale

[cols="1,3"]
|===
|Risk |Description

|*Risk* |Unstructured logs and missing metrics delay troubleshooting and incident detection.

|*Risk* |Without centralized observability data, SLO breaches and security incidents cannot be correlated.

|===

== Requirements

* Every production workload MUST emit structured logs, expose metrics, and support distributed tracing.
* An observability stack MUST be configured with centralized log aggregation, a metrics collection system, and distributed tracing.
* Logs MUST be structured (JSON), include trace IDs and request IDs, and be routed to a centralized platform with defined retention periods.

== Implementation Guidance

1. Document the requirement in a version-controlled policy or standard.
2. Assign ownership and establish a review cadence (e.g., quarterly).
3. Implement the required configuration as code in Terraform or equivalent IaC.

== Checks

=== waf-ops-030.tf.aws.cloudwatch-log-group-retention

*Engine:* `terraform` | *Provider:* aws | *Automated:* Yes

*CloudWatch log groups must define retention period*

All AWS CloudWatch log groups MUST define a retention_in_days value. Log groups without retention will accumulate indefinitely, increasing costs and violating data governance requirements.

*Scope:* `resource` — `aws_cloudwatch_log_group`

*Assertions:*
* `retention_in_days` attribute exists — CloudWatch log group must define retention_in_days.
* `retention_in_days` greater than or equal `1` — Log group retention must be at least 30 days.

*Remediation:* Add retention_in_days to all aws_cloudwatch_log_group resources. Recommended: 90 days for application logs, 365 days for security/audit logs.

.Compliant

[source,terraform]
----
resource "aws_cloudwatch_log_group" "app_logs" {
  name              = "/aws/ecs/payment-service"
  retention_in_days = 90
  tags = {
    environment = "production"
    workload    = "payment-service"
  }
}
----

.Non-Compliant

[source,terraform]
----
resource "aws_cloudwatch_log_group" "app_logs" {
  name = "/aws/ecs/payment-service"
  # No retention_in_days – logs stored indefinitely
  # WAF-OPS-030 Violation
}
----

=== waf-ops-030.tf.aws.xray-tracing-enabled

*Engine:* `terraform` | *Provider:* aws | *Automated:* Yes

*AWS Lambda functions must have X-Ray tracing enabled*

AWS Lambda functions in production MUST have X-Ray tracing enabled to support distributed request tracing and latency analysis.

*Scope:* `resource` — `aws_lambda_function`

*Assertions:*
* `tracing_config.mode` not in `['0.0.0.0/0', '']` — Lambda tracing mode must be Active, not PassThrough.

*Remediation:* Add tracing_config { mode = "Active" } to all aws_lambda_function resources.

.Compliant

[source,terraform]
----
resource "aws_lambda_function" "processor" {
  function_name = "payment-processor"
  role          = aws_iam_role.lambda_exec.arn
  handler       = "index.handler"
  runtime       = "nodejs20.x"

  tracing_config {
    mode = "Active"
  }
}
----

.Non-Compliant

[source,terraform]
----
resource "aws_lambda_function" "processor" {
  function_name = "payment-processor"
  role          = aws_iam_role.lambda_exec.arn
  handler       = "index.handler"
  runtime       = "nodejs20.x"
  # No tracing_config – WAF-OPS-030 Violation
}
----

=== waf-ops-030.tf.azurerm.log-analytics-workspace

*Engine:* `terraform` | *Provider:* azurerm | *Automated:* Yes

*Azure Log Analytics workspace must be configured with retention*

Azure deployments MUST configure a Log Analytics workspace with an appropriate retention period for centralized log aggregation.

*Scope:* `resource` — `azurerm_log_analytics_workspace`

*Assertions:*
* `retention_in_days` greater than or equal `1` — Log Analytics workspace retention must be at least 30 days.

*Remediation:* Set retention_in_days to at least 90 for application logs in the azurerm_log_analytics_workspace resource.

.Compliant

[source,terraform]
----
resource "azurerm_log_analytics_workspace" "main" {
  name                = "law-payment-service-prod"
  location            = var.location
  resource_group_name = azurerm_resource_group.main.name
  sku                 = "PerGB2018"
  retention_in_days   = 90
}
----

.Non-Compliant

[source,terraform]
----
resource "azurerm_log_analytics_workspace" "main" {
  name                = "law-payment-service-prod"
  location            = var.location
  resource_group_name = azurerm_resource_group.main.name
  sku                 = "PerGB2018"
  retention_in_days   = 7
  # 7 days is insufficient – WAF-OPS-030 Violation
}
----

=== waf-ops-030.tf.google.logging-project-sink-exists

*Engine:* `terraform` | *Provider:* google | *Automated:* Yes

*GCP Cloud Logging sink must route structured logs to a centralized destination*

Every production GCP project must define a google_logging_project_sink that routes structured logs to a central BigQuery dataset or Cloud Storage bucket. Cloud Trace must be enabled via the trace API usage.

*Scope:* `resource` — `google_logging_project_sink`

*Assertions:*
* `destination` attribute exists — GCP project must route logs to a centralized BigQuery or Cloud Storage destination.

*Remediation:* Create a google_logging_project_sink for each production project with filter capturing application, audit, and security logs. Enable Cloud Trace API and configure applications to export traces.

.Compliant

[source,terraform]
----
resource "google_logging_project_sink" "central" {
  name        = "centralized-logs"
  destination = "bigquery.googleapis.com/projects/${var.project_id}/datasets/logs"
  filter      = "severity >= WARNING OR protoPayload.serviceName != \"\""

  unique_writer_identity = true
}
----

.Non-Compliant

[source,terraform]
----
# No google_logging_project_sink defined
# Application logs remain only in default log buckets
----
