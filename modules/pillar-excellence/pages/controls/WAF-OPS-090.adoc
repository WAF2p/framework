== Description

All production infrastructure MUST be continuously compared against its IaC definition. Configuration drift – any difference between the actual infrastructure state and the declared IaC state – MUST be detected automatically, reported to the owning team, and remediated within defined SLAs based on severity. Emergency manual changes MUST be codified in IaC within 24 hours.

== Rationale

[cols="1,3"]
|===
|Risk |Description

|*Risk* |Drift between IaC and actual infrastructure leads to shadow IT and unexpected configurations.

|*Risk* |Undetected manual changes undermine compliance and security controls.

|===

== Requirements

* All production infrastructure MUST be continuously compared against its IaC definition.
* Configuration drift – any difference between the actual infrastructure state and the declared IaC state – MUST be detected automatically, reported to the owning team, and remediated within defined SLAs based on severity.
* Emergency manual changes MUST be codified in IaC within 24 hours.

== Implementation Guidance

1. Document the requirement in a version-controlled policy or standard.
2. Assign ownership and establish a review cadence (e.g., quarterly).
3. Implement the required configuration as code in Terraform or equivalent IaC.

== Checks

=== waf-ops-090.tf.aws.config-rule-enabled

*Engine:* `terraform` | *Provider:* aws | *Automated:* Yes

*AWS Config must be enabled with compliance rules for drift detection*

AWS Config MUST be enabled in production accounts and MUST have compliance rules configured to detect configuration changes and non-compliant resource states.

*Scope:* `resource` — `aws_config_configuration_recorder`

*Assertions:*
* `recording_group` attribute exists — AWS Config recorder must define recording_group.

*Remediation:* Enable AWS Config with a configuration recorder and delivery channel. Add aws_config_config_rule resources for key compliance checks.

.Compliant

[source,terraform]
----
resource "aws_config_configuration_recorder" "main" {
  name     = "default"
  role_arn = aws_iam_role.config_role.arn

  recording_group {
    all_supported = true
    include_global_resource_types = true
  }
}

resource "aws_config_delivery_channel" "main" {
  name           = "default"
  s3_bucket_name = aws_s3_bucket.config.bucket
}

resource "aws_config_config_rule" "s3_public_read_prohibited" {
  name = "s3-bucket-public-read-prohibited"
  source {
    owner             = "AWS"
    source_identifier = "S3_BUCKET_PUBLIC_READ_PROHIBITED"
  }
}
----

.Non-Compliant

[source,terraform]
----
# No AWS Config recorder or rules defined
# WAF-OPS-090 Violation: no configuration drift detection
----

=== waf-ops-090.tf.aws.cloudtrail-enabled

*Engine:* `terraform` | *Provider:* aws | *Automated:* Yes

*AWS CloudTrail must be enabled for all regions to detect console changes*

AWS CloudTrail MUST be enabled across all regions to audit all API calls, including console changes that may indicate configuration drift from IaC.

*Scope:* `resource` — `aws_cloudtrail`

*Assertions:*
* `is_multi_region_trail` is true — CloudTrail must be a multi-region trail to capture all console changes.
* `enable_log_file_validation` is true — CloudTrail must have log file validation enabled.

*Remediation:* Set is_multi_region_trail = true and enable_log_file_validation = true on your aws_cloudtrail resource.

.Compliant

[source,terraform]
----
resource "aws_cloudtrail" "main" {
  name                          = "production-trail"
  s3_bucket_name                = aws_s3_bucket.cloudtrail.id
  is_multi_region_trail         = true
  enable_log_file_validation    = true
  include_global_service_events = true
}
----

.Non-Compliant

[source,terraform]
----
resource "aws_cloudtrail" "main" {
  name                       = "production-trail"
  s3_bucket_name             = aws_s3_bucket.cloudtrail.id
  is_multi_region_trail      = false
  enable_log_file_validation = false
  # Single-region trail without validation – WAF-OPS-090 Violation
}
----

=== waf-ops-090.tf.azurerm.policy-assignment-drift

*Engine:* `terraform` | *Provider:* azurerm | *Automated:* Yes

*Azure Policy must be assigned for configuration compliance monitoring*

Azure Policy initiatives MUST be assigned to production subscriptions or resource groups to continuously evaluate configuration compliance and detect drift.

*Scope:* `resource` — `azurerm_subscription_policy_assignment`

*Assertions:*
* `policy_definition_id` not empty — Policy assignment must reference a policy or initiative definition.

*Remediation:* Assign Azure Policy or built-in initiative (e.g., Azure Security Benchmark) to the production subscription using azurerm_subscription_policy_assignment.

.Compliant

[source,terraform]
----
data "azurerm_policy_set_definition" "security_benchmark" {
  display_name = "Azure Security Benchmark"
}

resource "azurerm_subscription_policy_assignment" "security" {
  name                 = "security-benchmark"
  subscription_id      = data.azurerm_subscription.current.id
  policy_definition_id = data.azurerm_policy_set_definition.security_benchmark.id
  description          = "Azure Security Benchmark for configuration drift detection"
  display_name         = "Security Benchmark – Production"
}
----

.Non-Compliant

[source,terraform]
----
# No Azure Policy assigned to subscription
# Configuration drift undetectable – WAF-OPS-090 Violation
----

=== waf-ops-090.tf.google.security-command-center-asset-drift

*Engine:* `terraform` | *Provider:* google | *Automated:* Yes

*GCP Security Command Center must be enabled for asset inventory and drift detection*

GCP Security Command Center (SCC) or Asset Inventory feeds must be enabled to continuously compare cloud resources against the IaC definition. Audit logging must be enabled to detect console/API changes.

*Scope:* `resource` — `google_security_center_notification_config`, `google_logging_project_sink`

*Assertions:*
* `pubsub_topic` attribute exists — Security Command Center notification config must route asset findings to a Pub/Sub topic.

*Remediation:* Enable Security Command Center at the organization level. Create google_security_center_notification_config resources to route asset changes and findings. Ensure google_logging_project_sink routes audit logs to a durable store.

.Compliant

[source,terraform]
----
resource "google_security_center_notification_config" "asset_changes" {
  config_id    = "asset-drift"
  organization = var.org_id
  pubsub_topic = google_pubsub_topic.scc.id

  streaming_config {
    filter = "category = \"CATEGORY_ASSET\""
  }
}

resource "google_logging_project_sink" "audit" {
  name        = "audit-logs"
  destination = "bigquery.googleapis.com/projects/${var.project_id}/datasets/audit_logs"
  filter      = "protoPayload.@type=\"type.googleapis.com/google.cloud.audit.AuditLog\""
}
----

.Non-Compliant

[source,terraform]
----
# Security Command Center not enabled; no audit log sink configured.
# Manual console changes can drift undetected.
----
