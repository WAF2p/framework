== Beschreibung

All production workloads MUST be deployed with network topology optimized for latency. Services that communicate frequently MUST be co-located in the same availability zone or use VPC peering to avoid cross-region traversal. Content Delivery Networks (CDN) MUST be used for all public-facing static and cacheable content. VPC Endpoints MUST be used for internal AWS service traffic to avoid internet routing. Cross-AZ data transfer costs and latency MUST be evaluated and minimized in service topology design.

== Begründung

[cols="1,3"]
|===
|Risiko |Beschreibung

|*Risk* |Internet-facing resources or open management ports become direct attack vectors.

|*Risk* |Lateral movement is easier when network segmentation and access rules are missing.

|===

== Anforderungen

* All production workloads MUST be deployed with network topology optimized for latency.
* Services that communicate frequently MUST be co-located in the same availability zone or use VPC peering to avoid cross-region traversal.
* Content Delivery Networks (CDN) MUST be used for all public-facing static and cacheable content.
* VPC Endpoints MUST be used for internal AWS service traffic to avoid internet routing.
* Cross-AZ data transfer costs and latency MUST be evaluated and minimized in service topology design.

== Checks

=== waf-perf-070.tf.aws.vpc-endpoint-s3

*Engine:* `terraform` | *Provider:* aws | *Automated:* Ja

*AWS VPCs with private subnets must have S3 Gateway VPC Endpoints*

VPCs containing private subnets that access S3 must use Gateway VPC Endpoints to avoid internet routing and reduce latency and data transfer costs.

*Scope:* `resource` — `aws_vpc_endpoint`

*Assertions:*
* `service_name` matches pattern `.*\\.s3$` — VPC Endpoint should be configured for S3 service.
* `vpc_endpoint_type` equals `Gateway` — S3 VPC Endpoint must be Gateway type.

*Remediation:* Create an aws_vpc_endpoint resource for S3 with vpc_endpoint_type = "Gateway" and associate it with private route tables. This routes S3 traffic via AWS backbone.

.Compliant

[source,terraform]
----
resource "aws_vpc_endpoint" "s3" {
  vpc_id            = aws_vpc.main.id
  service_name      = "com.amazonaws.${var.region}.s3"
  vpc_endpoint_type = "Gateway"
  route_table_ids   = [aws_route_table.private.id]
  tags = { Name = "vpce-s3-${var.environment}" }
}
resource "aws_vpc_endpoint" "dynamodb" {
  vpc_id            = aws_vpc.main.id
  service_name      = "com.amazonaws.${var.region}.dynamodb"
  vpc_endpoint_type = "Gateway"
  route_table_ids   = [aws_route_table.private.id]
}
----

.Non-Compliant

[source,terraform]
----
# No VPC Endpoints defined
# S3 and DynamoDB traffic routes via internet gateway
resource "aws_vpc" "main" {
  cidr_block = "10.0.0.0/16"
  # All service traffic exits to internet – WAF-PERF-070 violation
}
----

=== waf-perf-070.tf.azurerm.cdn-profile-configured

*Engine:* `terraform` | *Provider:* azurerm | *Automated:* Ja

*Azure applications with public endpoints should use CDN or Front Door*

Public-facing Azure applications should use Azure CDN or Azure Front Door to cache static content and reduce origin load and end-user latency.

*Scope:* `resource` — `azurerm_cdn_profile`, `azurerm_frontdoor`, `azurerm_cdn_frontdoor_profile`

*Assertions:*
* `sku` not empty — CDN profile must have SKU defined.

*Remediation:* Deploy azurerm_cdn_profile with endpoints for static content delivery. For global applications, use Azure Front Door for routing and caching.

.Compliant

[source,terraform]
----
resource "azurerm_cdn_profile" "main" {
  name                = "cdn-payment-frontend"
  resource_group_name = azurerm_resource_group.main.name
  location            = "global"
  sku                 = "Standard_Microsoft"
}
resource "azurerm_cdn_endpoint" "static" {
  name                = "static-assets"
  profile_name        = azurerm_cdn_profile.main.name
  resource_group_name = azurerm_resource_group.main.name
  location            = "global"
  origin {
    name      = "storage-origin"
    host_name = azurerm_storage_account.static.primary_blob_host
  }
}
----

.Non-Compliant

[source,terraform]
----
# No CDN or Front Door configured
# All static content served directly from Storage Account or App Service
# – WAF-PERF-070 violation
----

=== waf-perf-070.tf.google.cloud-cdn-enabled

*Engine:* `terraform` | *Provider:* google | *Automated:* Ja

*GCP backends with public traffic should have Cloud CDN enabled*

GCP HTTP(S) Load Balancer backend services serving public content should have Cloud CDN enabled to reduce origin latency and improve user experience.

*Scope:* `resource` — `google_compute_backend_service`

*Assertions:*
* `enable_cdn` is true — External backend service should have Cloud CDN enabled.

*Remediation:* Set enable_cdn = true on google_compute_backend_service for external load balancers. Configure cdn_policy with appropriate cache mode and TTL settings.

.Compliant

[source,terraform]
----
resource "google_compute_backend_service" "frontend" {
  name                  = "backend-payment-frontend"
  protocol              = "HTTP"
  load_balancing_scheme = "EXTERNAL"
  enable_cdn            = true
  cdn_policy {
    cache_mode                   = "CACHE_ALL_STATIC"
    default_ttl                  = 3600
    client_ttl                   = 3600
    negative_caching             = true
    serve_while_stale            = 86400
  }
  backend {
    group = google_compute_instance_group.frontend.id
  }
}
----

.Non-Compliant

[source,terraform]
----
resource "google_compute_backend_service" "frontend" {
  name                  = "backend-payment-frontend"
  protocol              = "HTTP"
  load_balancing_scheme = "EXTERNAL"
  enable_cdn            = false  # CDN disabled – WAF-PERF-070 violation
}
----
