== Description

All relational and document databases used in production MUST have a documented performance baseline including query execution times, I/O throughput, and connection pool utilization. An index strategy MUST be defined and maintained for all tables with significant read/write loads. Slow query logging MUST be enabled and reviewed regularly. Database performance insights or equivalent monitoring MUST be active on all production database instances. Missing indexes on frequently queried columns in high-traffic tables are treated as violations.

== Rationale

[cols="1,3"]
|===
|Risk |Description

|*Risk* |Databases without performance insights let slow queries and capacity bottlenecks go unnoticed.

|*Risk* |Missing monitoring data complicates targeted optimization and capacity planning.

|===

== Requirements

* All relational and document databases used in production MUST have a documented performance baseline including query execution times, I/O throughput, and connection pool utilization.
* An index strategy MUST be defined and maintained for all tables with significant read/write loads.
* Slow query logging MUST be enabled and reviewed regularly.
* Database performance insights or equivalent monitoring MUST be active on all production database instances.

== Implementation Guidance

1. Document the requirement in a version-controlled policy or standard.
2. Assign ownership and establish a review cadence (e.g., quarterly).
3. Implement the required configuration as code in Terraform or equivalent IaC.

== Checks

=== waf-perf-040.tf.aws.rds-performance-insights

*Engine:* `terraform` | *Provider:* aws | *Automated:* Yes

*AWS RDS instances must have Performance Insights enabled*

RDS and Aurora instances must have Performance Insights enabled to allow query-level performance monitoring and diagnosis of slow queries and lock contention.

*Scope:* `resource` — `aws_db_instance`, `aws_rds_cluster_instance`

*Assertions:*
* `performance_insights_enabled` is true — RDS instance must have Performance Insights enabled.
* `enabled_cloudwatch_logs_exports` not empty — RDS instance must export logs to CloudWatch (slowquery, error, general).
* `monitoring_interval` greater than or equal `1` — Enhanced Monitoring must be enabled (monitoring_interval >= 1).

*Remediation:* Set performance_insights_enabled = true, monitoring_interval = 60 (or 1 for high-granularity). Set enabled_cloudwatch_logs_exports = ["slowquery", "error"] for MySQL or ["postgresql"] for PostgreSQL.

.Compliant

[source,terraform]
----
resource "aws_db_instance" "main" {
  identifier             = "db-payment-api"
  engine                 = "postgres"
  instance_class         = "db.t3.medium"
  allocated_storage      = 100
  performance_insights_enabled          = true
  performance_insights_retention_period = 7
  monitoring_interval                   = 60
  monitoring_role_arn                   = aws_iam_role.rds_monitoring.arn
  enabled_cloudwatch_logs_exports        = ["postgresql"]
  deletion_protection    = true
}
----

.Non-Compliant

[source,terraform]
----
resource "aws_db_instance" "main" {
  identifier    = "db-payment-api"
  engine        = "postgres"
  instance_class = "db.t3.medium"
  # Performance Insights disabled – WAF-PERF-040 violation
  # No CloudWatch log exports
  # No Enhanced Monitoring
}
----

=== waf-perf-040.tf.azurerm.sql-query-insights

*Engine:* `terraform` | *Provider:* azurerm | *Automated:* Yes

*Azure SQL Database must have auditing and threat detection enabled*

Azure SQL Database must have auditing enabled which captures query execution data, and should have Query Performance Insight accessible via the portal.

*Scope:* `resource` — `azurerm_mssql_database`, `azurerm_mssql_server`

*Assertions:*
* `min_tls_version` equals `TLS1_2` — Azure SQL Server must enforce TLS 1.2.
* `public_network_access_enabled` is false — Azure SQL Server must not be publicly accessible; use private endpoints.

*Remediation:* Set min_tls_version = "1.2" and public_network_access_enabled = false. Configure azurerm_mssql_server_extended_auditing_policy for query performance tracking.

.Compliant

[source,terraform]
----
resource "azurerm_mssql_server" "main" {
  name                         = "sql-payment-api"
  resource_group_name          = azurerm_resource_group.main.name
  location                     = azurerm_resource_group.main.location
  version                      = "12.0"
  administrator_login          = var.db_admin_user
  administrator_login_password = var.db_admin_password
  minimum_tls_version          = "1.2"
  public_network_access_enabled = false
}
resource "azurerm_mssql_server_extended_auditing_policy" "main" {
  server_id              = azurerm_mssql_server.main.id
  storage_endpoint       = azurerm_storage_account.audit.primary_blob_endpoint
  retention_in_days      = 90
  log_monitoring_enabled = true
}
----

.Non-Compliant

[source,terraform]
----
resource "azurerm_mssql_server" "main" {
  name                          = "sql-payment-api"
  minimum_tls_version           = "1.0"  # Old TLS – violation
  public_network_access_enabled = true    # Publicly accessible – WAF-PERF-040 violation
}
----

=== waf-perf-040.tf.google.cloudsql-insights-enabled

*Engine:* `terraform` | *Provider:* google | *Automated:* Yes

*GCP Cloud SQL must have Query Insights enabled*

GCP Cloud SQL instances must have Query Insights enabled to track query performance, identify slow queries, and monitor database efficiency.

*Scope:* `resource` — `google_sql_database_instance`

*Assertions:*
* `settings.insights_config.query_insights_enabled` is true — Cloud SQL Query Insights must be enabled.
* `settings.backup_configuration.enabled` is true — Cloud SQL automated backups must be enabled.
* `deletion_protection` is true — Cloud SQL deletion protection must be enabled.

*Remediation:* Set insights_config { query_insights_enabled = true } in settings block. Enable backup_configuration and deletion_protection = true.

.Compliant

[source,terraform]
----
resource "google_sql_database_instance" "main" {
  name             = "db-payment-api"
  database_version = "POSTGRES_15"
  deletion_protection = true
  settings {
    tier = "db-custom-2-4096"
    backup_configuration {
      enabled    = true
      start_time = "03:00"
    }
    insights_config {
      query_insights_enabled  = true
      query_string_length     = 1024
      record_application_tags = true
    }
  }
}
----

.Non-Compliant

[source,terraform]
----
resource "google_sql_database_instance" "main" {
  name             = "db-payment-api"
  database_version = "POSTGRES_15"
  settings {
    tier = "db-custom-2-4096"
    # No insights_config – WAF-PERF-040 violation
    # No backup_configuration
  }
}
----

=== waf-perf-040.tf.stackit.auto-scaling-enabled

*Engine:* `terraform` | *Provider:* stackit | *Automated:* Yes

*All relational and document databases used in production for stackit*

All relational and document databases used in production must be documented in IaC via a auto-scaling-enabled tag/label on stackit_project. This validates the control is tracked as code.

*Scope:* `resource` — `stackit_project`

*Assertions:*
* `labels` key exists — stackit_project is missing the auto-scaling-enabled tag/label.

*Remediation:* Add a auto-scaling-enabled tag/label to the stackit_project resource to show the stackit implementation of WAF-PERF-040 is tracked in IaC.

.Compliant

    auto-scaling-enabled = "true"
  }
}
