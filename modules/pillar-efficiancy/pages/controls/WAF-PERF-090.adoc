== Beschreibung

All block storage (EBS, Azure Managed Disks, GCP Persistent Disk) and object storage used by production workloads MUST be configured with appropriate I/O performance settings (IOPS, throughput, storage class). Storage volumes MUST use the most cost-efficient performance tier for their workload. EBS volumes MUST use gp3 instead of gp2 for new deployments. Storage I/O performance MUST be monitored and alerts configured for throughput saturation and high queue depth.

== Begründung

[cols="1,3"]
|===
|Risiko |Beschreibung

|*Risk* |Slow or over-provisioned storage extends response times and increases cost.

|*Risk* |Missing storage-tiering strategies prevent cost-efficient long-term archiving.

|===

== Anforderungen

* All block storage (EBS, Azure Managed Disks, GCP Persistent Disk) and object storage used by production workloads MUST be configured with appropriate I/O performance settings (IOPS, throughput, storage class).
* Storage volumes MUST use the most cost-efficient performance tier for their workload.
* EBS volumes MUST use gp3 instead of gp2 for new deployments.
* Storage I/O performance MUST be monitored and alerts configured for throughput saturation and high queue depth.

== Implementierungsleitfaden

1. Document the requirement in a version-controlled policy or standard.
2. Assign ownership and establish a review cadence (e.g., quarterly).
3. Implement the required configuration as code in Terraform or equivalent IaC.

== Checks

=== waf-perf-090.tf.aws.ebs-gp3-volume-type

*Engine:* `terraform` | *Provider:* aws | *Automated:* Ja

*AWS EBS volumes must use gp3 type instead of gp2*

EBS volumes must use gp3 type for new deployments. gp3 provides baseline performance of 3000 IOPS and 125 MB/s throughput without burst mechanics, at 20% lower cost than gp2. gp2 volumes deplete burst credits under sustained load causing unpredictable performance.

*Scope:* `resource` — `aws_ebs_volume`, `aws_db_instance`, `aws_launch_template`

*Assertions:*
* `volume_type` not equals `gp2` — EBS volume must not use gp2 type. Migrate to gp3 for consistent performance and lower cost.
* `volume_type` in `['gp3', 'io2']` — EBS volume type must be explicitly set to gp3 or io2.

*Remediation:* Change volume_type from "gp2" to "gp3". For databases requiring higher IOPS, set explicit iops and throughput values on gp3 (max 16000 IOPS, 1000 MB/s). Migration from gp2 to gp3 is online and non-disruptive.

.Compliant

[source,terraform]
----
resource "aws_ebs_volume" "data" {
  availability_zone = "eu-west-1a"
  size              = 100
  type              = "gp3"
  iops              = 6000    # Explicitly set above default 3000
  throughput        = 250     # Explicitly set above default 125 MB/s
  encrypted         = true
  tags = {
    Name    = "data-payment-api"
    workload = "payment-api"
  }
}
----

.Non-Compliant

[source,terraform]
----
resource "aws_ebs_volume" "data" {
  availability_zone = "eu-west-1a"
  size              = 100
  type              = "gp2"  # gp2 – burst-dependent – WAF-PERF-090 violation
  # No explicit IOPS; subject to credit depletion
}
----

=== waf-perf-090.tf.azurerm.managed-disk-premium

*Engine:* `terraform` | *Provider:* azurerm | *Automated:* Ja

*Azure Managed Disks for production database workloads should use Premium SSD*

Azure Managed Disks used for database data volumes should use Premium SSD (P series) or Ultra Disk for high-IOPS workloads. Standard HDD or Standard SSD is inappropriate for production database storage.

*Scope:* `resource` — `azurerm_managed_disk`

*Assertions:*
* `storage_account_type` not in `['Standard_LRS', 'StandardSSD_LRS']` — Production database disks must use Premium_LRS or UltraSSD_LRS, not Standard or StandardSSD.

*Remediation:* Set storage_account_type = "Premium_LRS" for database data disks. Use UltraSSD_LRS for extremely latency-sensitive workloads requiring sub-millisecond I/O.

.Compliant

[source,terraform]
----
resource "azurerm_managed_disk" "db_data" {
  name                 = "disk-db-payment-data"
  resource_group_name  = azurerm_resource_group.main.name
  location             = azurerm_resource_group.main.location
  storage_account_type = "Premium_LRS"
  create_option        = "Empty"
  disk_size_gb         = 256
  tags = {
    workload = "payment-db"
    tier     = "data"
  }
}
----

.Non-Compliant

[source,terraform]
----
resource "azurerm_managed_disk" "db_data" {
  name                 = "disk-db-payment-data"
  storage_account_type = "Standard_LRS"  # HDD for database – WAF-PERF-090 advisory
  create_option        = "Empty"
  disk_size_gb         = 256
}
----

=== waf-perf-090.tf.google.persistent-disk-ssd

*Engine:* `terraform` | *Provider:* google | *Automated:* Ja

*GCP Persistent Disks for production workloads should use SSD type*

GCP Persistent Disks for production compute and database workloads should use pd-ssd or pd-balanced type, not pd-standard (HDD) which has high latency.

*Scope:* `resource` — `google_compute_disk`

*Assertions:*
* `type` not equals `pd-standard` — Production Persistent Disk must not use pd-standard (HDD). Use pd-ssd or pd-balanced.

*Remediation:* Set type = "pd-balanced" for general workloads or type = "pd-ssd" for high-IOPS databases. pd-extreme is available for ultra-high IOPS requirements.

.Compliant

[source,terraform]
----
resource "google_compute_disk" "db_data" {
  name  = "disk-payment-db-data"
  type  = "pd-ssd"
  zone  = "europe-west3-a"
  size  = 100
  labels = {
    workload = "payment-db"
  }
}
----

.Non-Compliant

[source,terraform]
----
resource "google_compute_disk" "db_data" {
  name  = "disk-payment-db-data"
  type  = "pd-standard"  # HDD – high latency for database – WAF-PERF-090 advisory
  zone  = "europe-west3-a"
  size  = 100
}
----
